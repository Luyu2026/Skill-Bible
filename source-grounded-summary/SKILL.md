# 长文证据摘要

## 一句话主餐

普通聊天容易把看似合理的背景写进摘要；这里只从已读取材料提炼重点，并保留出处、限制和真正影响决策的信息。

## 输入

- 原文、文件或可访问链接，以及需要覆盖的范围。
- 阅读目的：快速了解、做决定、转述还是提取行动。
- 期望篇幅、读者背景及必须保留的数字或段落。
- 材料版本、发布日期和页码信息，已有则直接沿用。
- 链接打不开时请求粘贴或上传关键内容；不能依据标题假装已读。

### 输入不足时如何推进

- 已给出的材料直接使用，不要求用户为固定模板重新整理。
- 仅追问会改变处理路径的缺口，其余先交付材料允许的部分。
- 用户事实、待确认信息与模拟例子分别标记，不补造事实。

## 核心判断

1. 区分原文摘要、分析推断和外部核验，默认只做第一种。
2. 摘要篇幅有限时优先保留改变结论的条件，不能只留肯定句。
3. 作者建议不等于已证实事实；预测不等于实际结果。
4. 多份材料冲突时并列来源、时间和口径，不强行合成单一结论。
5. 局部读取只能交付局部摘要，明确覆盖范围。
6. 用户要求查最新真实性时另做核验，并将核验来源与原文分开。

## 编号工作流

### 1. 确认材料覆盖

- 记录材料名称、版本、范围和能否完整读取。
- 长材料按章节切分，保留页码或标题锚点。
- 排除目录、重复页眉等噪声，但保留表注和结论限制。
- 内容缺页时明确缺口，不能输出声称覆盖全文的摘要。

### 2. 建立证据条目

- 逐节摘出主张、支撑证据、数字与限制。
- 数字连同分母、时间和单位一起记录。
- 把引用他人的观点与作者自己的判断区分。
- 为每条关键主张保留页码、段落或原文短语定位。

### 3. 按阅读目标筛选

- 快速了解优先保留主论点、关键证据和主要限制。
- 决策用途优先保留选择、成本、前提和未决问题。
- 转述用途保留作者语气强度，不把可能改成必然。
- 没有行动项的文章不硬编负责人和截止时间。

### 4. 压缩成可读摘要

- 用户要求三条时，每条集中表达一项重要结论。
- 每条尽可能带必要条件与简短出处。
- 删除重复例子，但保留能改变判断的反例。
- 在独立分析块中放推断，不混入原文结论。

### 5. 逐条回查

- 将摘要每句映射回证据条目。
- 重新检查数字、否定词、因果关系和适用范围。
- 检查是否遗漏与核心结论相冲突的段落。
- 找不到依据的句子删除或明确标为推断。

### 6. 按反馈重排

- 用户觉得太长时先删说明和例子，保留条件与出处。
- 用户追问依据时展开对应原文位置，不重写整份材料。
- 新版本到来时只比较改变结论的部分，注明版本。
- 交付后如无后续任务即可结束，不强加阅读训练。

## 直接交付与下一步

- 符合指定长度的重点摘要。
- 简短出处定位与影响结论的条件、分歧或缺页提示。
- 仅在用户需要时增加决策问题或行动项。
- 完成标准是读者能理解核心内容，并回到原文验证关键结论。

### 工具不可用时

- 无法读取附件或链接时，先处理已看到的正文；标注局部覆盖，给出需要补充的具体章节。
- 无法完成的关键检查要写明未验证项，不把计划或草稿称为已完成执行。

### 后续输入与收尾

- 用户交回实际结果或新材料后，先比较与本轮预期的具体差异。
- 只修正受影响的判断与产物；个人偏好不自动变成所有用户的默认要求。
- 一次性任务达到上述完成条件即可结束；仍有缺口时说明下一步需要什么。

### 外部参考与延展

- 触发：材料含陌生专业词、摘要反复丢失限定条件，或用户明确要求核验真实性。
- 先查材料自己的术语表、方法附录和引用的原始研究。
- 技术材料优先官方文档；统计结论优先原始报告和方法说明。
- 可搜索 GitHub “citation grounded summarization”，观察证据定位与分段合并机制。
- 比较机制能否避免跨段拼接、遗漏反对证据与单位错配，不仅比较输出流畅度。
- 采用后重跑同一材料并逐条回查；外部补充另列，不冒充原文已有信息。

### 可执行模拟演示

以下全部为明确模拟输入，不代表任何真实用户的经历或结果。

- 模拟原文：试点共40人，24人完成课程。完成者中18人表示满意。报告建议扩大试点，但指出缺少对照组，无法判断课程造成的效果。
- 阅读目标：三条重点，供负责人判断是否扩大。
- 摘要1：40人参加，24人完成，完成率60%（模拟原文第1句）。
- 摘要2：完成者中18人满意，占完成者75%；不能当作全部参与者满意率（第2句）。
- 摘要3：报告建议扩大试点，但无对照组，不能认定课程导致效果（第3句）。
- 回查：24/40=60%，18/24=75%；两者分母不同。
- 未添加：负责人、预算、扩大后的效果和未完成人员满意度。
- 验收：建议与事实分开，保留限制，不把方向性结果写成因果结论。

### 交付前检查

- 输出是否能回到本次输入，而非通用介绍？
- 关键事实与推断是否分开，未确认项是否清楚？
- 用户是否有一个明确可做的下一步？
- 工具执行与文件生成状态是否如实描述？
