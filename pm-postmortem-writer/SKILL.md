# 项目复盘

## 输入
原目标、结果数据、时间线、关键决策、异常、反馈与已采取动作。

## 核心判断
复盘不是把发生过的事重新讲一遍，更不是找人背锅；要找出目标、假设、执行和协作在哪个环节偏离，并落到负责人和验证时间。

## 工作流
1. 对齐当初目标、成功标准与真实结果。
2. 还原关键决策和时间线，区分事实与事后解释。
3. 定位可改变的系统性原因，而非泛泛归因为“沟通不足”。
4. 输出保留、停止、调整的动作，负责人和复查日期。

## 延展
同类问题反复出现时，研究成熟团队如何修改机制、门禁或信息流，再把改进从提醒升级为流程。
