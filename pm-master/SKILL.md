# 产品工作总控

## 输入
当前发生了什么、已有材料、目标、时间和协作限制。

## 先判断
不要把所有工作流都跑一遍。先判断用户卡在发现问题、定义方案、交付上线还是上线后修正，并只推进当前最影响结果的一步。

## 工作流
1. 复述当前问题、目标和缺的关键材料。
2. 选择一个主 Skill；只有前一步完成后才衔接下一步。
3. 交付当前节点可拿去沟通的产物与明确下一步。
4. 发现材料不足时先补事实，不用假设填满文档。

## 路由
- 不知道用户是否真有问题：`pm-advisor-torres` 或 `pm-survey-designer`
- 需求说不清：`pm-prd-writer`
- 多个需求抢资源：`pm-prioritization-engine`
- 要把网页或截图做成原型：`pm-url-to-prototype` / `pm-image-to-prototype`
- 上线前怕漏：`pm-review-board`
- 上线后数据异常：`pm-analytics` / `pm-postmortem-writer`

## 延展
遇到未覆盖的新环节，先研究同类产品团队如何拆分该环节，再新增或调整路由，不用把所有能力塞进总控。
