# 番茄小说单章写作

## 一句话主餐

普通聊天常把片段当章节；本技能把现有设定或上一章接成具有事件闭环和章末牵引的 2200—2800 字正文。

## 输入

- 先读作者设定、分章大纲、上一章末尾和已确定的人物关系。
- 确认本章是首章、承接章还是改稿，不能用同一开头模板处理。
- 确认叙述人称、题材和本章必须发生的事件。
- 默认正文按非空白字符计数，标点计入；平台另有口径时另行报告。
- 缺设定时可创作并标注新增内容；不得宣称掌握平台内部流量机制。

输入处理顺序：
1. 先核对上一章结尾的承诺、人名和物件；只有首章才可从新场景开始。
2. 给定大纲与上一章冲突时指出具体两句冲突，询问采用哪版，不自行改既定事实。
3. 缺字数口径时采用正文非空白字符含标点，不把此口径称为平台字数。
4. 只有设定时允许新增虚构事件；续章缺材料则提供假设续写并明确未验证连续性。

## 核心判断

1. 首章优先让读者看见主角处境与异常；续章优先兑现上一章悬念。
2. 本章只推进一个主事件，支线用于增加阻力而非抢占主题。
3. 信息钩子必须对应可继续发生的事，不能每章都靠昏迷或假死。
4. 2200—2800 是本任务交付长度，不将其描述为所有平台的强制规则。
5. 爽点、悬念与情绪选择应服从题材和作者风格，不强塞打脸模板。
6. 正文与章后说明分开计数；不靠重复心理描写填长度。

判断落地检查：
- 本章状态变化必须写成“原先不能/不知道什么，结尾能/知道什么”。
- 逐段检查是否增加信息、成本或选择；都没有的段落删除。
- 章末新问题必须来自本章结果，不能另塞毫无关系的新敌人。

## 编号工作流

### 1. 建立章节账本

- 提取上一章未兑现的问题。
- 锁定人物位置、持有物和已知信息。
- 记录本章要改变的状态。
- 首章从设定中选一个能当场发生的事件。
- 交付：起始状态与结尾状态对照。

### 2. 设计事件骨架

- 写进入事件、尝试、升级、决策、结果。
- 每次升级增加具体成本。
- 确认主角参与推动结果。
- 给每段分配大致篇幅，避免末尾仓促。
- 交付：五段事件骨架。

### 3. 写完整正文

- 以正在发生的行为开场。
- 必要设定嵌入行动或争执。
- 在中段让第一次方案受阻。
- 让主角选择产生可见结果。
- 交付：连贯单章初稿，不以大纲代替。

### 4. 核对连续性

- 逐项查人物知识是否越界。
- 查时间、物件和空间位置是否矛盾。
- 续章兑现前章至少一个承诺。
- 保留尚未解决但有作用的悬念。
- 交付：修正后的正文与连续性更新。

### 5. 计数与重写

- 使用本地脚本或编辑器计数正文非空白字符。
- 不足时补因果环节或必要行动。
- 超长时删重复说明，保留关键决策。
- 再次计数，给出实际口径及结果。
- 交付：2200—2800 字的完整正文；无法计数则标明尚未验证。

### 6. 交付与续接

- 章末留下由本章结果引发的新行动。
- 附本章新增人物与设定。
- 给下一章第一场景一个起点。
- 接收作者对节奏或人设的具体反馈再改稿。
- 交付：正文、计数、连续性账本。

## 直接交付与下一步

- 完整单章正文为主交付，必须与计数范围一致。
- 附篇幅口径、人物状态更新和下一章起点。
- 完成标准：长度合格、事件结果清晰、上一章关键事实无矛盾。
- 本轮暂不安排全书大纲或运营，除非作者明确要求。
- 无文件工具时给正文供用户粘贴计数；不把估计写成已校验。

交付前验收：
- 提取正文后实际计数，标题、围栏、字数说明和账本全部排除。
- 2200 与 2800 均为合格边界，2199 与 2801 必须继续返修。
- 比对人物已知信息、物件归属和时间线，新增规则必须留账。
- 续章至少兑现上一章一个具体悬念，不能全章重复提出同一问题。
- 计数与连续性分别报告，长度达标不等于因果链已通过。

## 外部参考与延展

- 比较 fiction-scene-starter 的单场目标与本技能章节账本：采用主动选择机制，保留单章事件闭环和长度约束。
- 公开写作机制可查 [OpenLearn](https://www.open.edu/openlearn/history-the-arts/creative-writing/start-writing-fiction/content-section-0)；平台事项检索番茄小说官网作家帮助，不以论坛经验冒充政策。
- 连续两章重复冲突时，比较承诺兑现和状态变化；字数不够时比较因果缺环，而非寻找凑字数技巧。
- 只把补缺机制用于本章；用改前改后的事件链、实测长度和上章账本验证，不推断签约与分发效果。

### 篇幅验收与返修动作

- 动笔先分配约 2500 字预算，给事件触发、受阻、决策和结果留空间。
- 计数以实际成稿为对象，禁止复制上轮计数结果。
- 可使用 Python：`len("".join(body.split()))`，body 只含正文。
- 少于 2200：找一处“发现后直接成功”的跳跃，补试探、阻力与反应。
- 高于 2800：优先删重复背景和心理同义句，保留行动因果。
- 改写任何段落后重数整章；不能只推算增删字数。
- 无计数工具：交付完整稿并标“长度待校验”，说明可用编辑器复核。
- 后续续章只需带回上章末尾和更新账本，不要求重交全书。
- 验证用完整单章见 [正文与可复核计数](references/example.md)。

材料已经足够时直接交付；引用外部资料只帮助选择机制，不替代用户输入。
收到同类失败反馈时保留原输入与旧输出，修订判断后以原案例重跑，并同步 README 与示例。
