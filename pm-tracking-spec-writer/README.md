# pm-tracking-spec-writer

## 它适合什么场景

埋点与指标设计方案生成器。从产品需求/核心链路出发，输出完整的埋点方案文档（事件、字段、触发时机、口径说明、QA 校验清单）。 触发条件：用户提到"埋点"、"tracking"、"事件设计"、"数据采集"、"上报方案"、"埋点方案"、"事件规范"、"字段设计"、"指标口径"、"数据验收"、"QA校验"等关键词。

## 它解决什么

它把「每次都要从头想一遍」的产品工作沉淀成固定流程：输入你的材料，按内置判断和工作流拆解，交付可直接使用的产物（文档、清单、报告或原型），不虚构数据、不替你拍板。

## 一个重要机制

**链路拆解成事件字典**：把产品目标和用户链路拆成事件、字段、触发时机、口径说明，附带 QA 校验清单，埋点方案可被测试直接执行。

## 你会拿到什么

- 结构化交付物（格式见 SKILL.md「输出」章节）
- 基于你提供的真实材料，信息不足时先问或标注 **[待确认]**
- 工具不可用时自动降级（如无 docx 则输出 Markdown）

## 怎么开始

```text
请调用 pm-tracking-spec-writer，帮我处理下面这件事：
（粘贴你的问题、材料或文件）
```

## 边界

- 不编造事实：缺信息会先问，确实需要假设时标注 **[假设]**
- 它是产品工作链的一环，复杂问题建议先用 `pm-master` 判断当前最该推进哪一步
