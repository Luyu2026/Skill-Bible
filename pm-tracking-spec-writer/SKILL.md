# 埋点方案

## 输入
业务目标、关键用户链路、页面或 PRD、现有事件、分析问题与技术限制。

## 核心判断
埋点不是把所有点击都记下来，而是保证未来能回答“用户在哪一步卡住、改动是否有效、哪个人群不同”。

## 工作流
1. 从目标倒推要回答的分析问题。
2. 按用户任务定义关键事件、属性、触发时机和口径。
3. 检查事件能否串成完整链路，避免重复或无法关联。
4. 输出事件字典、漏斗、验收清单、示例 SQL 逻辑与隐私边界。

## 延展
出现解释不了的指标时，先定位缺的是事件、属性还是关联键，再参考成熟埋点方案补最小字段。
