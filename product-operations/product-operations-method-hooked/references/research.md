# 《上瘾》（Hooked, Nir Eyal）——用户运营方法论提炼

> 用途：用户习惯养成与留存判断框架（非读书笔记）。面向用户运营/增长从业者。

## 1. 书籍概述
行为设计经典。提出"Hook 模型"：通过 触发→行动→多变奖励→投入 四步循环，让用户形成"一想到某种情绪/场景就打开产品"的条件反射，实现自发性高频回访，用习惯代替营销。

## 2. 核心框架

### 框架 A：Hook 模型（Hook Model / 上瘾循环）
**适用场景**：判断/设计"用户为什么回来"的完整留存闭环；诊断留存曲线断点在哪个环节。
**四步**：
1. **触发（Trigger）**：行为的启动器。外部触发=推送、邮件、短信、App 图标、他人邀请；内部触发=无聊、孤独、焦虑、好奇等情绪与日常场景的关联。**目标：从外部触发过渡到内部触发**——用户"一感到 XX 情绪就打开产品"（首想即得 wins）。
2. **行动（Action）**：触发后做的最简单的行为（打开、点击、滚动、发布）。依据 BJ Fogg 行为模型 B=MAP：行动概率 = 动机 × 能力 × 提示。**降低摩擦比提高动机更有效**；动作必须是"最小阻力"版本。
3. **多变的奖励（Variable Reward）**：不可预测的回报，制造"期待"而非"满足"，激活多巴胺"想要"系统。三类：
   - 奖励的猎奇（Reward of the Hunt）：找信息/找好货（刷动态、搜索、闲鱼捡漏）
   - 奖励的自我（Reward of the Self）：掌控感/完成感（打怪升级、打卡连胜、清单打勾）
   - 奖励的族群（Reward of the Tribe）：社交认可（点赞、评论、被 @）
4. **投入（Investment）**：让用户付出时间/数据/内容/社交资本/钱，使产品对用户"越用越值钱"；同时投入本身成为下一次循环的触发（如关注了人→下次来看他发了什么）。**投入≠付费终点，而是提高下次经过 Hook 概率的储蓄**。
**输出物**：一页 Hook 拆解表（每环节写清触发源/动作定义/奖励类型/投入物+对应埋点指标）；基于此定位留存漏斗中最弱一环并迭代实验。

### 框架 B：习惯形成的两个条件（Habit Zone）
**适用场景**：立项前判断"这个产品值不值得做习惯化运营"；避免在低频/低感知价值产品上浪费资源。
**两个条件同时满足才进入"习惯区"**：
1. **使用频率（Frequency）**：用户多久用一次（日/周/月频，越频越好养）；
2. **感知效用（Perceived Utility）**：用户主观觉得多有用（不是客观价值）。
> 例：Trapper Keeper 文件夹低频高感知效用→习惯弱；拍照/搜索高频高感知效用→习惯强。
**输出物**：按"频率×感知效用"给现有/候选产品打点，决定运营重心是"做习惯"还是"做触发提醒"。

### 框架 C：操纵矩阵（Manipulation Matrix）+ 痛点药片论
**适用场景**：上线前自查伦理与用户利益，决定某机制"能不能上"。
- 正交两轴：你制造的是**物质性**还是**非物质性**（情感）结果？用户用了是**变好**还是**变坏**？
- 四象限：**促进者**（帮用户变好，如健康打卡）、**兜售者**（帮用户但主要由用户付钱，如健身私教）、**娱乐者**（愉悦但不改善，如游戏）、**操纵者/药贩子**（伤害用户，如赌博、掠夺性借贷）。
- 维生素→止痛药：Hook 循环跑多了，"维生素"会变成"止痛药"——用户产生"不用反而难受"（FOG：fear of missing out 之外的"害怕错失"型不适感）。警惕"创造一个新的痛苦再声称自己能治它"。
**输出物**：每个留存机制上线前填一张矩阵自评表；建立"是否新增用户痛苦"红线清单。

## 3. 决策规则（If X → Then Y）
1. 如果用户触发全部依赖外部提醒（推送/短信/邮件）→ 说明内部触发未建立，先做"情绪×场景"绑定（让用户在特定时刻/情绪下自然想起产品），再做频率运营。（来源：框架A-触发；nirandfar）
2. 如果要做某个目标动作但转化率低 → 先砍摩擦（步骤、表单、加载、决策成本），不要先加动机/加奖励；B=MAP 里能力比动机更可控。（来源：框架A-行动）
3. 如果奖励是固定可预期的（签到固定积分/固定礼包）→ 换成可变奖励（随机掉落/开盲盒式），否则循环会退化为无好奇心的"灯光开关"。（来源：框架A-多变奖励）
4. 如果用户已养成高频使用但留存仍掉 → 检查"投入"环节：是否让用户积累数据/关系/内容资产；投入缺失则产品对用户不涨价值，竞品一出现就流失。（来源：框架A-投入）
5. 如果产品使用频率低（周/月频以下）且感知效用一般 → 不要投入做"习惯化"，改为高价值低频触发（关键节点提醒/周期性召回），或接受非习惯型定位。（来源：框架B-习惯区）
6. 如果机制属于操纵矩阵"操纵者/药贩子"象限（伤害用户）→ 不上线或重构为促进者/娱乐者；留存不得建立在对用户利益的损害上。（来源：框架C；书中第八章）
7. 如果要设计"投入"引导 → 放在奖励之后（多巴胺预期高峰）立刻请求，此时用户最愿意付出；且投入物必须提升下一次触发/行动/奖励。（来源：框架A-循环时序；gopractice 引 Eyal 原句）
8. 如果产品已形成"不用就难受"的依赖 → 视为成瘾信号而非成功信号，主动降频设计（如提醒节流、默认关闭、退出路径清晰）。（来源：框架C-维生素变止痛药；Yukaichou）

## 4. 检查清单（新机制/新版留存方案上线前）
- [ ] 触发：写清了外部触发（谁、何时、什么文案）？有明确计划把用户迁移到内部触发（情绪×场景）？
- [ ] 触发：是否绑定用户已有习惯/情绪（而非创造新场景）？首想即得：用户会"一无聊/一心烦就想到我"吗？
- [ ] 行动：目标动作是用户能力范围内的最小动作？列出并删掉了至少 3 处摩擦？
- [ ] 行动：动作与触发间隔足够短（3 秒内可完成第一步）？
- [ ] 奖励：奖励是可变/不可预测的吗？属于三类（猎奇/自我/族群）中哪一类？可感知吗？
- [ ] 奖励：奖励是否只满足"想要"而非"需要"的成瘾式设计？（对照操纵矩阵）
- [ ] 投入：有让用户存储价值（内容/关系/偏好/资产）的环节吗？投入物是否提升下一次循环？
- [ ] 循环：上一轮"投入"是否成为下一轮"触发"？（闭环没闭合=靠推送续命）
- [ ] 频率×效用：产品在"习惯区"吗？运营目标与产品真实频率匹配吗？
- [ ] 伦理：该机制在操纵矩阵哪一象限？是否新增了用户痛苦（FOG/不用难受）？有无退出/降频机制？

## 5. 反模式（书中/业界反复警告的错误）
1. **把"成瘾"当成功**：用可变奖励+投入把维生素产品做成止痛药，用户"不用就难受"——这是制造痛苦再兜售解药，长期引发投诉、监管与口碑反噬（案例：掠夺性游戏抽卡、赌博式电商）。
2. **奖励固定化**：把多变奖励做成固定签到/定额返利，循环退化为无聊反馈回路，用户动机熄火、留存曲线平掉。
3. **只靠外部触发续命**：永远用推送/短信拉回，不做内部触发迁移——成本随盘子增大线性膨胀，一旦推送受限（合规/卸载）留存崩塌（对照：Groupon 未闭环而衰退）。
4. **忽略投入的复利**：做完触发-奖励就结束，没有让用户累积内容/关系/资产；产品对每个用户永远是"一次性价值"，无迁移成本，无法抵御竞品。
5. **为留存牺牲用户利益**：用虚假稀缺、连续损失、隐性扣费操纵；操纵矩阵"药贩子"象限的做法短期拉指标、长期毁品牌。

## 6. 边界声明
1. **必须服务于真实用户价值**：Hook 循环的前提是产品解决真实痛点；无价值产品套 Hook 只会加速口碑崩坏（书中反复强调"习惯≠上瘾"）。
2. **不适用于所有产品**：低频、低感知效用、一次性消费型产品不宜强行做习惯化运营（习惯区条件）；工具类产品用户"用即走"也可能健康。
3. **伦理争议未解决**：模型本身被批评"制造成瘾机制而不解决伦理"（Yukaichou：黑帽动机盲区；操纵矩阵是起点而非答案）；道德化使用依赖团队自律。
4. **适用范围偏消费互联网**：模型以 C 端 App/社交/游戏为样本，对 B2B、低频高客单、监管行业（医疗/金融）需大幅改造并叠加合规约束。
