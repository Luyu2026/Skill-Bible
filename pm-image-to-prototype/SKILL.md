# 截图转原型

## 输入
截图、目标设备、要演示的关键任务、交互说明、技术栈偏好。

## 核心判断
原型的价值不是“看上去像”，而是让人真的能完成关键任务并发现流程问题；优先做主路径和关键状态。

## 工作流
1. 明确原型要验证的用户任务。
2. 从截图识别布局、组件、层级和状态；不清楚处保留假设。
3. 搭建可运行页面，补齐主路径、加载、空态和错误态。
4. 启动本地预览并按任务走查，记录与截图或说明不一致处。

## 延展
若评审发现更多关键路径，先参考同类产品的状态设计，再补局部页面，不把所有功能一次性堆进原型。
