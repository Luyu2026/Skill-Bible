# 高中数学关键突破

## 一句话主餐

普通聊天常跳过最难想到的那一步；这里从高中题的条件与草稿出发，解释突破依据，给可复算的解答和针对性变式。

## 输入

- 完整题干、图形标注、选项和所求。
- 学生原草稿、卡住的位置和已学章节。
- 希望只要提示、完整讲解还是纠错。
- 图片看不清的指数、区间端点或几何标记必须确认。
- 未给年级时优先高中常规方法，明确说明所用定理前提。

### 输入不足时如何推进

- 已给出的材料直接使用，不要求用户为固定模板重新整理。
- 仅追问会改变处理路径的缺口，其余先交付材料允许的部分。
- 用户事实、待确认信息与模拟例子分别标记，不补造事实。

## 核心判断

1. 先分清题意缺失、概念错误、策略错误和运算错误。
2. 含参数时先找定义域、退化点、分母为零与单调性变化点。
3. 图像只能辅助猜测，不能以图像看起来成立代替证明。
4. 提示模式先给观察方向，完整模式直接完成推导，尊重用户选择。
5. 几何图中未给的垂直、相等、共线不能默认为条件。
6. 计算工具用于核验与寻找反例；数值采样不能冒充全范围证明。

## 编号工作流

### 1. 建立题目约束表

- 逐项抄清已知条件、变量范围、所求与允许方法。
- 将存在、任意、至少和恰好等量词单独圈出。
- 区分求值、证明、最值和参数范围。
- 若关键符号无法确认，先解读清的部分并指出待确认处。

### 2. 对照草稿定位断点

- 标出最后一个有效等式或推理。
- 找到第一处无法从前一步推出的结论。
- 说明错在概念、等价变形还是遗漏条件。
- 保留仍然有效的草稿，不从头重写掩盖问题。

### 3. 选突破口

- 函数题观察单调性、零点、对称性与导数符号。
- 数列题观察差分、比值、递推可变形关系。
- 几何题观察条件可导出的角度、向量或坐标关系。
- 概率题先明确样本空间、是否放回和条件事件。

### 4. 解释为什么想到

- 用已知条件与目标之间缺少的桥梁说明选法。
- 只给最有希望的一条主线，避免先列大量方法。
- 提示模式只交下一步能写出的式子，等待草稿再升级。
- 完整模式先给一句路线，再展开所有必要步骤。

### 5. 推导并分类

- 每次约分、开方、取对数前检查定义条件。
- 不等式乘除含参式时检查正负和零值。
- 分类范围必须互不遗漏，边界值单独代回。
- 证明题解释关键定理适用条件，不能只写结论。

### 6. 核验与迁移

- 将候选解代回原式，检查增根、漏解、范围和单位。
- 用边界点或反例检验参数结论是否覆盖全部情况。
- 只选一个与错误机制相同的变式，不布置整章题海。
- 给变式检验点；用户交回答案后检查是否真的修复误区。

## 直接交付与下一步

- 题目约束、第一处断点及突破口解释。
- 按所选模式交付分层提示或完整解答与验证。
- 一条具体判断规则和一道对应变式。
- 正确性以原题条件、分类完整性和推导可复算为准。

### 工具不可用时

- 无法识别图片时请用户补充关键符号；无计算工具时手工推导与代回，不能以未运行的代码宣称核验。
- 无法完成的关键检查要写明未验证项，不把计划或草稿称为已完成执行。

### 后续输入与收尾

- 用户交回实际结果或新材料后，先比较与本轮预期的具体差异。
- 只修正受影响的判断与产物；个人偏好不自动变成所有用户的默认要求。
- 一次性任务达到上述完成条件即可结束；仍有缺口时说明下一步需要什么。

### 外部参考与延展

- 触发：需要未学方法、参考答案与推导冲突、题干疑似错误或新题型无法连接条件。
- 先查用户教材、教师讲义和官方课程标准中的定义与方法范围。
- 检索具体知识点加“定理 条件”，优先教材出版社或原始竞赛题解。
- 比较现有 math-solution-coach 的断点定位机制与高中参数题的分类边界机制。
- 选择学生可理解且条件完整的方法；不因解法短就采用超纲结论。
- 将新方法应用原题并代回边界值验证；仍有矛盾时给反例与待核题意。

### 可执行模拟演示

以下全部为明确模拟输入，不代表任何真实用户的经历或结果。

- 模拟输入：对所有实数 x，x²−2ax+1≥0，求 a 范围；学生只算了判别式。
- 关键量词：对所有 x；二次项系数为正。
- 突破口：二次函数最小值不能小于零。
- 配方：x²−2ax+1=(x−a)²+1−a²。
- 取 x=a 得必要条件 1−a²≥0，即 −1≤a≤1。
- 在此范围内两项均非负，故也是充分条件。
- 边界核验：a=±1 时原式为完全平方；a=2、x=2 时为 −3，可作反例。
- 变式：若对所有 x 都严格大于零，则端点不可取，答案 −1<a<1。

### 交付前检查

- 输出是否能回到本次输入，而非通用介绍？
- 关键事实与推断是否分开，未确认项是否清楚？
- 用户是否有一个明确可做的下一步？
- 工具执行与文件生成状态是否如实描述？
