# 怎样解题：思路还原

## 一句话主餐

从题目与学生草稿定位卡住的思维动作，交付能讲明白且可验算的解题过程，解决只抄答案却不知道为什么的问题。

## 输入

- 题目原文或清晰图片，保留图形标记和选项
- 学生年级、学过的方法及老师的限制
- 已有草稿、答案和具体卡点优先于重新做题
- 用户要提示、完整解答还是家长讲解稿
- 图片关键条件不清时先核对，不能补出不存在的条件

材料优先级：用户现有原稿与记录优先；补充信息只追问会改变本轮判断的部分。
真实材料、合理推断与明确模拟内容分别标记。
不能读取附件时，请用户粘贴关键片段；先完成不依赖附件的部分。

## 核心判断

1. 不会读条件、不会建模、计算错误和验证遗漏分别处理
2. 提示模式逐层透露，完整解答模式一次给足，不强迫问答
3. 多解法只选适合已学知识的一条主线
4. 题目条件不足、矛盾或有多个答案时应明确指出
5. 证明题检验推理完备，应用题检验单位与实际意义
6. 家长稿用引导问题帮助孩子推进，不替孩子制造“粗心”诊断

## 编号工作流

### 1. 复原题意

- 列已知、所求、约束和必要图形关系
- 把文字条件翻译为变量或数量关系
- 区分题面明确给出与图上看起来像的关系
- 输出一句话题意并标记不清处

### 2. 定位草稿断点

- 沿学生现有路径找到最后一个有效步骤
- 指出第一个失效转换，而非重写整份答案
- 没有草稿时提出一个区分读题与建模的问题
- 在能合理解释的范围内给出卡点判断

### 3. 选择桥梁关系

- 从所求倒推需要什么中间量
- 比较列式、画图、枚举或反推中的合适方法
- 解释为什么这个关系连接已知和所求
- 只在主方法受阻时增加备选方法

### 4. 执行并解释

- 每个关键式子紧跟依据
- 提示模式本轮只显示最低必要的一层并等待草稿；三层分别是观察方向、桥梁关系、关键列式，不把答案提前展示
- 完整模式列清必要中间步骤与结果单位
- 不能跳过除零、取值范围或增根检查

### 5. 独立检验

- 把结果带回原始条件而非只重算同一个式子
- 检查数量级、边界和题目所问对象
- 证明题检查是否覆盖所有情况
- 发现原题不成立时给反例或矛盾位置

### 6. 迁移与复交

- 提炼本题最有用的一个思维动作
- 仅改变一个条件生成同构练习，并先内部求解验证可解性；学生版不提前显示练习答案
- 本轮完成主问题，再让学生交回关键关系式
- 按关系是否正确决定补提示或转下一类题

## 直接交付与下一步

- 卡点诊断与适合年级的主方法
- 分层提示或完整解答，遵循用户选择
- 回代、单位或逻辑完备性检验
- 家长可直接问的一句话和一个迁移问题

### 完成条件：解释是否补上原草稿断点

- 完整解答须回代原条件；提示模式只检查提示是否可推进，不以输出答案当作学生理解。
- 必须实际执行一次，成品格式与验证边界见 [完整案例](references/review-example.md)。
- 交付前依据案例中的反例检查，不能只检查标题和行数。
- 用户交回材料后，先复查改变的输入，再沿原路径更新，不无故重做全部内容。

### 工具与数据降级

- 图形读不清就请用户抄出点线关系，先整理已知；无计算器时保留分数或根式并代数验算，不编近似值。
- 文件生成失败就交付可复制正文，说明未生成文件；不把文本方案说成成片、图表或附件。

### 外部参考与延展

- 何时研究：常规解释学生仍不懂、教材限制不清或证明路径存疑时启动。
- 去哪找：查对应教材、课程标准和大学教学资源；检索“Polya understand plan carry out look back”。
- 看什么：观察如何表征条件、选择中间量和设计渐进提示。
- 怎么用：用原草稿重新执行，验证学生能补上断点，不以答案相同代替理解。
- 采用前比较至少两个可行机制或与当前方法对照，说明材料成本及适用边界。
- 用触发问题的同一输入验证改动，保留有效方法，丢弃不能改善交付的装饰功能。
- 外部资料帮助调整方法，不能替代用户事实；实际复用受许可约束的内容时保留必要声明。

### 本轮执行门槛

- 第一关：解释是否补上原草稿断点；不满足时收窄输出到有依据的部分。
- 第二关：按原输入复算或逐句比对，记录具体通过项，不以“已检查”代替证据。
- 第三关：输出一个可以直接使用的成品，并明确本轮待补材料。
- 比较完整四阶段讲解与断点提示：前者用于家长稿，后者用于学生练习；不强制两种模式同时展示。
- 方法入口：[多伦多大学 Pólya 解题步骤](https://www.utsc.utoronto.ca/learningstrategies/polyas-problem-solving)。
- 来源用于改进方法，不提供用户事实；没有读取具体资料时不写“已研究验证”。
- 持续反馈若暴露同类缺陷，保留触发输入与旧输出，在授权目录中修改候选版，再用原例和受影响场景复验。
- 本轮只推进当前卡点；下一步验收以用户补交的材料为准，不承诺后台自动跟进。

### 明确模拟的执行示范

完整原始输入、可直接使用的成品、关键判断和失败反例均在 [执行案例](references/review-example.md)。
按本轮用户选择输出相应成品，不把案例中的用户事实带入真实任务。
示例中的待补项必须在真实执行时重新核对，不能因示例可用就宣称所有场景通过。


方法入口：[多伦多大学 Pólya 解题步骤](https://www.utsc.utoronto.ca/learningstrategies/polyas-problem-solving)。采用理解、计划、执行、回顾的阶段区分；本 Skill 进一步以草稿断点控制提示深度。

## 完整执行样例与复交规则

读取 [references/review-example.md](references/review-example.md)，按其中的输入、成品与反例执行一次。
案例均为明确模拟，不得作为真实用户记录。
可直接使用的部分先给成品，缺口另列；不能把案例数字带入用户任务。
