# 《The Business of Belonging》（归属感生意）方法论提炼

## 一、核心框架

### 1.1 归属感设计框架（为什么聚 → 谁聚 → 怎么聚 → 留下）
- **适用场景**：社区冷启动与定位、社区价值主张设计
- **步骤**：
  1. **为什么聚**：定义社区的核心归属感来源（共同身份/共同目标/共同兴趣/共同困境）
  2. **谁聚**：定义理想成员画像（不贪大，先服务核心人群）
  3. **怎么聚**：设计连接方式（话题/活动/仪式/线上线下的触点）
  4. **留下**：设计归属感强化机制（仪式/荣誉/关系/成长）
- **输出物**：社区归属感设计卡（价值主张+成员画像+连接设计）

### 1.2 社区驱动增长框架（Community-led Growth）
- **适用场景**：论证社区商业价值、社区作为增长引擎
- **步骤**：
  1. **留存**：社区提升产品留存（归属感降低流失）
  2. **口碑**：社区成员自发传播（信任背书）
  3. **共创**：社区反馈驱动产品迭代（用户共创）
  4. **转化**：社区成员转化路径（免费成员→付费成员/产品用户）
- **输出物**：社区商业价值论证（留存/口碑/共创/转化四维）

### 1.3 社区商业化阶梯（免费→付费→高阶）
- **适用场景**：社区商业化路径设计
- **步骤**：
  1. **免费层**：核心社区价值免费（归属感基础）
  2. **付费层**：进阶价值付费（深度内容/专属活动/身份特权）
  3. **高阶层**：高阶服务（咨询/共创/私董会）
- **输出物**：社区商业化阶梯方案

## 二、决策规则（8条，标注章节）

1. **如果**社区定位不清，**则**先定归属感来源（成员为什么聚在一起）（第2章 归属感）
2. **如果**要论证社区价值，**则**用四维框架（留存/口碑/共创/转化）而非单讲活跃（第5章 社区驱动增长）
3. **如果**商业化过早，**则**伤害信任；先建归属感再谈付费（第7章 商业化）
4. **如果**做付费社区，**则**免费层必须有真实价值（不是纯付费墙）（第7章 商业化阶梯）
5. **如果**社区不活跃，**则**检查连接设计（成员之间有没有关系），不是加内容（第3章 连接）
6. **如果**要规模化，**则**先建系统（机制/志愿者），不靠社区经理个人（第6章 规模化）
7. **如果**成员流失，**则**检查归属感是否弱化（仪式/关系/价值衰减）（第4章 留存）
8. **如果**社区与业务目标脱节，**则**重新对齐（社区要服务业务，不是自嗨）（第5章 目标）

## 三、检查清单

- [ ] 归属感来源明确（共同身份/目标/兴趣/困境）
- [ ] 理想成员画像清晰
- [ ] 连接设计（成员之间有关系的机制）
- [ ] 归属感强化机制（仪式/荣誉/成长）
- [ ] 免费层有真实价值
- [ ] 商业化阶梯设计（免费→付费→高阶）
- [ ] 系统化建设（机制/志愿者，不依赖个人）

## 四、反模式

- 把社区当客服渠道（只有服务没有归属）
- 只看规模不看归属感（大而空的群）
- 商业化过早（信任没建就收割）
- 社区经理一个人扛所有（无系统无志愿者）
- 社区与业务脱节（自嗨型社区）

## 五、边界声明（≥3条）

- 经验以海外社区（Discord/CMX 等）语境为主，中国社群（微信/知识星球）生态需适配
- "归属感"叙事有理想化倾向，商业社区现实更功利
- 社区驱动增长需要产品适配（非所有品类适用）；短期 ROI 难量化
- 作者立场：社区布道者，有"社区万能"倾向，产品力仍是基础
