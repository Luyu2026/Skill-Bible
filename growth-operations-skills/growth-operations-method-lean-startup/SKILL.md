# 《精益创业》· 增长实验方法论

> 本 Skill 由 [陆羽Skill](https://github.com/Luyu2026/Skill-Bible/tree/main/luyu-skill) 生成。

> Build-Measure-Learn 循环 + MVP + 创新核算 + 三种增长引擎，判断增长想法如何低成本验证、实验如何沉淀认知。

## 核心框架

### 1. Build-Measure-Learn 反馈循环
- **适用场景**：增长实验/新功能验证/新方向探索
- **步骤**：Build（最小可测产品）→ Measure（量化指标）→ Learn（判断假设成立与否 → 坚持或转型）→ 加速循环
- **输出物**：一轮实验记录（假设/做法/数据/结论/下一步）

### 2. MVP + 经证实的认知（Validated Learning）
- **适用场景**：判断增长想法是否值得投入
- **步骤**：写可证伪假设 → 最小成本验证（落地页/原型/灰度）→ 用真实数据证明或否定
- **输出物**：验证结论 + 是否放大的决策依据

### 3. 三种增长引擎
- **适用场景**：判断业务靠什么增长、增长卡在哪
- **步骤**：识别引擎 → 找关键指标 → 优化对应杠杆
  - 粘着式：关键指标是流失率，优化留存机制
  - 病毒式：关键指标是 K 因子，优化分享机制
  - 付费式：关键指标是 CAC/LTV，优化投放效率
- **输出物**：增长引擎判断 + 对应关键指标

## 决策规则（8条）

1. 想法无法写成可证伪假设 → 不做（不可学习）
2. 能用最小成本验证 → 不用完整产品（MVP 优先）
3. 数据不能驱动决策 → 是虚荣指标，换可行动指标
4. 实验显示假设错误 → 认真考虑转型，而非加倍投入
5. 业务靠留存增长 → 聚焦流失率（粘着式引擎）
6. K 因子 < 1 → 病毒增长未成立，优化传播机制而非放量
7. CAC > LTV → 付费引擎不可持续，降 CAC 或提 LTV
8. 增长指标与核心价值无关 → 重新选指标（创新核算）

## 检查清单

- [ ] 假设可证伪（有指标与阈值）
- [ ] 用了 MVP（没有过度开发）
- [ ] 指标可行动（避免虚荣指标）
- [ ] 明确了坚持/转型的决策标准
- [ ] 增长引擎明确（粘着/病毒/付费）
- [ ] 每次实验沉淀了认知（无论成败）

## 反模式

- 花大量资源做完美产品再验证（跳过 MVP）
- 用"感觉/直觉"代替数据决策
- 虚荣指标（下载量/浏览）当核心指标
- 实验失败后否认数据、加倍投入（沉没成本）
- 同时跑多个引擎/方向（没有焦点）

## 边界声明（≥3条）

- 以不确定性高、可快速迭代的互联网产品为主，重资产/强监管行业 MVP 节奏受限
- 过度 MVP 可能伤害品牌与早期口碑
- 用户量小时数据统计不可靠，易被噪音带偏
- 作者立场：方法论而非实证研究，案例有选择性
