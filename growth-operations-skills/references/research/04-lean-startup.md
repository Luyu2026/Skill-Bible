# 《精益创业》（The Lean Startup）方法论提炼

## 一、核心框架

### 1.1 Build-Measure-Learn 反馈循环
- **适用场景**：任何增长实验/新功能验证/新方向探索
- **步骤**：
  1. **Build**：把假设做成最小的可测产品（MVP）——只做验证假设所需的最小功能
  2. **Measure**：用可量化指标衡量用户行为（不是"感觉好不好"）
  3. **Learn**：从数据判断假设成立与否 → 坚持或转型（pivot）
  4. 循环加速：越快跑完一轮，认知越快
- **输出物**：一轮实验记录（假设/做法/数据/结论/下一步）

### 1.2 MVP + 经证实的认知（Validated Learning）
- **适用场景**：判断一个增长想法是否值得投入
- **步骤**：
  1. 写可证伪假设："如果做 X，则指标 Y 提升 Z%"
  2. 用最小成本验证（原型/落地页/人工模拟/灰度）
  3. 用真实数据证明或否定假设（经证实的认知）
- **输出物**：验证结论 + 是否放大的决策依据

### 1.3 三种增长引擎（Growth Engines）
- **适用场景**：判断业务靠什么增长、增长卡在哪
- **步骤**：识别当前引擎 → 找到该引擎的关键指标 → 优化对应杠杆
  - **粘着式引擎**：靠留存与流失率——关键指标是流失率（churn），优化留存机制
  - **病毒式引擎**：靠传播系数（K 因子）——K > 1 才能自增长，优化分享机制
  - **付费式引擎**：靠付费获取——关键指标是 CAC 与 LTV，优化投放效率
- **输出物**：增长引擎判断 + 对应关键指标

## 二、决策规则（8条，标注章节）

1. **如果**想法无法写成可证伪假设，**则**不做（假设不可证伪=无法学习）（第5章 测试假设）
2. **如果**能用最小成本验证，**则**不用完整产品验证（MVP 优先）（第6章 测试）
3. **如果**数据不能驱动决策，**则**该数据是虚荣指标，换可行动指标（第6章 经证实的认知）
4. **如果**实验显示假设错误，**则**认真考虑转型（pivot），而非加倍投入（第8章 转型还是坚持）
5. **如果**业务靠留存增长，**则**聚焦流失率（粘着式引擎）（第7章 增长引擎）
6. **如果**K 因子 < 1，**则**病毒增长未成立，需优化传播机制而非放量（第7章 病毒式引擎）
7. **如果**用户获取成本高于用户生命周期价值，**则**付费引擎不可持续，降 CAC 或提 LTV（第7章 付费式引擎）
8. **如果**增长指标与核心价值无关，**则**重新选指标（创新核算：只衡量真实进步）（第7章 创新核算）

## 三、检查清单

- [ ] 假设是否可证伪（有明确指标与阈值）
- [ ] 是否用了最小可行产品（没有过度开发）
- [ ] 指标是否可行动（避免虚荣指标）
- [ ] 是否区分了"坚持/转型"的决策标准
- [ ] 增长引擎是否明确（粘着/病毒/付费）
- [ ] 每次实验是否沉淀了认知（无论成败）

## 四、反模式

- 花大量资源做完美产品再验证（跳过 MVP）
- 用"感觉""直觉"代替数据决策
- 虚荣指标（下载量/页面浏览）当核心指标
- 实验失败后否认数据、加倍投入（沉没成本）
- 同时跑多个引擎/多个方向（没有焦点）

## 五、边界声明（≥3条）

- 精益创业以"不确定性高、可快速迭代"的互联网产品为主，重资产/强监管行业（医疗/金融/制造）MVP 节奏受限
- 过度 MVP 可能伤害品牌与早期口碑（用户以为买到完整产品）
- 数据驱动在用户量小时统计不可靠，易被噪音带偏
- 作者立场：Lean Startup 是方法论而非实证研究，案例有选择性
