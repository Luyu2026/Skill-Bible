# 八字紫微双盘核验

## 一句话主餐

建立统一生辰口径并分别核验八字与紫微盘，交付来源清楚的结构表与差异定位，避免凭记忆拼盘和用双盘互证命运。

普通聊天容易把日期换算正确当成盘面也正确。本技能先固定生辰和排盘参数，分别取得并核验八字、紫微结构，遇到分歧交付可以复现的差异表。

## 输入

- 出生日期、原始历法、公历或农历及是否闰月
- 出生地到城市、当地钟表时间、时区和时间精度，不要求详细地址
- 历史夏令时、是否使用真太阳时及换日规则，如用户已知
- 已有排盘截图、工具名称、版本、参数和宫位或四柱文字
- 需要大运等功能时才收集该工具明确必需的规则参数，说明用途

### 材料处理

- 优先读取已给原稿、附件和记录，不要求重复填写。
- 只追问会改变当前路径的缺口，其他缺失放在相关判断旁。
- 来源无法打开时使用用户摘录，并写明尚未独立核验。
- 用户事实、工具结果、合理推断与纯模拟分别标记。
- 不把演示数据移植成真实用户材料。

## 核心判断

1. 八字和紫微是不同传统系统，输入共享不意味着结果可互相证明。
2. 历法转换是可核验计算，吉凶解读是传统文化解释，两者分栏。
3. 未配置可靠算法或工具时不能自称已算出四柱与星曜位置。
4. 子时、闰月、节气、历史时区与夏令时边界可能改变盘面。
5. 紫微流派在闰月、四化和起运规则可能不同，先对齐规则再比较。
6. 缺时辰时可核验日期，但不伪造时柱、命宫或完整十二宫。

### 本轮执行门槛

- 完整生辰且有可靠工具：分别执行两套算法，保留参数和原始返回；未执行不能写已排盘。
- 已有截图：先逐格转录和确认 OCR，再核对参数；只能证实转录时标“仅转录”。
- 缺出生时刻：核验已知日期，保留候选时段，不生成唯一时柱、命宫或十二宫结论。
- 无可靠算法：交输入核验和可粘贴到工具的参数卡；盘面明确未计算，不把参数卡算作排盘成功。

## 编号工作流

### 1. 冻结原始生辰

- 逐项复述用户提供的日期、历法、地点和钟表时间。
- 不擅自把农历当公历。
- 保留原始记录与转换值两列。
- 记录时间为准确、约略或不详。
- 交付输入核对单。

### 2. 明确历法和时间规则

- 确定时区、夏令时与使用的时间尺度。
- 核实闰月标记。
- 说明八字换年换月及换日口径。
- 说明紫微闰月、四化和起运规则。
- 规则不明先列候选参数，不能悄悄采用默认值。

### 3. 取得工具输出

- 优先读取用户现成盘和能说明参数的排盘工具。
- 分别保存八字四柱与紫微十二宫输出。
- 记录工具名、版本、访问时间和参数。
- 没有工具时交付待填核验表，不手算补齐未知星曜。
- 不得把漂亮盘图当成已验证算法。

### 4. 核对确定部分

- 公农历转换用独立历法资料核验。
- 四柱与紫微分别按各自规则检查，不互相投票。
- 核查截图文字是否存在 OCR 错位。
- 缺宫位、星曜或时柱标记缺失。
- 交付确定、待核验与不适用清单。

### 5. 定位双盘或工具差异

- 先比较输入与时区，再比较换日、闰月与流派规则。
- 一次只改变一个参数，定位导致差异的条件。
- 出生时间跨边界时并列候选盘及需要的确认材料。
- 不通过编造过往灾祸来反推时辰。
- 交付差异矩阵和复现参数。

### 6. 解释与交付

- 八字表列年、月、日、时及核验状态。
- 紫微表列宫位、主星和来源，缺项保留空缺说明。
- 术语用传统象征语言解释，不推断健康、寿命或必然财富。
- 用户只要排盘则在核验表结束，不附加算命内容。
- 下轮补正确参数或来源后仅重算受影响部分。

## 直接交付与下一步

- 原始生辰、转换与流派参数表。
- 分别有核验状态的八字四柱和紫微宫位表，或明确未计算状态。
- 工具差异定位、候选盘与最少补充材料。

### 参数卡与状态词

原始日期、历法、闰月标记、城市、当地钟表时间、时间精度分别保留。
转换后日期与采用时区另列，不能覆盖用户原始输入。
排盘工具名、版本、实际执行时间、换年换月日界、时间尺度均须记录。
紫微另列闰月、四化、安星口径；工具未公开的参数写未披露，不宣称已核验。
大运等方向参数按工具实际要求收集，说明用途，不从姓名或照片推断。
状态限定为：未计算、仅转录、已工具计算、已按所列范围核验、冲突待解。
“已按所列范围核验”必须说明核验的是历法、参数还是某项排盘规则。
天文台日期对照仅支持历法核对，不能证明日柱、安星或吉凶解释正确。

### 盘面与差异表的交付规格

八字表固定列年柱、月柱、日柱、时柱；每项附原始输出和状态。
紫微表按用户盘面的十二地支宫位顺序逐格列宫名、主星、来源及状态。
没有原始盘时不预填宫名与主星；仅给结构和未计算原因。
同一宫位的星曜不得因截图换行而挪到相邻宫位。
截图看不清写“无法辨认”，请用户补该局部，不靠常见组合补齐。
比较两盘时先对齐同一生辰、时间尺度和全部规则，再比较结果。
一次仅改一个参数；若无法重跑，结论为可能原因而非已定位根因。
差异表字段：字段／工具 A／工具 B／共同参数／唯一变化／能否复现／影响范围。

### 完成、恢复与隐私

成功排盘需两套原始输出和结构表，不能只交文化说明。
核验请求可在有来源的差异表完成；不能复算时明确核验未完成部分。
算法不可用时参数卡是降级交付，标题写“排盘待执行”，列工具需要的字段和待补项。
出生范围跨日界时并列候选参数，不把某一候选当唯一盘面。
用户补时刻或工具参数后新开版本，保留旧值及受影响字段。
不需要姓名、精确住址或证件；公开案例只用明确模拟材料。
用户只要求结构时不追加命运解读，解释请求另标传统文化口径。

## 外部参考与延展

- **何时研究**：节气边界、子时换日、闰月或不同工具盘面不一致时启动。
- **去哪找**：公农历查香港天文台对照表 https://www.hko.gov.hk/tc/gts/time/conversion.htm；时区查 IANA tz database；星曜规则查所用工具文档及有版本的传统资料。
- **看什么**：重点比较历法、夏令时、真太阳时、日界、闰月和四化映射，不能只比解释文案。
- **怎么用**：同一输入按明确参数复现差异；日期换算验证不能冒称星曜算法已经验证，缺工具保留未计算。
- 将 [香港天文台历法对照](https://www.hko.gov.hk/tc/gts/time/conversion.htm)、[IANA 时区数据库](https://www.iana.org/time-zones) 与排盘工具文档分工比较：前两者校验历法和民用时间，后者说明算法口径；不能用两款共用同一算法的网页当独立证明。
- 来源热度只用于发现，不代表方法有效；原始规则优先于二手总结。
- 材料已经足够时直接交付，不机械追加联网研究。
- 外部方法只改变执行机制，不能创造用户经历、报价或个体事实。
- 若实际复用受许可约束内容，保留所需声明；独立改写不等于可以忽略许可。

### 交付前验收

1. 每个确定结论都能回到材料、计算或明确设定。
2. 关键数字、日期、资格和限制没有在改写中发生变化。
3. 交付与用户当前目标一致，没有串入无关阶段。
4. 复制正文即可使用，依赖工具的暂停部分有可操作恢复条件。
5. 不把模拟验证称为真实用户效果，不承诺未经测量的收益。

### 明确模拟的执行示范

只给农历五月初五晚上、上海，缺年份，无算法。成品保留四柱及十二格未计算状态、补充请求；另比较23:00和00:00日界参数，未重跑就不声称已定位盘面根因。
