# 朋友圈活动海报制作

## 一句话主餐

普通聊天往往只给设计建议；这里把已有活动信息变成一张信息准确、手机上能读清的海报，并交付可编辑源稿。

## 输入

- 活动原文或旧海报，优惠规则、日期、地点及报名方式。
- 已有 logo、商品图、品牌色和素材使用权限。
- 目标读者、发布渠道、希望读者完成的唯一动作。
- 用户指定尺寸优先；未指定时以 1080×1440 像素作为本次设计假设。
- 缺价格、截止时间或联系方式时只追问这些发布必需信息；不编促销事实。

### 本轮处理门槛

- 先确定交付是可编辑稿、已导出的图片还是修改旧稿；三者分别报告状态。
- “明天”“周日”须换成已确认的年月日；日期与星期不一致时不自行选一个。
- 价格须核对原价、活动价、单位、适用对象、叠加规则；不清楚的优惠不进入发布版。
- 缺少地址但仅面向熟客时可用已确认的店名；面向陌生人则地址是发布阻塞项。
- 品牌图不可用时提供纯文字方案；原图为低清位图时不声称放大后仍清晰。
- SVG 是可编辑稿，不等于平台可直接上传的 PNG；没有导出能力时明确这一差别。

## 核心判断

1. 先区分活动招募、商品促销和营业通知；只突出一个主行动。
2. 标题负责让人知道是什么活动，利益点负责说明为什么参加，规则负责防止误解。
3. 已有素材足够时排版优先；没有图片时用文字与色块完成，不强塞无授权照片。
4. 可发布成品必须有真实渲染文件；只有提示词或布局描述时标注为制作方案。
5. 用户明确要求位图且工具可用时调用图像工具；精确价格、日期、二维码需另行核对。
6. 不把生成图片中似是而非的文字视为正确；文字密集时优先可编辑 SVG 或 HTML。

## 编号工作流

### 1. 提取活动事实

- 列出标题、利益点、日期、地址、适用人群与限制。
- 逐项标记原文位置；“全场”与“部分商品”有冲突时先解决。
- 明确报名链接、二维码或私信入口，避免出现多个竞争行动。
- 输出事实清单和影响发布的缺口。

### 2. 收敛文案层级

- 主标题不堆全部活动条件，副标题只补足必要利益。
- 将限制写成可读的小字，不能通过极小字号隐藏。
- 删除没有证据的“全网最低”“最后机会”等宣传承诺。
- 输出海报完整文案，不让用户自己从建议中拼接。

### 3. 制定一版布局

- 按手机阅读顺序安排标题、主视觉、利益、规则、行动入口。
- 默认保留约 6% 边距，二维码周围留白。
- 正文长时先精简语言，不能只靠缩小字号容纳。
- 输出元素坐标、字号、颜色与素材对应关系。

### 4. 制作可编辑成品

- 按可用工具产出 SVG、HTML 或设计源稿，并保留文字可编辑。
- 二维码只使用用户提供或由已确认链接生成的真实码。
- 没有二维码时改成真实可执行的私信方式，不画装饰假码。
- 有渲染工具时导出 PNG；无渲染工具则交付 SVG 并写明导出路径。

### 5. 缩小核对与修正

- 将海报缩至手机预览比例检查标题和日期可读性。
- 逐字对照事实清单，核验价格、门店、日期和入口。
- 实际打开链接或扫码核验；无法测试时明确保留该待验项。
- 检查文字溢出、图像拉伸和遮挡后再交付。

### 6. 承接修改

- 用户反馈“看不清”时先改层级和字号，不盲目换配色。
- 用户反馈“没重点”时只调整主利益与行动入口。
- 每轮保留准确的活动事实，只改反馈对应的视觉问题。
- 交付新版并注明适用渠道和导出尺寸。

### 各步执行与验收细则

- 第 2 步把文案拆成“标题 / 时间地点 / 利益 / 限制 / 行动”，逐字段回指输入；缺项用待确认标记，不混进发布图。
- 第 3 步在 1080 宽稿上先用标题 76、正文 44、规则 36 像素试排；这些仅是起点，缩到 360 宽后重查。
- 中文长行用多个 text/tspan 明确分行，先量字宽再调行距；不依赖 SVG 自动折行。
- 第 4 步以 viewBox 固定画布、保留独立文本层；不将整张稿栅格化后冒充可编辑源文件。
- 第 5 步按 360×480 预览检查正文；不清楚则删冗词或增加版面，不把规则藏成小字。
- 导出 PNG 时检查实际宽高和四边裁切；二维码未测试则列为发布前待验，不写入口已可用。

## 直接交付与下一步

- 可编辑海报源文件；工具支持时同时给 PNG。
- 一份完整文案与发布前仍需确认的事实。
- 一句发布配文，沿用海报事实且只保留一个行动。
- 验收以内容准确、缩小可读、入口可用、文件可打开为准。

### 工具不可用时

- 不能渲染时交付可编辑 SVG 与明确导出步骤；不能创建文件时只给完整 SVG 源码，注明尚未生成图片成品。
- 无法完成的关键检查要写明未验证项，不把计划或草稿称为已完成执行。

### 后续输入与收尾

- 首轮交付前核对事实表、源稿、配文三处的日期和价格一致。
- 用户只说“不高级”时，让其指出希望保留的一处和不能接受的一处，再调整字体、色块或留白。
- 用户回传手机截图后以截图中的文字拥挤或裁切位置返修，不要求重新提供活动全部信息。
- 已有完整模拟成品见 [交付示例](references/delivery-example.md)；修改版式后复查同一组长中文与规则。

### 外部参考与延展

- 触发：文字溢出、品牌风格无法对齐，或用户要求新渠道尺寸。
- 优先读品牌规范、发布渠道官方图片说明与 SVG/浏览器官方文档。
- 可搜索 GitHub “editable event poster svg”，比较文字层、导出和留白处理。
- 重点看长中文、优惠规则、二维码在手机预览中的层级，不按点赞量选方案。
- 仅吸收能解决本轮可读性缺口的机制；不复制其他商家的文案或商标。
- 将机制接入布局或渲染步骤，用同一活动信息重新缩图验证。

### 可比较的参考机制

- [W3C SVG 文本规范](https://www.w3.org/TR/SVG/text.html)：比较可编辑 text/tspan 与整图位图，采用明确文本层和分行；不据此假定所有字体都可用。
- [W3C SVG 规范](https://www.w3.org/TR/SVG/single-page.html)：查看 viewBox 与 viewport 的缩放关系；将检查接到导出前后尺寸核对。
- 对照长文证据摘要的“字段回查”，用于核对日期与优惠口径；不把促销正文压缩到遗漏适用限制。

### 可执行模拟演示

以下全部为明确模拟输入，不代表任何真实用户的经历或结果。

- 模拟输入：小禾书店，2026年11月8日14:00读书会，免费，限20人，店内报名。
- 目标：让附近读者到店登记，不添加虚构地址和二维码。
- 主标题：一起读本书。
- 副标题：小禾书店读书会｜11月8日 14:00。
- 规则：免费参加 · 限20人 · 请提前到店报名。
- 行动：到小禾书店登记席位。
- 布局：上部标题，中部书页色块，下部时间、规则和报名入口。
- 验证：免费与限额同时保留；未提供地址则提示发布前补足位置。

### 交付前检查

- 用 references/delivery-example.md 的输入走完当前模式，对照关键判断逐项核验。
- 将本轮最终成品与输入事实逐项对照；无依据的新增事实必须删除或标为未知。
- 先检查处理门槛和失败分支，再检查行文与格式；不能用篇幅达标代替可用性。
- 新反馈触发通用修正时保留原案例，比较旧版与新版，再同步 README 和必要示例。
