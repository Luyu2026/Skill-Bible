# 明确模拟：SQL 岗位简历证据修复

## 输入与验证范围
模拟 JD：必须能使用 SQL 汇总订单并输出每周经营报告；有 Python 经验优先。
模拟简历原句：“赋能运营，显著提升效率。”
模拟用户确认：本人用 SQL 汇总订单，每周向运营团队发报告；没有效率测量，没有 Python 经历。
本例只提供正文，没有 PDF、Word 或目标招聘系统权限。

## 可直接复制的改稿
使用 SQL 汇总订单数据，形成每周经营报告，供运营团队复盘。

## 改稿依据与缺口
“使用 SQL”“汇总订单”“每周”“运营团队”均来自模拟用户确认。
删除“显著提升效率”，因为没有测量；不加数据量、节省工时或独立负责等未经确认事实。
待补项目日期和 SQL 具体处理动作，例如连接、去重或口径校验；未确认前不加入成品。
本轮正文可读性检查通过，尚未验证投递文件提取，更未验证雇主 ATS。

## 文件复验动作
用户导出最终文件后，用本地可用的文档提取工具提取文本，记录工具、文件名和时间。
核对姓名联系方式、项目标题日期、SQL 原句和经历先后顺序，逐项记录正常、丢失或错序。
PDF 无文字层时先以 OCR 辅助定位，再核对每个数字；不能把 OCR 成功等同招聘系统兼容。
若双栏使经历错位，改为单栏，重新导出并提取；本例没有文件，不伪造测试日志。
下一步只交回最终文件与项目日期，先验证本地提取，暂不追求第三方分数。
反例：为了命中优先项加“精通 Python”，违反补证边界，必须删除。
