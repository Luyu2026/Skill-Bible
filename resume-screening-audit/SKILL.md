# 简历筛查可读性诊断

## 一句话主餐

从简历实际文本与目标 JD 找出解析障碍和证据缺口，交付可验证修正，解决用不透明 AI 分数制造焦虑的问题。

## 输入

- 实际投递文件和可复制正文，优先读取已有简历
- 目标 JD、投递系统要求或用户看到的评分截图
- 能确认的项目、时间、职责和结果依据
- 用户希望核查解析、匹配还是两者
- 无 JD 时只做文本与证据审查，不给岗位匹配总分

材料优先级：用户现有原稿与记录优先；补充信息只追问会改变本轮判断的部分。
真实材料、合理推断与明确模拟内容分别标记。
不能读取附件时，请用户粘贴关键片段；先完成不依赖附件的部分。

## 核心判断

1. 解析失败、岗位证据不足和表达冗余是三个不同问题
2. 用户自己的文件提取成功不等于所有 ATS 都会成功
3. 匹配标记分明确支持、部分支持、未体现，不能推断不会
4. JD 中硬条件与偏好分列，不把每个关键词同等加权
5. 不从风格断言 AI 写作、造假或候选人诚信
6. 不隐藏关键词、伪造技能或增加用户未确认经历

## 编号工作流

### 1. 复现可读性问题

- 提取文本并记录所用工具与文件版本
- 比较姓名字段、经历顺序、日期与段落边界
- 用户只贴文本时说明没有验证原文件解析
- 失败时提供单栏纯文本重排版供用户替换

### 2. 拆解 JD 要求

- 标记必须项、职责、优先项与申请问答条件
- 每项保留 JD 原句位置
- 不自行添加学历、年龄或公司偏好门槛
- 条件不清时按待确认项处理

### 3. 建立证据映射

- 表格列 JD 要求、简历证据、支持程度、缺口
- 证据定位到具体项目与原句
- 同义表达先判断含义再决定是否补术语
- 没有经历依据时给补证问题，不能直接补关键词

### 4. 排序修正

- 先修提取丢失和联系方式等可执行问题
- 再修关键能力无证据、职责归属模糊与时间矛盾
- 最后调整冗余和表达顺序
- 每项说明影响、动作和如何复验

### 5. 生成可投递改稿

- 只改最影响本轮目标的段落或整体文本版
- 保留真实数字、个人贡献与时间边界
- 没有数据时以已确认动作与范围表达
- 输出改前改后及改动依据，避免只给建议

### 6. 复验与交接

- 对实际新文件再次提取并比较关键字段
- 逐项复核 JD 映射是否因补证而改善
- 没有目标系统权限时明确只完成本地检查
- 用户交回新文件或真实筛查反馈后定位下一项

## 直接交付与下一步

- 文件解析结果与验证边界
- 逐项 JD 证据覆盖表及修正优先级
- 可复制的重点段落改稿或纯文本版
- 缺证问题、复验方式及材料使用说明

### 完成条件

- 交付物逐项回到输入来源，关键判断有依据或明确的未知边界。
- 用户能直接使用本轮成品，而不是再把方法说明自行转成成品。
- 待确认项只阻塞相关结论，不阻塞已可完成的部分。
- 本轮结束时指出一个最值得交回的材料和它会改变的判断。

### 工具与数据降级

- 工具不可用时说明已执行到哪一步，交付可编辑文本或底表。
- 依赖外部事实的部分没有核验就保留待确认，不写成已经完成。
- 文件交付失败时直接提供可复制正文，并保留建议文件名。

### 外部参考与延展

- 何时研究：系统解析与本地结果不同、特定格式失效或评分规则不明时启动。
- 去哪找：先查招聘平台官方帮助与职业服务资料；检索“resume parsing supported format applicant tracking”。
- 看什么：比较文件类型、字段读取和可解释要求映射，不采信万能过筛分数。
- 怎么用：用同一份用户文件复验关键字段，不能把第三方评分提升当录用概率提升。
- 采用前比较至少两个可行机制或与当前方法对照，说明材料成本及适用边界。
- 用触发问题的同一输入验证改动，保留有效方法，丢弃不能改善交付的装饰功能。
- 外部资料帮助调整方法，不能替代用户事实；实际复用受许可约束的内容时保留必要声明。

### 交付前逐项复核

1. 对照原始材料，检查是否改变数字、条件、角色或时间。
2. 检查推荐路径是否符合用户现有工具和材料条件。
3. 把仍需核验的结论与已经完成的内容分开。
4. 用下方模拟案例执行主流程，核对输出是否能落地。
5. 遇到模拟案例未覆盖的真实限制，缩小承诺后再交付。
6. 对后续反馈只改影响本轮目标的判断，避免无关扩展。
7. 输出文件与对话结论保持一致，不把计划称为执行结果。

### 明确模拟的执行示范

- 模拟 JD：需要 SQL 分析与每周经营报告；模拟简历：“赋能运营，显著提升效率”。
- 用户确认材料：曾用 SQL 汇总订单数据，每周给运营团队发送报告；没有效率测量。
- 映射：SQL 分析原文未体现，补证后明确支持；效率提升仍无证据。
- 改稿：“使用 SQL 汇总订单数据，形成每周经营报告，供运营团队复盘。”
- 解析边界：本例仅文本，未测试 PDF 或目标招聘系统，不给 AI 分数。
- 复验：用户导出最终文件后检查 SQL、项目日期和段落顺序是否可提取。

参考入口：[Harvard 职业服务：AI 与简历](https://careerservices.fas.harvard.edu/ai-resumes-and-cover-letters/)。采用职位相关表达与申请要求核对机制，不将其解释为通用 ATS 分数公式。

### 材料使用说明：交付末尾规则

最终配套诊断报告末尾只保留下表，按本次情况填写；表后不再附文字。
正式投递简历文件不放此表。
仅当用户明确授权且实际读取知识库时写已调用，否则写本次未调用或实际无权限。
不能复述知识库原文或用其案例替代本人经历。
