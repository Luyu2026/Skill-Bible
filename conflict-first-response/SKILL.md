# 冲突当下回复急救

## 一句话主餐

普通聊天可能把回复写成辩论长文；这里先判断当前是否适合接触，再交付一条能发送的回复和明确停止条件。

## 输入

- 最近一条原话、消息时间与必要的前后文。
- 用户想降温、澄清、安排事务还是结束沟通。
- 对方是否明确要求不联系，之前是否已反复发送。
- 是否存在当下威胁、跟踪、强迫或人身安全问题。
- 只需相关片段；不收集无关身份信息和整段聊天史。

### 本轮处理门槛

- 明确“今晚不要发”也是接触边界；无必要事务时直接不发送，不能借确认再发一次。
- 对方只是说“我需要缓一缓”且未禁止回复时，才可给一次简短暂停确认；已确认过则停止。
- 消息时间不明时不按已读或沉默时长推断态度；先确定最新可见原话。
- 必要交接只在双方认可的渠道进行；没有可用渠道时先整理交接清单，不擅自绕行联系。
- 有威胁或强迫时暂停普通修复话术；不让用户单独去见对方以测试能否谈好。
- 分手意愿清楚时不把事务消息夹带成挽回长文；不把回复率作为交付成功指标。

## 核心判断

1. 先判断安全和接触边界，再优化措辞。
2. 明确拒绝联系时不设计换号、找朋友传话或堵门等绕过方式。
3. 暂停沟通与惩罚性失联不能仅凭沉默推断，分别给可观察的判断线索。
4. 分手已明确时只处理必要事务，不把挽回作为默认目标。
5. 道歉只承担本人可确认的行为，不承认未发生的事实换取回复。
6. 不把一句话包装成必然复合或保证对方消气的技巧。

## 编号工作流

### 1. 确定接触是否合适

- 读取最新消息与时间，避免用旧消息推断当前状态。
- 有即刻危险时优先帮助用户离开危险情境并联系当地紧急或可信支持。
- 对方已拒绝接触时停止劝说性消息。
- 仍有必要物品交接时，只安排可接受的事务渠道。

### 2. 选本轮唯一目标

- 在降温、澄清、道歉、边界或交接中选一项。
- 用户想同时解释所有委屈时先压缩到当前可处理的一件事。
- 说明本轮先解决什么，哪些争议留待双方愿意谈时再谈。
- 不替双方决定关系是否继续。

### 3. 拆开事实与刺激词

- 保留具体行为，去除人身评价和动机断言。
- 将“你每次都这样”改成最近一次可核对的事件。
- 不复述对方羞辱性词语作为回击。
- 识别本方真正要表达的责任、需求或边界。

### 4. 写一条可发回复

- 通常用两到四句，长度服从情境，不机械凑字数。
- 先承接当前状态，再表达本方责任或界限，最后给可拒绝的下一步。
- 不附带一串反问、不要求即时回复、不用自伤威胁。
- 若正确行动是不发，则明确写“不发送”，并给用户自己的下一步。

### 5. 预设回应分支

- 对方愿意谈：约定一个双方方便的时机，只谈一个问题。
- 对方继续辱骂：结束当前交流，不继续逐句反击。
- 对方没回复：不按统一倒计时追发，根据边界和必要事务决定。
- 对方明确结束：尊重决定，只处理必要交接。

### 6. 接住后续反馈

- 用户交回实际新消息，而非猜测对方心理。
- 检查回复是否被误解、边界是否明确、事务是否安排。
- 降温成功后再进入长期需求协商，不一次布置关系改造任务。
- 出现新威胁时重新评估安全，不沿用原来的普通争执路径。

### 各步执行与验收细则

- 第 1 步把状态写成“可回复 / 有条件暂停 / 明确不联系 / 安全优先”，并引用决定状态的原话。
- 第 2 步用户提出的目标若违反对方明确边界，保留其感受，但把本轮行动改成不发送与个人草稿。
- 第 3 步道歉逐句对应本人确认行为，例如吼叫；删除“都是我的错”等无法核验的总括认错。
- 第 4 步交付先写发送判断，再给正文；不发送时不附一条容易被误用为立即发送的挽回备选。
- 第 5 步所有追发分支重查接触边界；无回应不是新的发送许可，也不设自动追发倒计时。
- 第 6 步只有出现新的实际消息或必要事务变化才改路线；普通沉默不作为对方改变主意的证据。

## 直接交付与下一步

- 一条可直接发送的回复，或明确不发送的判断。
- 对应理由、紧接着的一个行动和停止条件。
- 针对愿意谈、继续攻击、无回应的简短分支。
- 验收看是否尊重边界、没有升级矛盾、下一步可执行，不看是否成功复合。

### 工具不可用时

- 没有发信工具时直接提供回复；即使有工具也不因生成草稿而自动发送，实际发送须有明确指令。
- 无法完成的关键检查要写明未验证项，不把计划或草稿称为已完成执行。

### 后续输入与收尾

- 本轮只处理这条消息；暂不生成长期关系修复作业与多天追发计划。
- 用户提供新的实际原话时重新判路；不能仅凭“我觉得他想我了”恢复发送。
- 交接完成且没有新问题即可结束，不制造额外联系理由。
- [模拟交付与边界回归](references/delivery-example.md)覆盖“今晚别发”的不发送结果；修改话术后必须仍守住该边界。

### 外部参考与延展

- 触发：多次回复都被理解成施压、接触边界不清或出现威胁性行为。
- 优先读取用户实际对话，再查可信的冲突修复教学资料与当地支持服务官方入口。
- 检索 “repair attempt conflict boundaries” 或 “domestic violence safety planning”。
- 比较修复尝试与个人安全计划的适用条件，不能把两者混为普通话术优化。
- 采用能减少施压并保留自主选择的机制，排除操控、跟踪和保证挽回内容。
- 将机制落实为一句修改与一个停止条件，用原消息检查是否仍含指责或强迫。

### 可比较的参考机制

- [Gottman 的修复尝试说明](https://www.gottman.com/blog/get-back-on-track-during-conflict/)：参考暂停、收回刺激措辞与重新聚焦问题的机制，不把它作为突破不联系边界的依据。
- 与 couple-needs-dialogue 比较：短回复只负责当下接触与停止，双方愿意谈后才转为需求和约定。
- 若现有修复句仍像施压，比较“承认自己行为”和“索取原谅”是否混在同一句，删除要求对方马上安慰的部分。

### 可执行模拟演示

以下全部为明确模拟输入，不代表任何真实用户的经历或结果。

- 模拟输入：对方说“我现在不想吵，今晚别再发了”；用户想连发解释。
- 判断：对方已明确要求今晚暂停，尊重该边界。
- 本例明确要求今晚不发，因此连确认消息也不发送；不因尚未确认而增加接触。
- 若此前已经确认过，则本轮不再发送，避免借确认继续接触。
- 紧接动作：把解释写在自己的草稿里，不发送。
- 停止条件：今晚不追发、不借其他渠道联系。
- 后续：对方主动表示愿意聊时，再约时间讨论一个具体问题。
- 验收：没有设置逼答期限，没有借道歉索取回复；沉默不被解释为一定分手。

### 交付前检查

- 用 references/delivery-example.md 的输入走完当前模式，对照关键判断逐项核验。
- 将本轮最终成品与输入事实逐项对照；无依据的新增事实必须删除或标为未知。
- 先检查处理门槛和失败分支，再检查行文与格式；不能用篇幅达标代替可用性。
- 新反馈触发通用修正时保留原案例，比较旧版与新版，再同步 README 和必要示例。
