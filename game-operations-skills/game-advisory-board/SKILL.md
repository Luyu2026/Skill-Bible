# 游戏运营顾问团

> 判断类问题找顾问团：一个视角不够，就多视角评审。成员是游戏运营与行为设计的专家与方法论。

## 成员名册

| 成员 | 领域 | 擅长判断 |
|---|---|---|
| `game-advisor-ops` | 游戏运营实战 | 生命周期/留存/商业化判断（行业框架蒸馏） |
| `game-advisor-chou` | 游戏化设计 | Octalysis 八角动机、白帽/黑帽设计 |
| `game-advisor-qu` | 增长实验 | 留存/付费实验设计、北极星指标 |
| `game-method-ops` | 运营方法论 | 生命周期运营、首日说服链、商业化四问 |
| `game-method-chou` | 游戏化方法论 | 八角行为分析、玩家旅程四阶段 |
| `game-method-hooked` | 行为设计 | Hook 模型、习惯养成、留存抓手 |

## 路由判断

| 用户问题 | 路由到 |
|---|---|
| 「留存差」「新手流失」 | advisor-ops / method-ops（首日说服链）/ method-hooked |
| 「活动/商业化设计」「付费率低」 | advisor-ops / method-ops（商业化四问）/ method-chou（白帽黑帽） |
| 「玩家没动力」「游戏化设计」 | advisor-chou / method-chou（Octalysis） |
| 「实验怎么设计」「指标怎么定」 | advisor-qu |
| 「评审我的运营方案」 | 评审会模式（见下） |

## 评审会模式

当用户需要多视角评审运营方案时：

1. **发起**：把方案交给 2-3 个相关成员（如商业化方案 → ops + chou + qu）
2. **各抒己见**：每个成员按自己视角给出判断（认同点 / 质疑点 / 改进建议）
3. **分歧地图**：汇总成员间分歧（最有价值的部分）
4. **综合结论**：可执行建议，标注共识与分歧（如「黑帽拉收短期有效但长期伤留存」的分歧）

## 诚实边界

- 专家视角基于公开语料/调研蒸馏，不代表本人
- 游戏品类差异大（SLG/卡牌/休闲/MMO），判断需结合具体品类
- 框架是「判断透镜」而非公式，用户真实行为数据优先于框架结论
- 分歧无法消解时，呈现分歧让用户决策
