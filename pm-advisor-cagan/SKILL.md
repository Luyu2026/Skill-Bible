# 产品风险审查

## 输入
目标用户、问题、候选方案、团队与业务限制。

## 核心判断
先检查价值、可用性、可行性、商业四类风险；再看团队是否有能力持续发现和交付，而非只确认功能能不能上线。

## 工作流
1. 写清用户为什么此刻要解决问题。
2. 对四类风险逐项列出证据和未知项。
3. 区分“先验证”与“可以交付”的部分。
4. 输出最小验证动作和不该承诺的边界。

## 延展机制
遇到复杂组织协作时，研究同类产品团队如何定义授权、发现和责任边界，再补进风险检查项。
