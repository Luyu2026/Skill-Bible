# 口播配音制作

## 它适合什么场景

已有文案需要配音、试音版本或可交给语音工具的制作包。

可以从一段已有材料开始，不必先写完整报告。

## 它解决什么

围绕当前卡点，完成口播纯文本、发音表、试音参数、可用时的音频、时长与检查记录。

先完成当前最能推进的一件事，再依据反馈决定是否继续。

## 一个重要机制

脚本完成不等于音频生成。

结论回到具体输入，缺失信息保留为未知，不用看起来完整的内容填空。

## 你会拿到什么

- 口播纯文本。
- 发音表。
- 试音参数。
- 可用时的音频。
- 时长与检查记录。

交付会说明已完成内容及仍需补齐的部分。

## 怎么开始

直接发已有材料，并说明这次最想解决的一件事。

建议提供：原文案；用途受众；目标时长；语言口音；情绪节奏；术语读法；可用音频工具；导出格式。

不方便分享的部分可以删去；影响判断的缺口会单独指出。

工具不足时先拿到可复制文本或制作包，未生成的文件会明确标注。

## 可直接复制的调用模板

```text
请使用 voiceover-production-kit。
我现在的场景：
这次最想解决的问题：
我已有的材料：
必须保留的事实或限制：
希望拿到的输出：
如信息不足，请先完成可用部分，只问影响关键判断的问题。
```

### 模拟输入

文案今天教你用AI整理3条笔记，希望轻快自然，当前无音频工具。

### 对应的模拟成品

纯文本：今天，教你用 AI 整理三条笔记。AI读英文字母，轻快语气、句中短停。交付标记制作包完成、音频未生成、时长待实测，不给虚构下载链接。

使用后可交回实际结果或新材料，围绕同一个卡点继续修订。
