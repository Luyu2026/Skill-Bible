# 口播配音制作

## 一句话主餐

已有文案需要可用配音时，把文字改成可朗读稿、解决数字术语读法并先做短段试音；有工具交音频，无工具交可直接导入的制作包且明确未渲染。

## 输入

优先使用已提供正文、截图、草稿与记录，不要求重复整理。

- 原文案。
- 用途受众。
- 目标时长。
- 语言口音。
- 情绪节奏。
- 术语读法。
- 可用音频工具。
- 导出格式。

### 材料处理规则

- 明确区分材料事实、用户陈述、合理推断和未知信息。
- 只追问会改变当前做法的缺口，其他缺口写入交付边界。
- 附件读不到时说明具体缺失，允许粘贴相关片段继续。
- 不编造用户经历、外部访问状态或工具执行结果。
- 演示必须标为纯模拟，不称为真实材料脱敏。
- 私人材料留在当前任务，不混入通用安装包。

### 会改变本轮做法的缺口

只追问工作流中会切换分支的字段；其余未知保留，不用完整问卷阻止已有材料产出。
外部访问失败只说明实际失败，不将“没有读取”写成“已核实无权限”。

## 核心判断

1. 纯文本稿、带导演标记稿和音频文件分开，括号里的指导语不能误读进正文。
2. 目标时长先估算，渲染后才叫实测；不以字数估时冒充文件时长。
3. 价格、时间、产品名和法律承诺不能为顺口擅改；更改数字读法必须保持含义。
4. 真人音色仅在有相应授权且用途允许时使用；不能做冒充他人身份的配音。
5. 工具支持什么参数以当前官方文档为准；不把某引擎的 SSML 当成通用能力。

## 编号工作流

### 1. 锁定交付规格

读取用途、受众、原稿、目标时长、语言口音、音色需求与导出格式。

未给格式时先保留待确认，不为未选工具伪造采样率和音色编号。

抽取不可改事实及高风险读法：数字、日期、缩写、多音字、品牌。

确认可用语音工具及是否能回听；无工具直接走制作包分支。

产出规格卡和待确认读法表，音色授权有缺口时改用普通合成音色建议。

### 2. 准备口播纯文本

按呼吸长度拆句，删掉只适合阅读的层级标签，保留事实和必要语义。

数字换成实际读法：数量、年份、编号分别处理，不把编号读成数量。

专名读法不明就标待确认；不要将猜测发音写为已核准。

同时保存纯文本与单独的段落导演表，重音和停顿标记不进入纯文本。

产出按段编号脚本及原稿到改稿的事实核对清单。

### 3. 设计可比较试音

先挑含数字、术语或情绪转折的短段，不先生成全稿再找问题。

A版自然说明，B版只改变一个参数，如更慢或更明确重音。

有引擎则使用支持的参数名与取值；无引擎用可交给操作者的自然语言指令。

估时可按字数除以假定每分钟字数，加停顿；外语单独估算并注明假设。

产出两版差异表、短段文本和预计时长范围。

### 4. 渲染短段并确认

调用获授权工具生成短段，保留实际返回文件、参数及错误信息。

能回听时按原文逐句检查错字、漏字、专名、停顿和尾音；不能回听则明确未试听。

反馈用“第几段、哪一个词、希望怎样读”记录，不只收“怪怪的”。

参数报错先查支持列表，删除不支持标签；不重复盲试全稿。

产出真实试音或未渲染试音包，只有确认读法和风格后才扩到全稿。

### 5. 生成全稿和检查音频

按已确认配置渲染；长稿逐段命名，保留拼接顺序并避免跨段漏词。

读取音频元数据记录格式、声道、采样率及实测时长；无法读取的字段写未核验。

可试听时检查开头、段间衔接、数字术语和结尾；响度或削波需实际测量才写通过。

导出要求不符时明确待转换，不把修改扩展名当转码。

产出文件路径与检查表，失败则保留脚本和已成功短段，不伪造下载链接。

### 6. 控制时长并交付

超时先比较可删冗句与不可删事实，再小幅调整语速；不能为压时长删关键条件。

时长不够先调整自然停顿，用户未授权时不添加产品卖点或事实。

修改后重新渲染并测时，旧实测时长不能沿用到新稿。

交付状态分别标：脚本完成、试音是否生成、全稿是否生成、是否试听、时长是否实测。

用户交回段号与错误类型后只重做受影响段，合并后复核衔接和总时长。

## 直接交付与下一步

交付纯文本、独立发音表、参数与段落导演表、音频或未渲染包、状态与检查记录。

音频完成要求有真实可访问文件且检查状态如实；制作包完成不等于配音已生成。

无工具时用户可将纯文本粘贴进自选 TTS，单独设置语速；不要把导演表粘贴进朗读区。

先处理一段试音再全文；下一轮交回音频或明确段号、读错词、期望读法。

核心受限项写清：当前无法生成音频或无法试听；不得声称已达到可播出音质。

输出为可复制 Markdown 或用户指定且当前可生成的文件；只有真实写出文件后才报告路径。

模拟执行及本轮缺陷回归见 [references/review-validation.md](references/review-validation.md)；不得把模拟结果当成真实用户反馈。

## 外部参考与延展

触发：SSML 标签被读出、数字持续误读、语速调整导致失真、导出规格不匹配。

入口：所选语音服务官方 TTS、SSML、音色授权和导出格式文档；音频格式查所用编码器官方说明。

比较当前引擎对 phoneme、say-as、break、prosody 的实际支持与语言范围；不跨引擎复制参数。

采用能解决同一错读或时长问题且不改变事实的机制；不因音色热门就更换授权范围不清的声音。

先在同一风险短段比较纯文本读法与引擎标签，检查兼容性和听感，再接入全稿；不可试听时把确认工作交给用户并标未核验。

研究前先读已有材料；已有依据能解决当前问题时直接交付，不重复检索。

运行时若采用新机制，说明它改动哪一步和如何验证；不能仅附链接充当研究。

保存通用改进时同步说明与受影响示例；个人偏好留在个人任务，不默认推广。
