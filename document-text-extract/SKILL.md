# PDF 与图片文字提取

## 一句话主餐

按页还原文字与必要的表格关系，保留位置和不确定项，让用户能复制也能核对原件。

## 输入

优先读取用户已经交来的材料，不要求重新抄写或重复上传可访问内容。

- PDF、扫描图、截图或用户提供的页面图像
- 需要处理的页码、正文与表格范围及输出格式
- 是否保留版面顺序、页眉页脚、批注及敏感字段

开始前记录本轮范围、已有材料、输出位置与不能确认的事项。
只缺非关键偏好时，明确采用的默认值并继续完成初稿。
缺少核心原件时交付可执行的补料要求，不宣称已完成原件处理。
不得把示例数字、他人经历或工具猜测写成用户事实。

## 核心判断

1. 原生 PDF 优先读取文本层，扫描件才走 OCR，混合文件逐页判断

2. 多栏阅读顺序与视觉位置分开处理，不按坐标机械拼接

3. 表格保留行列关系，无法识别的单元格不能挪到相邻列

4. 提取不等于校订；金额、日期、人名和公式不按常识改写

将每条重要信息标记为“材料明确”“用户补述”“编辑建议”或“待确认”。
标记只服务追溯；正式成品不堆内部操作记录。
遇到原材料自相矛盾，保留冲突位置，优先修复会改变结论的项。

## 编号工作流

### 1. 建立页面清单

- 读取文件页数与用户指定范围，记录可处理页面
- 文件加密或损坏时说明具体页和原因
- 超出工具容量时分批处理，保留已完成与未完成清单

执行细则：页面清单固定“文件名｜物理页码｜印刷页码｜可读状态｜处理方式”。同名附件按文件区分，用户指定页与工具页索引先对应。

验收与分支：加密文件请求可读副本，不绕过密码。部分页面不可读时仍交已完成页，同时逐页列出未覆盖原因。

### 2. 识别文本来源

- 逐页检查原生文本层、扫描图或混合内容
- 文本层乱码时与渲染页对照后切换视觉识别
- 不因第一页可复制就假设整份文件都可复制

执行细则：每页尝试文本层并对照页面；空文本走视觉/OCR，文本乱码或漏图中文字时按区域补识别。

验收与分支：没有 OCR 和视觉能力时不处理扫描区域；保留可读取原生文字，交“未提取区域”，不把 OCR 候选当作已核验。

### 3. 执行分区提取

- 先识别标题、正文、表格和脚注的相对关系
- 双栏按栏阅读，跨栏标题先提取
- 表格逐行输出固定列数，合并单元格另作说明

执行细则：双栏先读左栏再读右栏，跨栏标题先行，脚注紧随对应正文。页眉页脚若删除须在处理说明中说明规则。

验收与分支：表格先锁定列标题与单位，再逐行填固定列数；合并单元格说明跨列/跨行，空格与看不清分别用空值和[待核]。

### 4. 核对关键字段

- 回看金额、日期、编号、单位及负号小数点
- 疑似错误保留原读数并标注[待核]
- 公式复杂或图章遮挡时附位置和无法辨认原因

执行细则：金额、日期、编号、正负号、小数点和单位逐项回看原图；回看不了就在字段旁标“未回核”，不能声称已校验。

验收与分支：合计不相等仅报告差额及来源，保留原值。公式无法可靠转成可编辑式时给位置和原图需求，不按常识补。

### 5. 输出可编辑结果

- 正文按页分隔，保留标题层级和段落
- 表格交付 Markdown 或正确引用转义的 CSV
- 只在用户要求时另给清洗版，原始提取稿同时保留

执行细则：正文以文件和页码分隔，表格命名为“文件-p页码-表序号”；跨页表只有列结构相同且能确认延续时才合并。

验收与分支：CSV 对含逗号、引号、换行的字段正确加引号并双写引号；保留原始提取稿，清洗稿不得覆盖原稿。

### 6. 核验覆盖并交付

- 核对页码是否连续、表格行列是否对齐
- 交付提取稿、来源索引与异常清单
- 用户补交局部高清图后按页码和区域定点修复

执行细则：清点约定页数、已提取页数、异常页数以及逐表行列数；完成状态必须说明正文、表格和图片中的文字各自覆盖情况。

验收与分支：用户补图须包含页码和区域；仅修对应字段并保留旧候选，核验同一行其余列没有位移后再更新成品。

## 直接交付与下一步

可运行示例见 [模拟输入与交付](references/worked-example.md)。该例标明验证范围；真实任务不得把样例验收当作实际媒体或文件验收。

交付顺序先放用户可以直接使用的成品，再列必要的核验说明。

- 按页分段的可复制文本及可编辑表格
- 关键字段复核记录和来源页码
- 缺页、低清区域与未识别内容清单

### 完成与降级

- 全部约定范围有结果，关键事实可追溯，待确认项不会被误认成事实。
- 工具可用时实际检查生成文件；不能只返回一个未经验证的路径。
- 工具不可用时交付本地 Markdown 或对话文本，并准确说明未完成的文件能力。
- 不自行发送、发布、上传个人材料；外部动作依用户授权执行。
- 本轮先完成一个可用版本，用户交回具体段落、页面或时间点后定点修复。
- 修复保留旧版与来源对应，避免下一轮丢失已经确认的事实。

## 外部参考与延展

- 启动信号：多栏串行、混合页漏识别、跨页表格错列或关键数字反复出错。
- 优先入口：[PyMuPDF 文本提取](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)；先读用户已有规则，再定位一个具体失败环节。
- 观察与取舍：比较自然阅读顺序、坐标块与 OCR 的输入条件；需要 OCR 时再查 OCRmyPDF/Tesseract 官方文档的语言与依赖，不默认环境已装齐。
- 融入与验证：把分栏和区域核验接入第 2、3 步；同一页对比丢行、错列和关键字段，改善后扩展。视觉核验不足时保留未核标记，不用置信度替代核对。
- 如果官方入口不可访问，沿用已验证流程并列出未核事项；不把搜索摘要当成已读全文。
- 需要新的工具参数、现行规定或平台访问能力时，查官方当前说明并记录所用版本；不凭旧记忆填写。
- 用户事实只来自本人材料；外部案例只用来比较机制，不用于补造数据、经历或原文。
- 保留触发案例及旧输出，定位修改后用相同输入回归；只把可泛化规则写回技能，个人偏好留在个人材料中。
