# PDF 与图片文字提取

## 一句话主餐

按页还原文字与必要的表格关系，保留位置和不确定项，让用户能复制也能核对原件。

## 输入

优先读取用户已经交来的材料，不要求重新抄写或重复上传可访问内容。

- PDF、扫描图、截图或用户提供的页面图像
- 需要处理的页码、正文与表格范围及输出格式
- 是否保留版面顺序、页眉页脚、批注及敏感字段

开始前记录本轮范围、已有材料、输出位置与不能确认的事项。
只缺非关键偏好时，明确采用的默认值并继续完成初稿。
缺少核心原件时交付可执行的补料要求，不宣称已完成原件处理。
不得把示例数字、他人经历或工具猜测写成用户事实。

## 核心判断

1. 原生 PDF 优先读取文本层，扫描件才走 OCR，混合文件逐页判断

2. 多栏阅读顺序与视觉位置分开处理，不按坐标机械拼接

3. 表格保留行列关系，无法识别的单元格不能挪到相邻列

4. 提取不等于校订；金额、日期、人名和公式不按常识改写

将每条重要信息标记为“材料明确”“用户补述”“编辑建议”或“待确认”。
标记只服务追溯；正式成品不堆内部操作记录。
遇到原材料自相矛盾，保留冲突位置，优先修复会改变结论的项。

## 编号工作流

### 1. 建立页面清单

- 读取文件页数与用户指定范围，记录可处理页面
- 文件加密或损坏时说明具体页和原因
- 超出工具容量时分批处理，保留已完成与未完成清单

本步完成条件：读取文件页数与用户指定范围，记录可处理页面；结果应能供下一步直接使用。

### 2. 识别文本来源

- 逐页检查原生文本层、扫描图或混合内容
- 文本层乱码时与渲染页对照后切换视觉识别
- 不因第一页可复制就假设整份文件都可复制

本步完成条件：逐页检查原生文本层、扫描图或混合内容；结果应能供下一步直接使用。

### 3. 执行分区提取

- 先识别标题、正文、表格和脚注的相对关系
- 双栏按栏阅读，跨栏标题先提取
- 表格逐行输出固定列数，合并单元格另作说明

本步完成条件：先识别标题、正文、表格和脚注的相对关系；结果应能供下一步直接使用。

### 4. 核对关键字段

- 回看金额、日期、编号、单位及负号小数点
- 疑似错误保留原读数并标注[待核]
- 公式复杂或图章遮挡时附位置和无法辨认原因

本步完成条件：回看金额、日期、编号、单位及负号小数点；结果应能供下一步直接使用。

### 5. 输出可编辑结果

- 正文按页分隔，保留标题层级和段落
- 表格交付 Markdown 或正确引用转义的 CSV
- 只在用户要求时另给清洗版，原始提取稿同时保留

本步完成条件：正文按页分隔，保留标题层级和段落；结果应能供下一步直接使用。

### 6. 核验覆盖并交付

- 核对页码是否连续、表格行列是否对齐
- 交付提取稿、来源索引与异常清单
- 用户补交局部高清图后按页码和区域定点修复

本步完成条件：核对页码是否连续、表格行列是否对齐；结果应能供下一步直接使用。

## 直接交付与下一步

交付顺序先放用户可以直接使用的成品，再列必要的核验说明。

- 按页分段的可复制文本及可编辑表格
- 关键字段复核记录和来源页码
- 缺页、低清区域与未识别内容清单

### 完成与降级

- 全部约定范围有结果，关键事实可追溯，待确认项不会被误认成事实。
- 工具可用时实际检查生成文件；不能只返回一个未经验证的路径。
- 工具不可用时交付本地 Markdown 或对话文本，并准确说明未完成的文件能力。
- 不自行发送、发布、上传个人材料；外部动作依用户授权执行。
- 本轮先完成一个可用版本，用户交回具体段落、页面或时间点后定点修复。
- 修复保留旧版与来源对应，避免下一轮丢失已经确认的事实。

### 外部参考与延展

- 启动信号：复杂双栏、跨页表格、手写批注或公式反复识别错误。
- 优先去哪里找：PyMuPDF、OCRmyPDF、Tesseract 官方文档及实际可用工具说明。
- 重点比较：比较阅读顺序、语言包、表格结构和区域定位能力。
- 先写出当前失败位置，再围绕该位置检索；不要无目的收集项目清单。
- 优先比较用户已有方法与一种相关成熟方法，列明需要增加的材料与工具。
- 仅当机制能改善本轮缺口、适合用户条件且可验证时采用。
- GitHub 如用于发现实现机制，应回到项目文档核对功能与运行条件。
- 涉及现行规范、平台规则或软件参数时查询官方现行说明，不靠旧记忆。
- 接入与验证：选择同一页做对比，统计关键字段错读和丢行，改善后再扩大处理。
- 比较未产生改善时沿用可用方案，如实说明局限，不增加无关功能。
- 用户事实继续以用户材料为准，外部案例不得填补用户缺失经历。
