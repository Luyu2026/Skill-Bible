# 短视频分镜脚本创作

## 一句话主餐

从用户真实素材写出能开口、能拍摄、能剪辑的一条短视频脚本，而不是泛泛列爆款技巧。

## 输入

优先读取用户已经交来的材料，不要求重新抄写或重复上传可访问内容。

- 选题、现有口播、产品事实、故事经历或参考视频
- 目标观众、发布平台、预期时长和本条视频的目标
- 可用人物、场地、道具、拍摄时间和表达禁区

开始前记录本轮范围、已有材料、输出位置与不能确认的事项。
只缺非关键偏好时，明确采用的默认值并继续完成初稿。
缺少核心原件时交付可执行的补料要求，不宣称已完成原件处理。
不得把示例数字、他人经历或工具猜测写成用户事实。

## 核心判断

1. 传播目标与拍摄条件一起决定脚本，不写现场拍不了的镜头

2. 开头承诺必须在正文兑现，不用虚假悬念或伪造效果

3. 口播、屏幕字幕、镜头动作分栏，避免把长文章当脚本

4. 用户经历与创意演绎分开；模拟台词不得伪装成客户证言

将每条重要信息标记为“材料明确”“用户补述”“编辑建议”或“待确认”。
标记只服务追溯；正式成品不堆内部操作记录。
遇到原材料自相矛盾，保留冲突位置，优先修复会改变结论的项。

## 编号工作流

### 1. 提炼单一观看理由

- 用一句话写清观众为什么愿意看完
- 从材料找一个矛盾、演示或具体问题作为主线
- 目标不明时默认先讲清一个问题，不强行销售

执行细则：将任务写成“给谁看｜看完知道什么或做什么｜最长时长”。教程交一个能照做的动作，产品介绍交一个有材料支撑的用途。

验收与分支：同一条稿出现两个独立目标时保留用户最急的一项，另一个放入备选选题，不硬塞成系列。

### 2. 确定拍摄边界

- 列出可拍地点、人物、道具及不能出镜的内容
- 没有素材的场景改成口播、手部演示或文字卡
- 产品参数和效果逐项回查用户资料

执行细则：建立“镜号｜所需人物/地点/道具｜已具备？｜替代拍法”表。无法现场获得的镜头必须换成现有屏幕、手部动作或口播。

验收与分支：未经证实的销量、疗效、客户反应一律不进台词。不能展示的界面用空白示意，并明确是演示。

### 3. 写开头与兑现点

- 给两种开头并解释适用语气，选一种继续展开
- 开头直接呈现问题、结果或对比，不虚构统计数字
- 先写正文兑现开头的句子，再补连接语

执行细则：开头 A 直陈问题，开头 B 展示结果；分别写出正文在哪一镜兑现。选与用户语气和现有素材一致的一个作为主稿。

验收与分支：若开头声称“三个方法”，正文必须有三个不同动作；只有一个事实就改成一个方法，不能凑数。

### 4. 生成分镜表

- 按时间段列镜号、画面、口播、字幕、声音和素材来源
- 每个镜头只承担一个信息动作
- 注明字幕为精简表达，不能改变原话事实

执行细则：分镜表固定“起止时间｜景别与动作｜口播｜屏幕字幕｜声音｜素材/道具”。每个时间段必须有可执行的画面动作。

验收与分支：时间从 0 开始连续覆盖目标时长，旁白可跨镜头但不重复计时；字幕突出关键词，完整原话保留在口播稿。

### 5. 做口读与可拍性检查

- 实际按自然语速读稿或估算并注明未实读
- 超时先删重复信息，再调整停顿和镜头
- 逐镜检查道具是否已有、转场是否必要、结尾是否明确

执行细则：按实际口读记录时长，工具不能实读时只给估算并要求试录。口播时长加演示静默与停顿后才是总时长。

验收与分支：超时先删重复解释；删除后仍需兑现开头。没有素材的镜头须替换，不能留“拍一些相关画面”。

### 6. 根据成片反馈迭代

- 交付主脚本、备用开头、拍摄清单和时长估算
- 用户交回粗剪或指出卡词时间点后再修
- 数据反馈只比较同类内容，不承诺播放量或转化率

执行细则：交付一份主稿而非让用户在多个半成品间拼接；备用开头单列，注明替换哪一段以及是否影响时长。

验收与分支：用户交回粗剪时间点或卡词句后，仅替换该镜；检查前后衔接和承诺兑现，不凭单条数据断言因果。

## 直接交付与下一步

可运行示例见 [模拟输入与交付](references/worked-example.md)。该例标明验证范围；真实任务不得把样例验收当作实际媒体或文件验收。

交付顺序先放用户可以直接使用的成品，再列必要的核验说明。

- 可拍分镜表：时间、镜头、口播、字幕与素材
- 完整口播稿及两个可选择的开头
- 拍摄准备清单和当前无法核实的事实

### 完成与降级

- 全部约定范围有结果，关键事实可追溯，待确认项不会被误认成事实。
- 工具可用时实际检查生成文件；不能只返回一个未经验证的路径。
- 工具不可用时交付本地 Markdown 或对话文本，并准确说明未完成的文件能力。
- 不自行发送、发布、上传个人材料；外部动作依用户授权执行。
- 本轮先完成一个可用版本，用户交回具体段落、页面或时间点后定点修复。
- 修复保留旧版与来源对应，避免下一轮丢失已经确认的事实。

## 外部参考与延展

- 启动信号：分镜在现有场地拍不出来、剪辑缺衔接画面，或口读后超时。
- 优先入口：[Adobe shot list](https://www.adobe.com/creativecloud/video/discover/shot-list.html)；先读用户已有规则，再定位一个具体失败环节。
- 观察与取舍：比较镜头清单的景别、动作、覆盖镜头与所需设备；保留手机和现有道具能实现的做法，不引入拍摄团队依赖。
- 融入与验证：将所需镜头与替代拍法接入第 2、4 步；用原素材重做一段，逐镜核对可拍条件与总时长，承诺未兑现则拒用。
- 如果官方入口不可访问，沿用已验证流程并列出未核事项；不把搜索摘要当成已读全文。
- 需要新的工具参数、现行规定或平台访问能力时，查官方当前说明并记录所用版本；不凭旧记忆填写。
- 用户事实只来自本人材料；外部案例只用来比较机制，不用于补造数据、经历或原文。
- 保留触发案例及旧输出，定位修改后用相同输入回归；只把可泛化规则写回技能，个人偏好留在个人材料中。

### 明确模拟的执行示范

模拟输入：30 秒桌面口播；只有笔记本电脑。讲“开会前整理问题”，材料是三个字段：现象、影响、希望谁决定。

本轮成品：

0–5 秒｜电脑屏幕上显示三个字段。口播：开会前，我先把问题写成三行。
5–20 秒｜逐行高亮。口播：第一行是什么现象，第二行影响谁，第三行希望谁做什么决定。字幕：现象 / 影响 / 决定。
20–30 秒｜回到全表。口播：下次开会前，先把你最想讨论的一件事填进去。时长为估算，拍摄后按实际停顿调整。

验收：成品仅使用上述模拟输入；缺失内容没有被补成事实。
此演示验证文本判断与交付路径，不代表已调用媒体处理或文件生成工具。
真实调用仍需检查实际文件、页面或片段的覆盖范围。
