# 首屏打招呼语验收尺

仅在需要评估、改写或复盘一条投递打招呼语时使用本尺。它服务于招聘方在列表页先看到第一句话、点击后才看到后文的聊天投递场景。

## 首屏第一句

必须同时满足：

1. 脱离后文也能读懂：读者知道候选人是谁、为什么与这个岗位有关。
2. 只放一个理由：一个岗位关键词或一个可核验结果，不堆项目清单。
3. 是本人事实：数字、职责、公司、项目和到岗状态均有来源；不确定时删除或标记待确认。
4. 不以“您好、打扰了、诚意求职、希望有机会”作为开头；这些词不能构成点击理由。
5. 不承诺招聘结果，不虚构“已深度研究贵司”“非常匹配”等判断。

## 点击后的展开内容

1. 用 1 条最相关的事实补证据，最多补 2 条；每条都回答“这与 JD 的哪一项有关”。
2. 不复述整份简历，不把工具名称或任务清单堆成匹配度。
3. 用一个低摩擦动作收尾，例如“方便的话，我把与 XX 最相关的简历版本发您”。
4. 招聘方身份、称呼、岗位状态未知时，不假装在与业务负责人或 HR 对话。

## 结果回流

以同一岗位族、相近渠道、相近发送时段下的实际反馈看变化。每轮只调整一个变量：首屏角度、展开证据或收尾动作。

- `未读`：优先检查发送时机、招聘方活跃状态或触达渠道，不能把它归因为文案失效。
- `已读未要简历`：优先检查首屏承诺与展开证据是否脱节、是否缺少明确下一步。
- `要简历`：记录首屏角度、岗位族、材料版本和后续面试结果；它是正向信号，不等于拿到面试。
