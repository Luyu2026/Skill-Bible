# 抖音视频文案提取

## 一句话主餐

把用户可访问的视频材料还原为带时间定位的口播与字幕，清楚标出听不清和画面差异，不把摘要冒充原文。

## 输入

优先读取用户已经交来的材料，不要求重新抄写或重复上传可访问内容。

- 用户上传的视频、录屏、音频、字幕文件或可访问的公开视频链接
- 提取范围：口播、画面文字、发布配文或全部
- 是否保留时间戳、语气词、口误和说话人区分

开始前记录本轮范围、已有材料、输出位置与不能确认的事项。
只缺非关键偏好时，明确采用的默认值并继续完成初稿。
缺少核心原件时交付可执行的补料要求，不宣称已完成原件处理。
不得把示例数字、他人经历或工具猜测写成用户事实。

## 核心判断

1. 视频口播、画面字幕、发布配文是不同来源，不混成一篇原文

2. 链接可见不代表可以下载，无法读取就明确未提取

3. 逐字稿保留原表达，整理稿只改标点和断句，改写另行交付

4. 听不清用时间戳标记，不根据上下文补成确定话语

将每条重要信息标记为“材料明确”“用户补述”“编辑建议”或“待确认”。
标记只服务追溯；正式成品不堆内部操作记录。
遇到原材料自相矛盾，保留冲突位置，优先修复会改变结论的项。

## 编号工作流

### 1. 确认可访问材料

- 先识别本地文件、字幕或链接，记录来源名称和范围
- 链接不可用时请求上传已获授权的录屏、音频或字幕
- 不绕过登录、访问控制或平台限制

执行细则：材料登记使用“文件/链接｜可读取？｜已知总时长｜用户指定范围｜可用工具”。链接打不开时记录失败，不从标题猜视频内容。

验收与分支：没有媒体工具但已有字幕时可完成字幕整理；只有链接且不能读取时仅列补料项，本次状态为未提取。

### 2. 划分提取轨道

- 列出需要的口播、字幕、画面文字及发布配文
- 优先使用已有字幕，但检查其是否与音轨对应
- 纯截图只能提取画面文字，不推断未出现的音频

执行细则：分别建立口播轨、画面文字轨和发布配文轨。字幕文件是文字来源，未经回听不标“音频已核实”。

验收与分支：仅有截图就只交截图文字；页面上可见的发布配文按页面来源交付，不当作口播。

### 3. 转写音频与提取画面

- 使用当前可用转写或视觉工具，记录覆盖时间
- 按自然停顿分段，标注说话人变化
- 画面文字记出现时间，重复水印不混入正文

执行细则：对每个片段保留原媒体时间与文件内时间的偏移。例如截取原片 01:00 起的 10 秒，内部 00:03 对应原片 01:03。

验收与分支：使用可用 ASR 时记录语言及实际处理区间；字幕工具不可用可逐条解析已有 SRT/VTT，不许伪造识别过程。

### 4. 对齐并复核

- 口播与字幕不一致时保留两轨并注明差异
- 人名、数字、否定词和产品名优先回听
- 无法确认写作[听不清 00:xx]，保留回查点

执行细则：优先复核数字、否定词、人名和说话人。听不清写“[听不清 00:03–00:05]”；候选词另记，不能默认为确定原话。

验收与分支：字幕与口播不同就并列差异；连续重复字幕可以合并出现区间，不删除真实重复说话。

### 5. 生成复制稿

- 逐字稿保留语气与口误，整理稿只断句和加标点
- 去重时注明连续重复字幕的合并范围
- 用户要改写时另列改写稿，不覆盖提取结果

执行细则：复制稿按“开始–结束｜说话人｜文本｜来源轨”交付。时间未知写未知，禁止为了表格齐全编造秒数。

验收与分支：整理稿只加标点与断句；删口头禅、修语病或重排句子必须另标编辑版，并保留逐字稿。

### 6. 交付覆盖范围与缺口

- 交付文本、时间索引、差异及无法辨认片段
- 长视频未处理的区间显式列出，不称全量完成
- 用户补交清晰片段后只更新对应时间段

执行细则：用区间并集核算覆盖，重叠字幕不能重复累加；列明请求范围内的空缺和是否为无声，而非把空缺当作静默。

验收与分支：补交片段后沿用原片时间更新对应区间，重验前后边界。只有字幕整理完成不能称视频全量转写完成。

## 直接交付与下一步

可运行示例见 [模拟输入与交付](references/worked-example.md)。该例标明验证范围；真实任务不得把样例验收当作实际媒体或文件验收。

交付顺序先放用户可以直接使用的成品，再列必要的核验说明。

- 可复制口播逐字稿或画面文字稿
- 时间戳与来源索引，含口播和字幕差异
- 提取覆盖范围及待核片段列表

### 完成与降级

- 全部约定范围有结果，关键事实可追溯，待确认项不会被误认成事实。
- 工具可用时实际检查生成文件；不能只返回一个未经验证的路径。
- 工具不可用时交付本地 Markdown 或对话文本，并准确说明未完成的文件能力。
- 不自行发送、发布、上传个人材料；外部动作依用户授权执行。
- 本轮先完成一个可用版本，用户交回具体段落、页面或时间点后定点修复。
- 修复保留旧版与来源对应，避免下一轮丢失已经确认的事实。

## 外部参考与延展

- 启动信号：字幕时间错位、重叠区间重复累计或字幕被误称为已回听口播。
- 优先入口：[W3C WebVTT](https://www.w3.org/TR/webvtt1/)；先读用户已有规则，再定位一个具体失败环节。
- 观察与取舍：比较字幕 cue 的起止时间、重叠与轨道信息；ASR 能力另查当前工具官方文档，用“中文 time stamps diarization”定位机制，不按项目热度选型。
- 融入与验证：时间语义接入第 3、6 步；用同一段带重叠的字幕核对区间并集和原片偏移。换识别器必须对同段实际音频复听，只有字幕时不评估识别准确率。
- 如果官方入口不可访问，沿用已验证流程并列出未核事项；不把搜索摘要当成已读全文。
- 需要新的工具参数、现行规定或平台访问能力时，查官方当前说明并记录所用版本；不凭旧记忆填写。
- 用户事实只来自本人材料；外部案例只用来比较机制，不用于补造数据、经历或原文。
- 保留触发案例及旧输出，定位修改后用相同输入回归；只把可泛化规则写回技能，个人偏好留在个人材料中。

### 明确模拟的执行示范

模拟输入：用户提供转写片段，00:00–00:03“今天讲三个整理方法”；同段画面字幕为“3个整理方法”；00:03–00:05 音频模糊。

本轮成品：

口播逐字稿
00:00–00:03 今天讲三个整理方法。
00:03–00:05 [听不清，需补交清晰音频]
画面文字
00:00–00:03 3个整理方法
覆盖说明：仅整理用户提供的 5 秒片段，未访问原视频；未补写所谓“三个方法”。

验收：成品仅使用上述模拟输入；缺失内容没有被补成事实。
此演示验证文本判断与交付路径，不代表已调用媒体处理或文件生成工具。
真实调用仍需检查实际文件、页面或片段的覆盖范围。
