# 八字搭档娱乐匹配

## 一句话主餐

基于两人的已核验排盘做传统文化娱乐对照，并转成合作沟通问题，解决匹配结论悬空且无法落地的问题。

## 输入

- 两人明确同意提供的出生记录或已有四柱
- 记录公历农历、出生地点、时区及时间精度
- 已有排盘需附工具名、历法口径及节气换月规则
- 希望讨论的合作情境，如分工、节奏或冲突沟通
- 可只用代号；缺时辰不自行补成某个时柱

材料优先级：用户现有原稿与记录优先；补充信息只追问会改变本轮判断的部分。
真实材料、合理推断与明确模拟内容分别标记。
不能读取附件时，请用户粘贴关键片段；先完成不依赖附件的部分。

## 核心判断

1. 传统象征解释与现实人格、能力和兼容性证据分开
2. 有生辰但无可靠排盘工具时只核对输入，不凭记忆算四柱
3. 时辰、换日和节气边界有争议时并列可能口径
4. 不同传统规则可能相互矛盾，不用精确匹配分伪装测量
5. 单项合冲不能推导两人必然合作成功或失败
6. 现实合作问题优先按实际行为讨论，不把八字当因果解释

## 编号工作流

### 1. 确认两人资料边界

- 用 A/B 代号记录，无需姓名联系方式
- 说明本轮为传统文化娱乐解读
- 核对各自同意提供的信息与时间精度
- 只要求会改变排盘的缺失项

### 2. 核验排盘来源

- 已有四柱逐项记录年、月、日、时
- 检查来源与时区、历法、换日口径
- 不能验证时明确标为用户提供未核验
- 工具不可用时交付输入核对单和现实沟通版

### 3. 选择对照维度

- 默认仅做可核对的地支六合、六冲符号对照，规则见 references/review-example.md；其他体系须先取得规则来源
- 记录每条规则来自哪个体系或工具说明
- 缺时柱时仅讨论可见部分，不推补隐藏关系
- 遇到冲突规则说明为何不做总分合并

### 4. 写条件化娱乐解读

- 表格列柱位与地支、规则匹配、文化解释边界、现实待观察点；未核验盘只写条件化符号对照
- 用“该体系通常象征”描述，而非断言人格
- 合冲出现时说明这是符号关系
- 不推断健康、忠诚度、财富或重大人生结果

### 5. 转成合作对话

- 针对用户实际场景设计分工和反馈问题
- 每个问题都可以靠双方回答而非排盘验证
- 建议把决定权、交付节奏和分歧处理写清
- 双方不同意象征解读时直接保留现实清单

### 6. 交付并控制后续范围

- 本轮只完成一次对照与一次合作讨论清单
- 用户若要修改输入，先比较排盘口径再重解
- 交回双方认可的合作约定，无需追加私密信息
- 不把娱乐互动引导为命运保证或付费化解

## 直接交付与下一步

- 两人排盘口径与缺失项记录
- 有依据的条件化传统娱乐对照
- 可直接用于讨论分工的合作问题清单
- 无排盘工具时的核对表和现实合作降级版

### 完成条件：符号对照是否有逐项依据

- 每条对照均写出 A/B 柱位与地支及所用规则；不匹配不能算冲突，缺失不能算不合。
- 必须实际执行一次，成品格式与验证边界见 [完整案例](references/review-example.md)。
- 交付前依据案例中的反例检查，不能只检查标题和行数。
- 用户交回材料后，先复查改变的输入，再沿原路径更新，不无故重做全部内容。

### 工具与数据降级

- 无可靠排盘工具时不生成四柱；可基于已提供地支做明确标为未核验的符号对照，同时交可直接填写的合作约定。
- 文件生成失败就交付可复制正文，说明未生成文件；不把文本方案说成成片、图表或附件。

### 外部参考与延展

- 何时研究：两工具排盘不同、节气边界或规则解释冲突时启动。
- 去哪找：查排盘工具算法说明、历法资料与明确版本的传统文献；检索“节气换月 子时换日 排盘口径”。
- 看什么：比较时间转换、规则来源和同一符号的解释差异。
- 怎么用：先修正输入与规则，再改对照；不能用网页数量多数投票决定真实命运。
- 采用前比较至少两个可行机制或与当前方法对照，说明材料成本及适用边界。
- 用触发问题的同一输入验证改动，保留有效方法，丢弃不能改善交付的装饰功能。
- 外部资料帮助调整方法，不能替代用户事实；实际复用受许可约束的内容时保留必要声明。

### 本轮执行门槛

- 第一关：符号对照是否有逐项依据；不满足时收窄输出到有依据的部分。
- 第二关：按原输入复算或逐句比对，记录具体通过项，不以“已检查”代替证据。
- 第三关：输出一个可以直接使用的成品，并明确本轮待补材料。
- 仅用于核对干支名称与历法背景，不作为人格或关系预测的证据；六合六冲是明确列出的传统符号规则。
- 方法入口：[香港天文台干支资料](https://www.weather.gov.hk/en/gts/time/stemsandbranches.htm)。
- 来源用于改进方法，不提供用户事实；没有读取具体资料时不写“已研究验证”。
- 持续反馈若暴露同类缺陷，保留触发输入与旧输出，在授权目录中修改候选版，再用原例和受影响场景复验。
- 本轮只推进当前卡点；下一步验收以用户补交的材料为准，不承诺后台自动跟进。
