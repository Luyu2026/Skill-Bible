# wechat-visual-narrative

公众号视觉叙事与批量配图助手。

它适合用在这样的场景：你的公众号文章已经写完，标题和正文也不想再动，但全文只有文字、读起来发空；你只需要把飞书文档交给 Agent，它会判断文章类型，并按对应规则把该补的图直接生成、放回原文档。

它不把每个二级标题都机械配一张图，也不再确认标题和文案。它只判断文章是讲 Skill 流程、命题论证，还是一篇真实案例复盘，再让图片承担不同任务。

## 它会先判断三种文章

| 文章类型 | 图要解决什么 |
| --- | --- |
| Skill 使用 / 流程型 | 把“我卡在哪 -> 用什么 -> 得到什么”讲清楚 |
| 命题论证 / 多人物视角型 | 让不同视角的分歧、盲区和作者结论变得可见 |
| 真实案例 / 复盘型 | 用真实过程、数据和前后变化支撑判断 |

例如，一篇讲“如何把多个 Skill 串成工作流”的文章，适合白底、蓝色线框、黄色重点的产品说明图；一篇用多位人物框架讨论同一个问题的文章，适合深蓝底、暖金光、中心命题的编辑插画。两者不该用同一种配图。

## 你会拿到什么

- 一份配图清单：每张图放在哪里、解决哪一个阅读任务。
- 一组统一的视觉系统，不会一篇文章里一半像产品页、一半像摄影海报。
- 每张图的生成提示词与需要补充的真实素材说明。
- 用户确认后生成真实图片；需要时插入原飞书文档，而不是留下画板或占位描述。

## 真实素材优先

技能真实输出、飞书页面、数据后台、用户反馈、改稿前后对比，优先使用真实截图。

生成图适合解释：流程、关系、抽象命题、无法拍摄的场景。它不能伪造真实数据、真实产品输出或用户反馈。

## 第一次使用

把已写好的飞书文档链接发给 Agent：

```text
请使用 wechat-visual-narrative 为这篇公众号文章补图：
[飞书文档链接]

标题和正文已经定稿，不需要确认或改写。
请先识别文章类型，再按对应视觉规则直接生成并插入图片。
真实截图位置不要伪造，直接标出我需要补的素材。
```

## 适合谁

- 公众号文章已经写好，但不知道哪些地方该补图。
- 想让图片真正帮助读者理解，而不是只让页面看起来热闹。
- 同时写流程型文章、观点型文章和案例复盘，想维持各自稳定的视觉语言。
