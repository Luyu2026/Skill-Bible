# 公众号视觉叙事

用户给出飞书文档时，默认标题和正文已经定稿。不要重新确认标题、重写文案、让用户确认配图清单，或把文章拆成新的大纲；任务是让图片为现有文章服务。

## 输入

- 已定稿的飞书文档链接或完整文章
- 可选：个人 IP 形象、已有封面、真实截图/数据、指定图片数量
- 可选：是否只生成图片，或生成后直接插入原飞书文档

若用户只说“补图/给文章配图”，默认直接生成；若当前环境能写入飞书，则将真实图片插到对应段落之后。只报告实际成功生成或上传的结果。

## 第一步：先识别文章类型

先通读全文，选一个主类型；不要混用不相干的视觉语言。

| 类型 | 文章真正要完成什么 | 默认视觉语言 |
| --- | --- | --- |
| `Skill 使用/流程型` | 让读者看懂一套能力如何解决具体卡点、如何串成流程 | 白底、蓝色线框、黄色重点、清晰箭头和卡片；像 AI 产品说明图 |
| `命题论证/多人物视角型` | 围绕一个问题，让不同视角形成冲突、补全和结论 | 深蓝/近黑底、暖金色光束或中心物、留白；像一篇有作者判断的编辑插画 |
| `真实案例/复盘型` | 用真实过程、数据或前后对比证明判断 | 真实截图、数据图、原始材料优先；生成图只补无法截图的关系或场景 |

文章可以有次类型，但只让主类型决定封面与大部分内图。若无法判断，先按“读者看完最该带走什么”判断，而不是按标题里的关键词判断。

## 第二步：决定图片是否必要

每一张图必须只完成一个阅读任务。不要因为一个二级标题就机械配一张图。

优先为以下位置配图：

1. `封面`：让陌生读者一眼知道文章的核心命题或收益。
2. `关键转折`：从问题进入方法、从分歧进入结论时，帮助读者跟上逻辑。
3. `复杂关系`：流程、对比、矩阵、优先级、多个视角的交叉，文字读起来费力时。
4. `可信证据`：真实产物、数据、前后对比、用户反馈；这里优先真实截图。
5. `结尾收束`：仅在需要把判断压成可传播画面时使用，不为装饰重复前文。

不配图的情况：一段本身已经是清晰的故事、一个短结论、或图片只会把文字再说一遍。

## 第三步：按类型规划视觉系统

### A. Skill 使用/流程型

目标是让用户相信“我知道自己卡在哪，也知道下一步怎么做”。

- 封面：`核心收益 + 个人 IP + 关键输入/输出`，不堆满所有功能。
- 正文：用流程图、输入输出图、卡点到结果的映射、真实产物截图。
- 统一使用白底、深蓝线框、蓝色信息层级、黄色强调；人物只在封面或“使用者”场景出现。
- 真实 Skill 输出、飞书页面、产品界面要用真实截图；不能用生成图伪造“实际运行结果”。

### B. 命题论证/多人物视角型

目标不是展示“有几个 Skill”，而是让读者看见同一个问题被不同框架照亮后，原来的盲区在哪里。

正文顺序默认是：

`具体困境 -> 为什么常见答案不够 -> 不同视角各看见什么 -> 冲突/盲区 -> 作者的判断 -> 可以复用的思考方法`

- 封面：一个中心命题或物体，被 2-3 道不同方向的光照亮；可以出现个人 IP 作为叙述者。
- 人物视角：优先用“人物名 + 核心问题 + 视觉符号”的视角卡，而不是排列名人头像。
- 只有在用户已有可用素材、且确实增强识别时，才使用人物肖像；不要生成真实名人的仿真肖像。
- 内图优先：视角分歧图、盲区交叉图、结论收束图。保持深蓝/近黑、暖金、克制的编辑感。
- Skill 只在结尾作为“这套思考如何被复用”的载体，不抢文章主线。

### C. 真实案例/复盘型

目标是让读者相信“这件事真实发生过，结论来自过程而不是口号”。

- 先索要或复用真实截图：数据后台、初稿与改稿、对话、表格、页面、用户反馈。
- 每张截图只标一条要看的证据，必要时加简短箭头/标注。
- 生成图只能解释抽象关系，例如“问题如何从数据中被定位”；不能替代证据。

## 第四步：直接生成并插入

识别类型后，不必要求用户确认配图方案，直接完成以下动作：

1. 从文章逻辑里挑出真正需要视觉解释的节点；短文通常 3-4 张，中长文通常 5-7 张，不为凑数量配图。
2. 统一生成同一组图片，先保持视觉系统一致，再追求单张花样。
3. 封面负责点击，内图负责理解；图中文字仅保留手机端必须读到的 1-2 句。
4. 只在图片真实生成、上传成功后，才写入飞书文档。插图紧跟其解释的段落，除非用户明确要求统一附在文末。
5. 遇到需要真实 Skill 输出、飞书页面、数据后台或用户反馈的段落，保留真实截图位置并简短说明用户需要补什么；绝不以生成图冒充。
6. 插入结束后，逐张核对位置、比例和移动端文字可读性，再返回飞书链接。

## 统一质量线

- 一张图只讲一件事；没有“标题 + 六段字 + 八个图标”的信息堆砌。
- 图中文字必须能在手机端读清，优先短句、数字、对比和箭头。
- 一篇文章只使用一个主视觉系统；流程型不混入半写实照片，命题型不混入产品说明图。
- 没有真实数据或真实界面时，不伪造截图、成交、用户反馈或 Skill 输出。
- 人物 IP 只在能增强作者身份或叙事时出现，不强迫每张图都有人。
- 图片不是装饰。删掉某张图后，如果读者理解没有损失，就不该生成它。

## 持续迭代

当用户反馈“读不下去、图太像模板、看不懂、转化弱”时，先定位问题发生在封面、逻辑节点、信息密度还是视觉系统。再研究同类高质量文章的具体做法，更新对应类型的图式和提示词，并把关键变化记入版本记录。不要因为一次反馈就给所有文章换一套风格。
