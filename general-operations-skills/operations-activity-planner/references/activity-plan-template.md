# 活动方案模板

本文件是 operations-activity-planner 的参考模板。生成活动方案时按此结构输出，每个章节的说明文字是写作指引（不要原样复制到最终文档里），根据实际需求填充内容。

---

## 文档头部

```markdown
# [活动名] 活动方案

方案版本：V1.0
日期：（当天）
```

---

## 一、概述

**作用**：一段话说清活动全貌，供快速决策。

```markdown
## 一、概述
- **活动目标**：（量化，如拉新 5w 注册 / 转化率提升 2pp）
- **目标用户**：（谁参加，他们现在怎么解决）
- **时间窗口**：（预热期 / 正式期 / 收尾期）
- **预算**：（总预算 + 单用户成本上限）
- **活动类型**：（拉新/激活/留存/转化/品牌）
```

## 二、活动设计

**作用**：核心机制，要具体到可执行。

```markdown
## 二、活动设计
### 2.1 活动机制
（一句话说清：用户做什么 → 得什么 → 门槛是什么）

### 2.2 参与链路
（用户从哪看到 → 怎么参与 → 怎么领奖，完整闭环）

### 2.3 激励设计
| 激励 | 成本 | 吸引力评估 |
|------|------|-----------|

### 2.4 触达计划
| 渠道 | 内容 | 时间 | 目标用户 |
|------|------|------|---------|
```

## 三、页面与物料需求

**作用**：让设计/开发能直接开工的清单。

```markdown
## 三、页面与物料需求
- [ ] 落地页（含规则、参与入口）
- [ ] 弹窗 / Banner
- [ ] 推送 / 短信文案
- [ ] 设计物料清单
```

## 四、风控与合规

**作用**：易漏项，必须有。

```markdown
## 四、风控与合规
- **防刷机制**：（设备/手机号/身份限制、单人上限）
- **风险预案**：（服务器/恶意参与/用户投诉）
- **合规检查**：（活动规则合法性、奖品合规、个保法）
```

## 五、成本收益测算

**作用**：用数据说话，区分直接 ROI 与长期价值。

```markdown
## 五、成本收益测算
| 项 | 测算 | 依据 |
|----|------|------|
| 成本 | 奖品 X + 投放 Y + 人力 Z | ... |
| 直接收益 | 参与量 × 转化率 × 客单价 | 行业区间 |
| 直接 ROI | 收益/成本 | >1 才做 |
| 长期价值 | 拉新用户 LTV、品牌曝光 | 定性 |

> ROI < 1 不意味着不做——判断长期价值（拉新用户后续 LTV）。区分"直接 ROI"与"长期价值"。
```

## 六、执行计划

**作用**：时间轴，让项目可管理。

```markdown
## 六、执行计划
| 阶段 | 时间 | 关键事项 | 负责人 |
|------|------|---------|--------|
| 开发 | 7/1-7/7 | 页面、埋点 | 张三 |
| 测试 | 7/8-7/9 | 全链路验收 | 李四 |
| 预热 | 7/10-7/12 | 预告、蓄水 | 王五 |
| 上线 | 7/13-7/20 | 正式期 | 全员 |
| 收尾 | 7/21 | 兑奖、归档 | 王五 |
```

## 七、验收指标与埋点

**作用**：让效果可衡量，为复盘留证据。

```markdown
## 七、验收指标与埋点
- **北极星指标**：（本次活动的核心指标）
- **过程指标**：（参与率/转化率/分享率）
- **埋点事件清单**：（曝光/点击/参与/转化/分享）
```

## 八、风险与假设

**作用**：诚实标注不确定项，评审会可用。

```markdown
## 八、风险与假设
- [ ] 假设1：（如"工具型用户对现金激励敏感"）若违反则（调整方案）
- [ ] 待确认：（预算、转化率基准、合规审批）
```
