# 《增长黑客》· 增长体系方法论

> 核心立场：增长不是单点爆款技巧，而是**制度化的数据驱动体系**——组增长团队、定北极星指标、跑高频实验循环。

## 核心框架一：增长黑客实验循环

**适用场景**：产品已过 PMF 验证、留存达竞品基线后追求可持续增长。

```
① 分析（定量漏斗/群组/留存 + 定性调研，定位薄弱环节）
    → ② 提想法（跨职能头脑风暴，多多益善并存库）
    → ③ 排优（ICE：影响 Impact × 信心 Confidence × 易做 Ease 打分排序）
    → ④ 快节奏测试（A/B，一次只改一个变量）
    → ⑤ 度量复盘（记录假设、结果、干扰因素、结论）
    → 回到 ①，形成闭环
```

**输出物**：实验想法库、ICE 评分表、实验记录模板（名称/描述/类型/关键指标/假设/结果/干扰因素/结论）。

> 原则："缓慢起步，逐渐提速"——先小规模跑通循环，再加速。

## 核心框架二：北极星指标

**适用场景**：团队目标分散、指标打架、跨职能协同时。

**步骤**：
1. 选一个代表"用户获得核心价值"的单一指标（如付费订阅数、周活跃用户）
2. 拆成增长等式（如 DAU = 新增活跃 + 老用户活跃 + 流失召回）
3. 配套关键指标看板（定量）+ 用户心理决策地图（定性）
4. 定期复核是否仍代表价值

**输出物**：增长等式、指标看板、北极星指标说明书（含选择理由与排除项）。

## 核心框架三：AARRR 用户生命周期漏斗

**适用场景**：定位增长瓶颈、按阶段分配资源。

| 环节 | 核心要点 | 关键公式/方法 |
|------|---------|--------------|
| 获客 | 语言-市场匹配 + 渠道-产品匹配 | LTV > CAC 才放量 |
| 激活 | 引导"啊哈时刻" | 转化 = 触发物 + 欲望 − 摩擦 |
| 留存 | 初期（激活延伸）/中期（养成习惯）/长期（重新认识价值） | 留存曲线对比竞品基线 |
| 变现 | 绘制旅程盈利点与阻碍点 | 定价/套餐实验 |
| 推荐 | 病毒系数 | K = 邀请数 × 受邀接受率 |

## 决策规则（8 条，标注来源）

1. **如果**产品尚未验证"不可或缺性"（PMF），**则**不烧钱获客，先做用户调研（"明天不能用有多失望"问卷 + 访谈）并与竞品留存对比，改进至留存达竞争基线。（第 2 章）
2. **如果**团队对增长目标各说各话、指标打架，**则**先定单一北极星指标并拆成增长等式、上线看板，再谈任何实验。（第 4 章）
3. **如果**实验想法过多，**则**用 ICE 打分排序，优先执行"高影响+高信心+易实现"批次，每轮只做 1-3 个。（第 5 章）
4. **如果**新用户激活率低，**则**优先减摩擦（精简注册字段、简化 onboarding）而非加功能，设计直通"啊哈时刻"的引导路径。（第 7 章）
5. **如果**某获客渠道 ROI 不明，**则**不加大投放，先小预算多渠道路测做渠道-产品匹配，确认 LTV > CAC 再放量。（第 6 章）
6. **如果**中期/长期留存下滑，**则**从"养成习惯"入手：调优触发物频率与奖励设计，周期性推出新功能让用户重新体验价值。（第 8 章）
7. **如果**实验结果无法沉淀复用，**则**强制按固定模板记录假设/结果/干扰因素/结论，回写想法库作为下一轮输入。（第 5 章）
8. **如果**要做推荐/裂变，**则**先确认产品价值体验到位，算出病毒系数 K，再以实验调优邀请话术与数量。（第 6/9 章）

## 检查清单

**启动前**
- [ ] 不可或缺性已验证（问卷 + 竞品留存对比）？
- [ ] 有单一北极星指标并拆成增长等式？
- [ ] 有跨职能增长小组与固定实验节奏（如每周一轮）？
- [ ] 埋点/看板能支撑分环节漏斗与群组分析？

**每轮实验**
- [ ] 基于数据分析定位环节，而非拍脑袋？
- [ ] 假设清晰："改变 X → 影响 Y 指标"？
- [ ] ICE 排序后只做优先级最高的 1-3 个？
- [ ] 控制变量：一次一变量、样本量与时长足够？
- [ ] 按模板记录名称/类型/关键指标/假设/结果/干扰因素/结论？
- [ ] 结果回写想法库或更新基线，形成下一轮输入？

## 反模式

- 无 PMF 硬砸钱获客（漏斗漏得比进的快）
- 把增长黑客当一次性"爆点技巧"而非制度化实验体系
- 虚荣指标当北极星（注册量/下载量/曝光 ≠ 激活留存）
- 实验无沉淀 + 触发物骚扰（同样的坑反复踩；推送过度反噬留存）

## 边界声明

- 原书是美国 SaaS/科技公司语境（2017），默认有工程/数据团队与 A/B 基础设施；中国运营语境更依赖渠道投放、补贴、社群与平台规则——**循环方法论适用、案例不直接照搬**
- 方法论默认产品已过 PMF 验证；需求验证期的产品应先走精益/访谈路线
- 小团队可跑简化版；高客单 B2B、低频场景样本量小、A/B 不现实，应以群组分析 + 定性调研替代
- 裂变、K 因子等技巧依赖渠道红利窗口，用前需验证当前环境；GDPR/个保法下数据实验须合规
