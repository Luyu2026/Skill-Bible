# 数据分析报告模板

本文件是 operations-data-analysis 的参考模板。生成分析报告时按此结构输出，每个章节的说明文字是写作指引（不要原样复制到最终文档里），根据实际需求填充内容。

---

## 文档头部

```markdown
# [指标名] 分析报告

报告人：（自动）
日期：（当天）
数据来源：（用户提供 / 用户描述 / 授权查询）
```

---

## 一、结论先行

**作用**：让读的人 30 秒内抓住要点。

3 句话内回答：
- 发生了什么（现象）
- 影响多大（量级）
- 最可能的原因（初步判断 + 证据等级）

```markdown
## 结论先行
- **现象**：DAU 环比下降 10%（23.1w → 20.8w）
- **影响**：约 2.3w 日活流失，按当前 ARPU 测算影响月收入约 X
- **初步判断（B 强推断）**：主要受 7 月 12 日推送策略调整影响，待验证
```

## 二、数据体检

**作用**：先确认数据可信，再谈分析。逐项打勾。

```markdown
## 数据体检
| 检查项 | 结果 | 说明 |
|--------|------|------|
| 数据周期完整 | ✅/❌ | ... |
| 口径一致 | ✅/❌ | ... |
| 异常峰值/谷值 | ⚠️ | 7/11 大促带动 |
| 样本量足够 | ✅ | ... |
| 对比基准合理 | ⚠️ | 去年同期基数低 |

**数据可信度：[高/中/低]**（体检发现问题则降级，不硬下结论）
```

## 三、拆解过程

**作用**：展示你从总指标拆到具体环节的过程，让别人能复核。

每次只拆一个维度，直到定位到最大贡献因子：

```markdown
## 拆解过程
总指标：DAU -10%
├── 渠道维度 → 自然流量 -15%（最大贡献）、付费 -5%、活动维持
│   └── 自然流量 → 老用户回流 -20%、新用户 -3%
│       └── 老用户回流 → 与推送策略调整时间吻合（7/12）
├── 用户群维度 → 低频用户流失 -25%（主要）
└── 环节维度 → 激活率稳定、留存下滑
```

## 四、现象定位

**作用**：给出定位结论 + 证据等级。现象 ≠ 原因，原因标注推断等级。

```markdown
## 现象定位
- **定位**：老用户（尤其低频用户）回流减少是 DAU 下滑主因
- **证据等级**：
  - 数据支持（A）→ 拆分数据明确显示...
  - 强推断（B）→ 时间点与推送调整吻合...
  - 推测（C）→ 可能是推送频次下降导致，需验证
```

## 五、行动建议

**作用**：从分析到动作。区分止损 / 验证 / 长期优化。

```markdown
## 行动建议
| 优先级 | 动作 | 类型 | 期望效果 |
|--------|------|------|---------|
| P0 | 恢复低频用户推送频次（7/12 前水平） | 止损 | 回流率回升 |
| P1 | 对低频用户做分群 A/B 测试触达内容 | 验证 | 确认最优触达策略 |
| P2 | 建立低频用户唤醒自动化机制 | 长期 | 降低流失率 |

## 待验证假设
- [ ] 假设1：推送频次下降导致回流减少（验证方式：恢复后对比 2 周数据）
- [ ] 假设2：竞品 7 月新增同类功能分流（验证方式：竞品数据/市调）
```
