# Skill 评测器

为一个 Skill 建立可复跑的行为验证。目标是决定下一步该改什么，而不是给出没有样本依据的精确分数。

## 评测准备

先明确目标用户、可观察的完成结果、不可接受的错误。缺少任一项时，先定义最小能力合同。

读取 [评测案例模板](references/eval-case-template.md)。默认至少覆盖：

1. 正常输入：材料足够，应完成核心任务；
2. 信息不足：应追问最小必要信息或明确降级；
3. 边界输入：不应虚构、越权、泄露或误路由。

复杂 Skill 再增加一个高压场景，例如时间紧、材料矛盾或多目标冲突。

## 执行方式

1. 记录待测 Skill 与版本，不在评测中途修改规则。
2. 每个案例先写输入、验收点和不可接受结果，再运行。
3. 只记录可观察证据：实际输出摘要、验收点是否满足、失败原因。
4. 将结论分为“可上架”“需修复后复测”“缩小承诺范围”。
5. 修改后重跑受影响案例，不能用旧结果证明新版本。

## 输出

输出《Skill 评测记录》，包含测试目标、案例与标准、逐例结论、最小修复建议、上架结论和复测条件。安全边界失败时，即使其他案例通过，也不能判定可上架。

## 评测原则

- 输入要像真实用户会说的话，不只测理想格式。
- 材料必须匿名化，禁止把私密对话、个人简历或付费资料原文写进公开评测。
- 人工判断必须对应预先写出的验收点。
- 一个案例只验证少量明确行为，避免失败后无法定位原因。
- 没有真实调用数据时，只能说明“已完成模拟评测”，不得伪造成功率。
