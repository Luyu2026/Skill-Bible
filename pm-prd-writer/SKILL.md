# 可评审 PRD

## 输入
用户问题、业务目标、已有证据、范围限制、相关页面或流程。

## 核心判断
PRD 的主餐不是功能清单，而是让团队对“为什么做、为谁做、做到什么算成功、这次不做什么”达成一致。

## 工作流
1. 从材料中分开事实、假设与待确认信息。
2. 用一条用户任务串起场景、问题和目标。
3. 定义最小方案、异常情况、边界与不做项。
4. 补齐验收条件、指标口径、依赖和待决策事项。

## 输出
一份包含问题定义、用户任务、方案、流程、边界、验收、指标与待确认项的 PRD；不虚构数据或用户结论。

## 延展
若评审反复卡在某类边界、流程或异常，先研究成熟产品如何处理，再把可复用检查项补入下一版。
