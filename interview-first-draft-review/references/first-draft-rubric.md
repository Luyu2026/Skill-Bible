# 面试逐字稿初稿审阅量表

只在需要逐段判断时读取。本量表用于定位问题和生成可执行修改建议，不用于把每一段打分后堆成报告。

## 1. 经历结构

| 检查点 | 合格信号 | 常见初稿问题 | 审阅动作 |
| --- | --- | --- | --- |
| 简历原稿 | 能看到原句或可追溯事实 | 直接从“我做了很多事”开始 | 要求保留简历原稿，先锁事实范围 |
| 经历简述 | 30-60 秒说清业务、本人职责、结果 | 一上来讲公司背景，听不出本人做了什么 | 用“我在什么场景，负责什么，解决了什么，结果如何”重写开头 |
| 背景 | 说明业务限制或用户问题 | 用公司简介代替问题 | 删除无关百科，只保留不解决会怎样 |
| 任务 | 有本人职责和成功标准 | 用“负责运营/协助项目”代替任务 | 追问本人交付物、边界和指标 |
| 问题/判断 | 说明为什么做下一步 | 动作罗列，没有问题来源 | 补现象、数据、访谈或约束，并说明为什么不是另一个问题 |
| 动作 | 2-3 个有先后关系的关键行动 | 一段里塞满十个动作/框架 | 保留改变结果的动作，补顺序、取舍和协作 |
| 结果 | 有指标与事实边界 | 只写“效果很好/增长显著” | 补基线、口径、周期、个人归属；无证据则写待确认 |
| 复盘 | 能说明不足和下一次怎么验证 | 空泛“以后会更努力” | 指向当前方案不能证明的地方，给出可执行改进 |

## 2. 数据与因果

一个数字至少检查五件事：

1. **是什么指标**：咨询率、付费率、留存率、接待能力、GMV 等不能混称“增长”。
2. **怎么计算**：分子、分母、基线或对照分别是什么。
3. **观察多久**：日期、活动周期、30 日窗口、累计还是单期。
4. **谁的结果**：个人、项目、团队、平台背景必须拆开。
5. **能证明到哪里**：多个动作同时变化时，只能说“调整后同向改善”，不能声称每个动作的精确贡献。

以下表述默认判为风险，直到补到证据：

- “提升 30%”没有指标、基线或周期；
- “覆盖 1 万用户”没有去重、触达/参与定义；
- “排名前三”没有评价范围和标准；
- “接待能力翻倍”被说成收入翻倍；
- 团队数据直接写成个人产出；
- 调整后指标变化被说成完全由某一动作导致。

## 3. 高风险追问

每段核心经历优先从下列问题中选最相关的 3-5 个，而不是全部罗列：

| 信号 | 必问追问 | 需要准备的证据 |
| --- | --- | --- |
| 大幅数据提升 | 数据从哪里来、口径是什么、比较了谁 | 指标定义、时间窗口、原始记录或可核验来源 |
| “主导/负责/推动” | 你本人做了什么，其他人做了什么 | 个人交付物、决策权、协作分工 |
| “做调研/用户洞察” | 样本是什么，具体发现如何改变动作 | 访谈/问卷对象、问题、关键发现和决策变化 |
| 方案选择 | 为什么选这个，不选什么 | 替代方案、成本、风险、约束 |
| 多个动作 | 顺序是什么，哪一步最关键 | 优先级、依赖、资源限制 |
| 成功结果 | 如何排除自然波动或其他变化 | 同批次比较、观察窗口、不能证明的边界 |
| 失败与复盘 | 重做会怎么改 | 记录方式、验证方案、停止条件 |

## 4. 口述验收

主线成熟不等于背得流利。要求学生不看稿，在 60-90 秒内完成：

1. 第一段直接回答“这段经历是什么”；
2. 说清一个由事实支持的问题判断；
3. 讲出不超过三个、顺序明确的动作；
4. 给出一个有边界的结果；
5. 被问“为什么”和“数据怎么算”时不换题、不编造。

出现以下情况，先回到结构或证据，不做辞藻润色：讲到一半忘记下一步、只能背原句、数字说不出口、被追问后开始泛讲框架、无法区分自己和团队的贡献。
