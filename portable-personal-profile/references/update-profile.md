# 续写已有档案

1. 读取档案版本、受影响的记录及其来源。用户要求记录当前会话时，从最近已存的决定或进度开始核对。只有能回查的对话节选才作为证据。保存用户确认的内容、说过的偏好、实际发生的进展，以及会影响下一步的待决定事项。
2. 同一个决定或项目沿用原 ID。语义与来源都相同的重复内容无需写入。如果本次增加了确有价值且未收录的依据，只补一条来源。沿用同一份会话摘录时给新内容加独立的 ASCII 小节名，保留旧小节。
3. 已确认的项目状态按时间推进。例如原记录为「待发布」，本轮查到发布回执，更新同一 ID 并在版本记录保留前后状态。有同一时期、同一情境的相互矛盾说法时，保留双方出处并用 `conflict` 待裁决。AI 提案保持待决定，直到用户确认或有执行回执。
4. 只在内容或来源实际变化时递增档案版本。校验后生成 `PROFILE.md`。回读一条新增或变更记录并与来源核对，再告诉用户实际新增、更新和待确认的事项。有并行改动时重新读取受影响文件并合并差异。

同一批材料重复处理时，记录内容、来源登记和档案版本应保持一致。更新本地档案与同步到 GitHub 是两个可分别授权的动作，GitHub 同步由用户指定私有仓库后执行。
