# 冲突与隐私操作

同 id 多值不得覆盖：先在内存比较，再写一条含双方来源的 conflict。若磁盘已存在重复 id，校验会拒绝；人工整理成 variants 后再运行。不同日期或不同用途的偏好可能共存，先问适用情境，不替用户裁决。

用户明确裁决后：把原记录连同双方值存入 history/ 的带版本文件；登记用户裁决摘录为新来源，原 id 更新为裁决值；版本记录注明旧版本、改动 id、取舍理由、被替代值与历史文件位置。没有裁决时保持 pending_user。Git 合并失败先处理文本冲突，再查同义不同 id 的语义冲突；不使用强制覆盖、reset 或丢弃他人改动。

秘密在进入档案前删除，不把敏感标记当凭证保险箱。来源摘录尽量最小化；邮箱、薪资、公司内部信息等显式 sensitive=true。原始私有结构化文件仍含敏感数据，不能因 PROFILE.md 隐藏了内容而公开整个文件夹。

`render_profile.py --public` 只导出 confirmed/current 且 sensitive=false 的记录，省略原始来源和不确定项；它仍显示来源 id 与复核触发文本，人工需检查所有这些字段及再识别风险。不要连同 sources、history 或 Git 历史分享。已泄露秘密须撤销/轮换；仅删除最新文件不能清除 Git 历史泄露。

扫描覆盖包内 UTF-8 文本（跳过 .git），拒绝符号链接，检测常见 token/私钥/凭证赋值与本机绝对路径；不能发现所有秘密、个人信息或自然语言冲突。脚本不改变系统权限。备份与同步访问权限由用户实际配置。

生成视图统一转义外部字符串中的 Markdown/HTML 标点（包括来源引用、复核字段、正文与变体），并将换行和控制字符替换为空格，防止文本形成链接、HTML 或其他渲染注入。来源 id 仅接受小写字母开头及小写字母、数字、点、下划线、连字符；引用可追加 #anchor，anchor 仅接受 ASCII 字母、数字、点、下划线、连字符。

sensitive=true 的记录在私有 PROFILE.md 中仅保留稳定 id 与状态，正文、来源引用、复核字段及所有变体统一隐藏；公开视图仍整条跳过。转义仅防渲染注入，不等于加密或权限控制，原始档案仍需私有保存。
