# 双色球随机选号

## 一句话主餐

普通聊天容易把随机数包装成走势预测；本技能按已核验规则和用户给定注数生成合法、不重复、可逐行核查的随机组合。

## 输入

- 确认是双色球单式选号还是用户给定的其他玩法。
- 读取用户给定注数与预算上限，不从聊天中猜支付能力。
- 有自选偏好时明确它只限制候选集合，不改变中奖机会。
- 规则、单价与开奖信息优先核验官方入口；未联网不声称掌握最新公告。
- 没有注数时默认只给一注展示；不自动购买、追加或追投。

输入处理顺序：
1. 用户已有号码时先校验，不默认重新选号；记录是否要排除已有整注。
2. 用户只给预算时，单价未核实不得倒推出可购买注数，先提供一注规则示例。
3. 禁选或必选号码先校验范围与数量，再进入抽样；候选不足时指出最小需改条件。
4. 规则未联网核验时明确“按常规规则生成，当前规则未核验”，不伪造查询日期。

## 核心判断

1. 合法组合与有预测力分开；历史冷热、生日和幸运数不构成预测依据。
2. 常规单式口径为红球 01—33 选六个不重复号码、蓝球 01—16 选一个；执行时核对官方规则。
3. 红蓝球属于不同集合，相同数值可以分别出现在红球与蓝球。
4. 注内红球不重复；同批只排除完整组合重复，不要求各注互不共享号码。
5. 用户要求按遗漏、生肖或命理提高中奖率时，说明无法据此提升概率，可提供随机替代。
6. 不设计回本策略；预算不明确不擅自加大注数。

判断落地检查：
- 随机模式用无放回红球抽样，蓝球独立抽取；有约束时仅在合法候选空间内抽样。
- 计算候选容量后再去重，注数超过容量时停止，避免无限重试。
- 当前任务仅生成或校验号码；不给冷热预测、保本承诺或下注执行。

## 编号工作流

### 1. 锁定规则与边界

- 确认用户要的玩法名称。
- 读取中国福彩网规则页面并记录查询日期。
- 不能核验时标注采用的常规规则假设。
- 如发现公告变化，先调整生成规则。
- 交付：规则口径与本次注数。

### 2. 核对预算和限制

- 核对所需注数是否超用户上限。
- 费用只有在单价核验后才精确列出。
- 限制号码导致候选不足时明确拒绝生成该配置。
- 不建议借钱、加注或用下一期弥补。
- 交付：本批生成范围和限制条件。

### 3. 随机抽样组合

- 工具可用时用系统随机源抽六个不同红球。
- 蓝球从独立范围抽一个。
- 红球升序排列，统一显示两位数。
- 同批完整组合重复则重新抽样。
- 交付：号码候选表。

### 4. 逐行校验

- 检查每行红球数量恰为六个。
- 检查红球互异且在规则范围。
- 检查蓝球范围和整行组合重复。
- 任何一行失败都修正后重新校验整批。
- 交付：校验通过的最终号码。

### 5. 标明生成性质

- 说明是随机组合，不是中奖预测。
- 用户偏好筛选须标注为受限随机。
- 没有随机工具时可给示例但标“人工示例，非系统随机”。
- 不伪造种子、程序执行或开奖对比结果。
- 交付：一行生成方式说明。

### 6. 完成并收口

- 只输出约定注数，不追加“更稳”的方案。
- 附规则来源和查询状态。
- 下一轮可改注数或禁选范围，但不建议追损。
- 收到预算反馈先调整数量再重新生成。
- 交付：可核对号码表及生成说明。

## 直接交付与下一步

- 红球升序、蓝球独立列出的号码表与校验状态。
- 完成标准：数量符合要求、每注合法、整批没有相同组合。
- 只生成文本，不购票，不声称已下注。
- 工具不可用时标注人工示例，允许用户复制校验脚本自行运行。
- 用户要求保证中奖时停止该承诺，仍可交付合法随机组合。

交付前验收：
- 检查红球六个互异且在 1—33；蓝球一个且在 1—16，输出均为两位数。
- 以排序红球元组与蓝球组成整注键；共享个别红球或蓝球不判重复。
- 校验用户给定注数、禁选、必选和既有整注排除条件。
- 候选红球少于六个、蓝球为空或请求超容量时须先报告不可行。
- 未执行随机程序时输出标人工示例，不能伪称系统随机。

## 外部参考与延展

- 当前规则入口为 [中国福彩网](https://www.cwl.gov.cn/)，历史演示的地方民政部门规则文件只作出处，不冒充当次最新核验。
- 实现依据 [Python random 文档](https://docs.python.org/3/library/random.html)：比较 sample 的无放回抽样与 SystemRandom 的系统随机来源。
- 用户报告重复时，先区分红球重叠与完整注重复；限制导致卡住时先计算候选容量，不能靠增大重试次数掩盖。
- 将核实规则变成范围与数量断言，验证边界号码、注内重复、红蓝同值、超容量；不以历史开奖回测宣称预测收益。

### 可运行生成与边界校验

- 完整标准库实现见 [生成与校验脚本](references/picker.py)。
- 运行方式：`python3 references/picker.py 3`，只生成三注文本。
- 脚本默认常规 6/33 + 1/16 规则，不连接购票服务。
- 必选红球先固定，从剩余允许红球中无放回补足六个。
- 候选容量是可选红球补足组合数乘可用蓝球数。
- 恰好六个红球且只留一个蓝球时只能生成一注。
- 请求超容量：说明需减少注数或放宽限制，不无限重抽。
- 红蓝同值合法；同一注红球重复不合法。
- 无运行环境：给人工合法示例与校验步骤，不编执行记录。
- 实际脚本结果与边界验证见 [选号结果](references/example.md)。
