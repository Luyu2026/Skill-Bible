# 一天行动重整

## 一句话主餐

普通聊天容易给宏大自律清单；这里把用户现有事项收敛为当天可以启动、完成并复盘的一次改变。

## 输入

- 当前最烦心的事项、已有待办或随手记录。
- 当天剩余可支配时段、固定安排与精力状况。
- 必须履行的责任、真实截止时间及可用资源。
- 用户希望当天结束时出现的一个可观察变化。
- 没有完整清单时从用户刚提到的事项开始，不要求先做全面人生盘点。

### 本轮处理门槛

- 今天的日期、当前时刻和收工时间以用户当地时间为准；未知时用相对时间块，注明起点待定。
- 把“必须今天”分成真实硬截止与主观焦虑，真实截止优先于自选成长目标。
- 多个硬截止冲突时列出无法同时完成的部分及需协调的人，不靠压掉全部休息掩盖冲突。
- 一个主目标只约束可选择的时间，不挤占照护、就医和其他刚性责任。
- 日程含求职事项但仅做时间分配时，不推断岗位能力或生成简历事实。
- 执行很困难时先缩小到一次可观察动作；本 Skill 不把低执行力解释成诊断。

## 核心判断

1. 区分当天能改变的行动与需要长期积累的结果，不承诺一天改变人生。
2. 先保住刚性责任，再安排能解除主要阻塞的一件事。
3. 紧急感不等于真实截止；核验外部时限和拖延后果。
4. 低精力时缩小动作而非增加自律要求。
5. 计划必须装进真实日程；保留转换、休息和意外余量。
6. 重大离职、投资或关系决定不作为当天冲动任务，改成收集信息或写决策问题。

## 编号工作流

### 1. 清空并归类

- 直接读取用户的待办，不要求重新填写模板。
- 区分硬截止、生活维护、想改变和暂时不做。
- 把无法控制的外部结果改写成可控制的下一步。
- 输出简短事项表，保留原有承诺与时限。

### 2. 选当天突破点

- 找最影响其他事项推进的阻塞。
- 比较延误成本、今天可推进性和用户真实意愿。
- 选择一个主任务；其他事项只保留必要维护。
- 写明为什么先做它，以及今天停止推进哪些非必要目标。

### 3. 定义可见完成物

- 把“提升自己”变成可提交、可展示或可检查的结果。
- 信息不足时先做草稿、整理文件或发起必要确认。
- 为主任务写清开始动作与结束证据。
- 不把“努力一小时”当作唯一验收标准。

### 4. 装进当天时间

- 从当前时刻排到用户约定的结束时间。
- 绕开已有会议、照护、通勤和吃饭安排。
- 按任务实际复杂度估时，并留出明显余量。
- 若装不下，砍范围或延期，不延长到不现实的深夜。

### 5. 设置失败后的重启

- 列出最可能的一个阻碍及应对动作。
- 准备精力不足时仍有价值的缩小版本。
- 被打断后从最近可恢复的节点继续，不要求清零重来。
- 给出现在即可执行的第一动作，不先安排复杂工具搭建。

### 6. 收工复盘

- 检查完成物而非只问今天心情如何。
- 记录完成、未完成、实际阻碍和明天的一个承接动作。
- 区分范围过大、资源缺失和优先级变化。
- 只调整相关环节，不将一天表现升级为人格评价。

### 各步执行与验收细则

- 第 1 步将事项逐行写为“截止 / 不做后果 / 依赖 / 预计用时”，未知估时标为估计。
- 第 2 步先圈必须履约事项，再选能解除其他任务阻塞的主任务；并列时按用户最想推进的一项取舍。
- 第 3 步写清最低可见完成物与理想完成物，最低版也应能检查或交接，不只是花了时间。
- 第 4 步用可支配总分钟减去固定安排、转换和休息，任务耗时总和不得超过余额。
- 第 5 步写一条“若出现具体阻碍，就做具体替代动作”；触发线索须可观察，不写“有毅力就坚持”。
- 第 6 步按预计与实际耗时比较；任务没完成先定位范围、依赖或优先级变化，再安排下一次动作。

## 直接交付与下一步

- 一个当天主目标及明确完成物。
- 覆盖剩余时间的行动表、必要维护和暂缓清单。
- 一个缩小版本及被打断后的重启动作。
- 当天结束交回完成物与实际阻碍，才据此安排后续。

### 工具不可用时

- 没有日历权限时使用用户已给的固定安排，交付文本时间表，不声称已创建提醒或后台监督。
- 无法完成的关键检查要写明未验证项，不把计划或草稿称为已完成执行。

### 后续输入与收尾

- 本轮交付后立即做第一个动作，不要求先购买软件或建立完整习惯系统。
- 被打断后报告剩余分钟与已完成部分，保留已做内容后重排，不整天清零。
- 收工只需交完成物、实际用时和最大阻碍，下一轮据此决定继续还是换优先级。
- [模拟计划与被打断重排](references/delivery-example.md)提供可直接照着执行的时间块与最低版本。

### 外部参考与延展

- 触发：反复排满仍做不完、时间估算持续失准或启动动作始终无法开始。
- 优先比较用户真实执行记录与原计划，确认是范围还是启动障碍。
- 查实施意图的原始研究和可信时间管理资料，检索 “implementation intentions if then”。
- 重点看情境—行动联结与任务拆分如何减少启动成本，而非复制网红作息。
- 只采用一个可执行改动，避免为重整当天新增复杂系统。
- 把改动接入首个时间块，用完成物与实际耗时检验；不承诺疗效或长期结果。

### 可比较的参考机制

- [实施意图原始研究](https://sparq.stanford.edu/sites/g/files/sbiybj19021/files/media/file/gollwitzer_brandstatter_1997_-_implementation_intentions_effective_goal_pursuit.pdf)：参考可观察情境与行动联结，不照搬实验效果为个人结果保证。
- 与 source-grounded-summary 比较信息压缩：仅保留会改变截止、依赖和完成标准的事实，不能把未定任务排成已确认承诺。
- 若反复未启动，比较“继续细分任务”和“指定明确启动线索”，仅采用能减少本次具体障碍的一项。

### 可执行模拟演示

以下全部为明确模拟输入，不代表任何真实用户的经历或结果。

- 模拟输入：现在14:00，16:00开会，18:00结束；提案未写、桌面乱、想学英语。
- 真实约束：会议16:00—17:00；本例假定14:00—16:00可自由使用。
- 主目标：完成可供讨论的一页提案草稿，而非一次解决全部目标。
- 14:00—14:10：打开原材料，写出提案要回答的三个问题。
- 14:10—15:00：写问题、建议与依据；15:00—15:15休息。
- 15:15—15:45：补缺口标记并自检；15:45—16:00准备会议。
- 17:00—17:30：按会议结果修订；其余时间留作收尾与缓冲，英语暂缓。
- 缩小版：若临时被占用，只交问题、建议、待确认三段草稿，收工核对是否可讨论。

### 交付前检查

- 用 references/delivery-example.md 的输入走完当前模式，对照关键判断逐项核验。
- 将本轮最终成品与输入事实逐项对照；无依据的新增事实必须删除或标为未知。
- 先检查处理门槛和失败分支，再检查行文与格式；不能用篇幅达标代替可用性。
- 新反馈触发通用修正时保留原案例，比较旧版与新版，再同步 README 和必要示例。
