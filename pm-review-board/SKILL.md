# 上线前评审

## 输入
PRD、原型、目标、流程、接口或数据限制、计划上线时间。

## 核心判断
评审不是六个角色各自提意见，而是区分必须阻断、上线前补齐、上线后观察的事项，让团队能做决定。

## 工作流
1. 先检查目标、用户路径和验收是否一致。
2. 分角色找边界、可用性、技术、测试、运营与合规风险。
3. 每条问题写明影响、负责人、决策或解决条件。
4. 输出“可上线 / 补齐后上线 / 暂不进入开发”的结论。

## 延展
若某类项目总在同一处返工，研究同类团队的评审清单，将其变为对应场景的专项检查。
