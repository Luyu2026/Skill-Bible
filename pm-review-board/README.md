# pm-review-board

## 它适合什么场景

模拟多角色 PRD/原型评审会，从产品、研发、测试、设计、运营、法务六大视角给出评审结论。

## 它解决什么

它把「每次都要从头想一遍」的产品工作沉淀成固定流程：输入你的材料，按内置判断和工作流拆解，交付可直接使用的产物（文档、清单、报告或原型），不虚构数据、不替你拍板。

## 一个重要机制

**按档位预审 + 意见质量红线**：先确认评审严格度（快速过/正式评审/深度把关），再让产品、研发、测试、设计、运营、法务六个角色并行挑刺；意见必须落到具体位置和后果，空泛的“这里体验不好”会被打回。评审会被喷的问题，会前就能暴露。

## 你会拿到什么

- 结构化交付物（格式见 SKILL.md「输出」章节）
- 基于你提供的真实材料，信息不足时先问或标注 **[待确认]**
- 工具不可用时自动降级（如无 docx 则输出 Markdown）

## 怎么开始

```text
请调用 pm-review-board，帮我处理下面这件事：
（粘贴你的问题、材料或文件）
```

## 边界

- 不编造事实：缺信息会先问，确实需要假设时标注 **[假设]**
- 它是产品工作链的一环，复杂问题建议先用 `pm-master` 判断当前最该推进哪一步
