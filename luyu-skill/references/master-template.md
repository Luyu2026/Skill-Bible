# 总控 Skill 模板（career-master）

构建 `[职业]-master`（总控）时使用。总控是整套职业 Skill 链的入口：负责分诊、路由、编排链路。

## 核心能力

1. **分诊**：判断用户问题是判断类（该不该做/怎么选/值不值）还是产出类（写文档/出方案/做分析）
2. **路由**：根据问题类型路由到执行链 Skill 或顾问团
3. **编排链路**：任务横跨多步时，编排执行链顺序，保证上一步产出是下一步合法输入

## 标准结构

```markdown
---
name: [职业]-master
description: |
  [职业]工作总控。用于用户不知道先做哪一步时：分诊问题 → 路由到最合适的 Skill →
  编排多 Skill 链路。
  触发词：「[职业] master」「[职业] 总控」「我该用哪个 skill」「帮我推进这件事」。
---

# [职业] 工作总控

## 成员名册

### 执行链（产出型）

| Skill | 一句话职责 | 典型输入 → 输出 |
|-------|-----------|----------------|
| `career-xxx` | ... | ... |
| ... | ... | ... |

### 顾问团（判断型）

判断类问题一律转交 `[职业]-advisory-board`（顾问团子总控），由它路由到专家/方法论，
或召开多专家评审会。总控不重复它的路由表。

## 第一步：问题分诊

收到请求后，先分诊到三类之一：
1. **判断类**（该不该做、怎么选、值不值、方向对不对）→ 转顾问团
2. **产出类**（写文档、出方案、做分析）→ 按路由表选 1 个执行 Skill
3. **链路类**（任务横跨多步）→ 按预置链路编排

分不清时用这个测试：**用户要的是"一个结论/视角"还是"一份可交付物"？** 前者判断类，后者产出类。

## 第二步：单点路由表

| 用户在说什么 | 路由到 | 备注 |
|---|---|---|
| ... | `career-xxx` | ... |
| ... | ... | ... |

路由后：说明选择理由（一句话），确认后加载对应 Skill 执行。用户明显着急或指令明确时直接执行。

## 第三步：预置工作流链路

用户任务横跨多步时，推荐链路并列出每步的交接物。**每一步的产出必须是下一步的合法输入**。

## 第四步：顾问团评审

用户要"让专家们看看""开评审会"时 → 转 `[职业]-advisory-board`：
并行调用 3 位专家 → 输出共识/分歧/综合结论（条件化，不替用户拍板）。

## 诚实边界

- 不编造用户未提供的材料
- 顾问团覆盖不到的领域（无真实数据、超出专家知识范围）明确说明
```

## 构建要点

- 路由表必须覆盖 Phase 1 调研出的高频决策场景（这是体系化的核心）
- 分歧地图非空：3 个专家观点高度一致 = 遴选失败信号
- 执行链命名统一 `career-*` 或 `[职业前缀]-*`，与 pm-* 风格一致
