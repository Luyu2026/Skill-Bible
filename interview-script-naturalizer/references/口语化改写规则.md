# 口语化改写规则

## 一条回答只保留一条主线

不要同时讲“用户洞察、策略设计、内容运营、协同推进、数据复盘”。先确定这题真正回答什么，再只保留能证明它的关键动作。

推荐顺序：

```text
结论 → 当时看到的问题 → 关键判断 → 2-3 个动作 → 结果与口径 → 复盘
```

## 把抽象词翻译成具体动作

| 不要停在这里 | 要继续说清 |
| --- | --- |
| 提升用户体验 | 哪个用户在什么环节卡住，具体改了什么 |
| 做用户调研 | 问了谁、问了什么、得到什么判断 |
| 推动协同 | 找了哪些角色、如何对齐、发生了什么取舍 |
| 数据驱动 | 看了哪个指标、周期多长、据此改了什么 |
| 形成闭环 | 从发现问题到复盘，中间哪一步真的改变了 |

## 可以保留的自然连接

- 我当时先确认的是……
- 后来我发现，真正卡住的不是……而是……
- 所以我没有先做……，而是先……
- 这个动作之后，我主要看……来判断有没有效果。
- 最后结果是……，这个数字的口径是……
- 如果重做一次，我会更早……

## 改写禁区

- 不把团队成果全写成“我做到”；
- 不补不存在的用户、预算、增长、转化或团队规模；
- 不为了口语化加入夸张、网络梗或无关故事；
- 不把答案改得更长。主回答宁可少讲一个动作，也不要让面试官找不到重点；
- 不掩盖不确定性。数据没核对，就在练习前列为待确认。
