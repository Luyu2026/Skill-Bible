Skill-Bible 不是提示词堆，也不是把所有东西装进一个仓库。每个 Skill 都应解决一个反复出现、值得被标准化的真实问题：把判断、材料要求、工作流程、交付格式和边界收好，让 Agent 下次可以稳定推进。

这里同时收录两种能力：**单点 Skill** 解决一个明确任务；**职业 Skill 链** 处理一整段工作流。你不需要安装整个仓库，也不需要先理解全部 94 个 Skill。

---

## 从这里开始

先描述你现在卡住的事。下面这些是每个方向的推荐入口：

| 你现在在做什么 | 先用哪个入口 | 它会把你带到哪里 |
|---|---|---|
| 求职时不知道先投什么、改什么、怎么备面 | [job-search-pilot](./job-search-pilot/) | 当前问题判断 → 简历 / 备面 / 复盘 / Offer 的下一步 |
| 需求说不清、项目不知道怎么推进 | [pm-master](./pm-master/) | 判断 → PRD / 评审 / 排序 / 排期 / 数据 / 复盘 |
| 运营目标、数据、活动、内容混在一起 | [operations-master](./general-operations-skills/operations-master/) | 策略 → 数据 / 内容 / 活动 / 用户 / 复盘 |
| 想提升留存、召回、会员或社群 | [user-operations-master](./user-operations-skills/user-operations-master/) | 分层 → 生命周期 / 留存 / 召回 / 会员 / 社群 |
| 要做海外市场、内容 SEO、投放或邮件 | [overseas-marketing-master](./overseas-marketing-skills/overseas-marketing-master/) | 调研 → 定位 / 内容 SEO / 投放 / 邮件 / 分析 |
| 有一个内容想法，但不知道怎么展开或补图 | [daily-idea-expander](./daily-idea-expander/) / [wechat-visual-narrative](./wechat-visual-narrative/) | 口播文案 / 已定稿文章的视觉叙事 |
| 想用一个人物视角重新审视决策 | [思维视角](#思维视角) | 13 个有明确边界的人物框架 |

**只有一个明确任务时，直接使用专项 Skill。** 只有当你不知道下一步、或任务天然跨多个环节时，才从 `*-master` 开始。

## 职业 Skill 链

职业套件不是把一堆文件绑在一起，而是同一工作流中的能力有明确分工、交接物和总入口。先装总控，再按需要装子 Skill 即可。

| 套件 | 适合谁 | 总入口 | 完整目录 |
|---|---|---|---|
| 📦 产品经理 · 21 个 Skill | 需求、调研、原型、实验、数据与复盘 | [pm-master](./pm-master/) | [产品工作链](./pm-master/README.md) |
| 📣 通用运营 · 14 个 Skill | 策略、活动、内容、运营数据与复盘 | [operations-master](./general-operations-skills/operations-master/) | [通用运营套件](./general-operations-skills/README.md) |
| 👥 用户运营 · 14 个 Skill | 分层、生命周期、留存、召回、会员与社群 | [user-operations-master](./user-operations-skills/user-operations-master/) | [用户运营套件](./user-operations-skills/README.md) |
| 🌍 海外市场营销 · 14 个 Skill | 市场调研、定位、SEO、投放、邮件与分析 | [overseas-marketing-master](./overseas-marketing-skills/overseas-marketing-master/) | [海外营销套件](./overseas-marketing-skills/README.md) |

每个套件内都区分三层：

- **总控**：判断当前问题属于哪一类，并安排必要的工作链。
- **执行 Skill**：产出可直接使用的方案、报告、文档或分析。
- **顾问团 / 方法论**：处理“该不该做、怎么取舍”的判断，不替用户拍板。

## 安装一个 Skill

打开你需要的 Skill 页面，复制网址，然后把下面这段话发给你的 Agent：

```text
请帮我安装这个 Skill：
[把 Skill 页面的网址粘贴在这里]

我只想安装这一个 Skill，不需要下载整个仓库。
请判断我当前使用的 Agent、正确的 Skill 安装目录和下载方式，并直接完成安装。
安装完成后告诉我：它装在了哪里，以及我下一句话该怎么调用它。
```

如果文档型 Skill 需要飞书但你没有配置飞书 CLI，它应优先交付本地 Markdown，而不是因为权限卡住。

## 收录与来源

Skill-Bible 重视真实可用性，也保留来源边界：

- 原创或重新设计的 Skill，按本仓库规范维护输入、工作流、交付、边界与验证。
- 保留外部机制或原始内容的 Skill，会在对应目录的 `SOURCES.md` 标明来源、作者、协议和本仓库实际做过的变化。
- “被收录”不等于“适合所有人”；没有必要的能力不应为了凑数量被安装或调用。

你可以提交原创 Skill，也可以推荐值得研究的项目：[提交 / 推荐一个 Skill](https://github.com/Luyu2026/Skill-Bible/issues/new?template=submit-skill.yml)。Skill 使用分享可在抖音、小红书或公众号搜索“陆羽”查看。
