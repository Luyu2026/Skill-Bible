# pm-roadmap-planner

## 它适合什么场景

版本规划与路线图设计 Skill。从季度目标、团队产能、依赖方信息出发，输出可执行的版本路线图（里程碑、依赖风险、缓冲策略、每阶段成功指标）。 触发条件：用户提到"路线图"、"版本规划"、"roadmap"、"里程碑"、"季度计划"、"迭代规划"、"版本排期"、"项目排期"、"依赖梳理"、"风险预案"、"缓冲方案"、"迭代计划"、"sprint规划"、"release plan"、"OKR拆解"等关键词。

## 它解决什么

它把「每次都要从头想一遍」的产品工作沉淀成固定流程：输入你的材料，按内置判断和工作流拆解，交付可直接使用的产物（文档、清单、报告或原型），不虚构数据、不替你拍板。

## 一个重要机制

**目标反推里程碑**：从季度目标、团队产能、依赖方出发反推版本节奏，明确里程碑、依赖风险、缓冲策略和每阶段成功指标。

## 你会拿到什么

- 结构化交付物（格式见 SKILL.md「输出」章节）
- 基于你提供的真实材料，信息不足时先问或标注 **[待确认]**
- 工具不可用时自动降级（如无 docx 则输出 Markdown）

## 怎么开始

```text
请调用 pm-roadmap-planner，帮我处理下面这件事：
（粘贴你的问题、材料或文件）
```

## 边界

- 不编造事实：缺信息会先问，确实需要假设时标注 **[假设]**
- 它是产品工作链的一环，复杂问题建议先用 `pm-master` 判断当前最该推进哪一步
