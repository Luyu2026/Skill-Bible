# 朋友圈场景文案

## 一句话主餐

把用户眼前的一张照片或一件小事，写成三条风格清楚、事实一致、可以直接发布的朋友圈文案。

直接让聊天工具“写得好看”，常会补出心情、天气或行程。本技能把照片可见内容与本人确认事实分开，再围绕同一个细节写出真正不同的三版。

## 输入

- 照片或照片内容描述；识别不到的细节先确认
- 事情的时间、地点、人物关系和用户愿意公开的事实
- 本次目的：记录生活、表达心情、分享活动或邀请参与
- 希望谁看到、哪些信息不能出现、平时说话的例子

### 材料处理规则

- 优先读取已经给出的材料，不要求用户再次填写相同信息。
- 只问会改变当前处理路径的缺口；其他缺口说明边界后继续。
- 用户事实、推断和模拟必须分开标记。
- 不把缺少的经历、数据或条件补写成真实事实。
- 只使用当前任务必要的信息，公开示例使用明确模拟材料。

## 核心判断

1. 先区分生活记录和商业邀请；生活记录不能擅加购买引导。
2. 照片中可见的物体不等于用户的经历；不能由海边照片推断旅行地点。
3. 三种风格应在叙述视角和节奏上不同，不能只替换形容词。
4. 所谓爆款只能作为吸引力目标，不能承诺点赞量或制造虚假稀缺。

### 本轮执行门槛

- 至少有一项可写事实：照片中的物件、用户确认的动作或活动信息。只有“帮我写爆款”时先问写哪件事。
- 若只给照片，写可见物件与画面关系；不把杯中饮品、温度、拍摄地点或拍摄者身份当成已知。
- 活动邀请缺时间、地点或参加方式时，先交付不含报名承诺的预告，并指出缺哪一项才能成为完整邀请。
- 用户只要一条时只交付推荐版；默认三版不是强制凑数量。

## 编号工作流

### 1. 整理事实底稿

- 逐项记录用户确认的事情、图片可见细节和不可确认信息。
- 仅将确认事实写进文案；图片判断保留来源。
- 遇到地点不明，使用“今天这段路”等不依赖地点的表达。
- 在内部整理小事实卡；仅将会影响发布的未知项单列给用户，不在可发正文前强塞问卷。

### 2. 确定发布意图

- 从分享、表达、邀请中选当前主要目的。
- 根据受众判断亲密程度和能否使用玩笑。
- 商业内容缺价格或活动时间时，只写已确认部分。
- 输出一句本次文案目标。

### 3. 选取一个细节

- 优先用照片中具体可见的动作、物件或场景开场。
- 把抽象的“美好”改成可感知的细节。
- 不同时塞入旅游攻略、人生感悟和产品促销。
- 输出一个所有版本共用的事实锚点。

### 4. 写三种完整版本

- 分别写自然记录、轻松幽默、克制感性三个版本。
- 每版默认一至三句，长度服从用户偏好。
- 幽默围绕自己或场景，不拿未同意的人开玩笑。
- 直接给完整可发正文，不让用户拼接句子。

### 5. 检查发布边界

- 核对每个数字、地点、人物和活动承诺。
- 删除不必要的定位、车牌、姓名和第三方隐私。
- 明确邀请内容的参加方式；未知时不自造报名链接。
- 输出需要用户确认的唯一关键缺口或说明无需补充。

### 6. 推荐一版

- 根据用户目的推荐最适合的一条。
- 理由落在受众、语气和信息量，不使用空泛评分。
- 用户有字数限制或要求再短时，收短推荐版；不默认在三版外另堆同义稿。
- 交付推荐正文及一句选择理由。

### 7. 接住真实反馈

- 用户说太文艺时改词汇和句长，不只删表情。
- 用户回传发布反馈时区分熟人互动与内容效果。
- 只调整本次表现最弱的维度。
- 下一轮索取喜欢的句子和不愿说的词。

### 文案落笔规格

- 事实卡只保留“确认事实／画面可见／未知”三类；未知不进入可发正文。
- 生活记录默认不加话题标签、购买入口或定位；用户要求时再加入。
- 默认每版一至三句；若用户给字数上限，先保住事件主体，再删除修饰。
- 幽默版允许夸张叙述方式，不允许捏造经历，例如“认真休息”可用，“睡了十二小时”需确认。
- 邀请文案按“发生什么—何时何地—如何参加”核查；价格、名额、效果没有来源就不补。
- 三版后只用一句话推荐；事实确认问题放在正文之外，避免用户误复制。

## 直接交付与下一步

- 三条可直接发的文案，清晰标明风格
- 一条推荐及理由；必要事实缺口单列
- 用户回传喜欢哪版和哪个词不像自己，即可继续精修

### 完成条件

- 三版事实一致；自然版用直述，幽默版改变观察角度，感性版改变停顿与留白。不能只换三个形容词。
- 推荐版可以直接复制，没有待填空位、未经确认的体验或夸张效果承诺。
- 发布是用户的下一步；本技能生成正文，不默认代发。
- 收到“太文艺”反馈，删除隐喻和结尾升华；收到“太冷淡”，只增加用户已表达的情绪。

### 工具降级

- 读不了照片时请用户描述主体和一处细节；先用描述完成正文，不声称已看图。
- 缺个人口吻样本时采用少修饰、短句的中性语气；不强行添加流行梗。
- 不能检索时仍可根据事实卡出稿；互动效果只能回看实际反馈，不能编造点赞预测。

### 交付前检查

- 逐项对照输入、输出与待确认项，检查是否越过本技能的事实和模式边界。
- 用 [复审与运行案例](references/review-validation.md) 中的主案例和失败回归重跑，保留可使用的成品。
- 提示、附件或对外发布等未执行动作必须如实标注；文件行数不能代替案例验收。

## 外部参考与延展

- 三版只是同义改写时，先比较本仓库 moments-natural-rewrite 的最少改动机制与本技能的视角变化；生成任务用后者，保留原稿任务用前者。
- 写法过度抽象时查看 [CPSC 平实语言原则](https://www.cpsc.gov/About-CPSC/Policies-Statements-and-Directives/plain-language-principles)，观察受众、动词和无效词删减；不把英文句长限制直接套给中文。
- 进一步检索可用“中文 微文案 叙事视角 品牌语气指南”；优先资料原作者的完整范例，观察同一事实如何改变节奏。
- 只采用能使三版视角不同且不新增事实的机制；用同一照片重写并逐项核对物件、感受和承诺。
- 保留事实卡与修改前后正文；效果无改善就回退，不把点赞量当成采用依据。
