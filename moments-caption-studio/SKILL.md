# 朋友圈场景文案

## 一句话主餐

把用户眼前的一张照片或一件小事，写成三条风格清楚、事实一致、可以直接发布的朋友圈文案。

普通聊天容易直接给出貌似完整的答案；本技能先保留用户已有证据，解决当前最卡的一步，再收成可使用的结果。

## 输入

- 照片或照片内容描述；识别不到的细节先确认
- 事情的时间、地点、人物关系和用户愿意公开的事实
- 本次目的：记录生活、表达心情、分享活动或邀请参与
- 希望谁看到、哪些信息不能出现、平时说话的例子

### 材料处理规则

- 优先读取已经给出的材料，不要求用户再次填写相同信息。
- 只问会改变当前处理路径的缺口；其他缺口说明边界后继续。
- 用户事实、推断和模拟必须分开标记。
- 不把缺少的经历、数据或条件补写成真实事实。
- 只使用当前任务必要的信息，公开示例使用明确模拟材料。

## 核心判断

1. 先区分生活记录和商业邀请；生活记录不能擅加购买引导。
2. 照片中可见的物体不等于用户的经历；不能由海边照片推断旅行地点。
3. 三种风格应在叙述视角和节奏上不同，不能只替换形容词。
4. 所谓爆款只能作为吸引力目标，不能承诺点赞量或制造虚假稀缺。

### 本轮执行门槛

- 能读清核心材料：进入工作流。
- 只有非核心细节缺失：按材料允许的范围交付。
- 关键事实存在冲突：指出冲突，并优先完成不受影响的部分。
- 用户明确要求短答案时压缩解释，但保留影响结论的条件。

## 编号工作流

### 1. 整理事实底稿

- 逐项记录用户确认的事情、图片可见细节和不可确认信息。
- 仅将确认事实写进文案；图片判断保留来源。
- 遇到地点不明，使用“今天这段路”等不依赖地点的表达。
- 输出一张小事实卡，不要求用户重新填长问卷。

### 2. 确定发布意图

- 从分享、表达、邀请中选当前主要目的。
- 根据受众判断亲密程度和能否使用玩笑。
- 商业内容缺价格或活动时间时，只写已确认部分。
- 输出一句本次文案目标。

### 3. 选取一个细节

- 优先用照片中具体可见的动作、物件或场景开场。
- 把抽象的“美好”改成可感知的细节。
- 不同时塞入旅游攻略、人生感悟和产品促销。
- 输出一个所有版本共用的事实锚点。

### 4. 写三种完整版本

- 分别写自然记录、轻松幽默、克制感性三个版本。
- 每版默认一至三句，长度服从用户偏好。
- 幽默围绕自己或场景，不拿未同意的人开玩笑。
- 直接给完整可发正文，不让用户拼接句子。

### 5. 检查发布边界

- 核对每个数字、地点、人物和活动承诺。
- 删除不必要的定位、车牌、姓名和第三方隐私。
- 明确邀请内容的参加方式；未知时不自造报名链接。
- 输出需要用户确认的唯一关键缺口或说明无需补充。

### 6. 推荐一版

- 根据用户目的推荐最适合的一条。
- 理由落在受众、语气和信息量，不使用空泛评分。
- 必要时附一个更短版本，避免继续无限出稿。
- 交付推荐正文及一句选择理由。

### 7. 接住真实反馈

- 用户说太文艺时改词汇和句长，不只删表情。
- 用户回传发布反馈时区分熟人互动与内容效果。
- 只调整本次表现最弱的维度。
- 下一轮索取喜欢的句子和不愿说的词。

## 直接交付与下一步

- 三条可直接发的文案，清晰标明风格
- 一条推荐及理由；必要事实缺口单列
- 用户回传喜欢哪版和哪个词不像自己，即可继续精修

### 完成条件

- 用户能直接复制结果或照着下一动作执行。
- 影响准确性的条件已说明，未确认内容没有混入确定结论。
- 本轮只推进当前问题，不默认增加其他任务。
- 后续若有新材料，指出改变了哪个判断，再更新受影响部分。

### 工具降级

- 图片或文件无法读取时，请用户补核心文字；先处理可读内容。
- 无法生成附件时，提供完整可复制正文和必要操作步骤。
- 未执行的导出、发布和外部核验必须如实说明。
- 不以工具缺失为由改造用户事实。

### 交付前检查

- 与原始输入逐项核对关键事实、条件或数值。
- 检查推荐理由能否对应用户本轮目的。
- 删除没有推动当前任务的通用作业。
- 用一个明确模拟输入走完流程，检查产物是否可直接使用。
- 演示见同目录 DEMO.md；演示中的结果不能当成用户事实。

### 外部参考与延展

- **何时研究**：三版风格雷同、图片缺少可写细节，或用户反馈像广告时启动。
- **去哪找**：检索中文微文案、叙事视角、品牌语气指南；可对照用户授权的历史朋友圈。
- **看什么**：比较开场细节、句长、幽默对象和邀请方式，不搬运别人的故事。
- **怎么用与验证**：把一个有用机制接入选细节或三版生成，用同一照片检查差异与事实一致性。
- 现有材料足够时直接交付，不每次重做检索。
- 至少比较两种可行做法的输入要求和适用条件，再决定是否采用。
- 记录采用机制解决了哪个缺口；没有实际改善则保持原方案。
- 外部材料只辅助判断，不能替代用户自己的事实与确认。
