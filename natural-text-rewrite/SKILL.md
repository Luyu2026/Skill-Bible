# 自然文本改写与对照

## 一句话主餐

从原文和真实说话习惯出发改出可直接使用的文本，并解释关键改动，解决泛泛要求“去 AI 味”却越改越空的问题。

## 输入

- 完整原文及不能改动的数字、引文、术语和立场
- 读者、用途、发布位置与希望对方采取的动作
- 可选：本人写过且满意的一小段文字
- 可选：字数、正式程度和必须保留的措辞
- 无个人样本时用清楚直接的中性语气，不冒充本人习惯

材料优先级：用户现有原稿与记录优先；补充信息只追问会改变本轮判断的部分。
真实材料、合理推断与明确模拟内容分别标记。
不能读取附件时，请用户粘贴关键片段；先完成不依赖附件的部分。

## 核心判断

1. 自然度问题与事实问题分开处理，不能靠虚构细节增加人味
2. 根据用途选择书面、口语或正式表达，不能一律改得随意
3. 识别空泛主语、无依据程度词、重复结论和过度整齐的排比
4. 保留必要的专业精度，不把技术词全删掉
5. 不输出 AI 生成概率，也不保证绕过检测器
6. 敏感语义、承诺和因果关系的变化要单列给用户确认

## 编号工作流

### 1. 圈定原文意图

- 复述作者要说什么、读者需要知道什么
- 抽取必须保留的事实与限制条件
- 原文有歧义时列出歧义所在句
- 能继续的部分先改，关键歧义保留待确认

### 2. 诊断机械感来源

- 只标注影响阅读的句子，避免对每句挑刺
- 把问题分为信息重复、空话、语气失配、逻辑跳步
- 每类给一个来自原文的具体位置
- 不把固定连接词出现一次就判为问题

### 3. 建立改写尺度

- 根据场景选择轻改或结构改写
- 轻改保留段落顺序，适合已审定稿
- 结构改写可移动信息，保留原始事实关系
- 用户没指定时优先保守修改并说明尺度

### 4. 交付完整可用稿

- 先输出连续全文，让用户可复制
- 用具体动作替换无信息动词
- 无法确定的对象保留原指代或标记待确认
- 不凭空添加经历、评价、时间和数据

### 5. 制作重点对照

- 列原句、改句、修改原因和语义风险
- 只收录会改变阅读体验的关键改动
- 事实纠错与文风变化分列
- 引文若需改动，改成转述并保留来源

### 6. 复读与续接

- 逐项比对数字、否定词、程度和承诺
- 按目标场景朗读或检查段落阅读顺序
- 用户反馈“太随意”时只调正式程度
- 用户交回不喜欢的句子和原因，形成可复用偏好

## 直接交付与下一步

- 可直接复制的完整改写稿
- 重点句子的原文改文对照
- 待确认事实或语义变化清单，无问题则明确写无
- 一项可调的语气方向及复交方式

### 完成条件

- 交付物逐项回到输入来源，关键判断有依据或明确的未知边界。
- 用户能直接使用本轮成品，而不是再把方法说明自行转成成品。
- 待确认项只阻塞相关结论，不阻塞已可完成的部分。
- 本轮结束时指出一个最值得交回的材料和它会改变的判断。

### 工具与数据降级

- 工具不可用时说明已执行到哪一步，交付可编辑文本或底表。
- 依赖外部事实的部分没有核验就保留待确认，不写成已经完成。
- 文件交付失败时直接提供可复制正文，并保留建议文件名。

### 外部参考与延展

- 何时研究：用户连续反馈不自然、行业术语不能删或目标文体陌生时启动。
- 去哪找：查用户认可的真实写作样本、机构文体指南；检索“plain language audience active voice”。
- 看什么：观察信息排序、动词选择、句长变化和正式程度，不收集所谓检测器漏洞。
- 怎么用：取一段原稿做两种改法，按事实保留与读者理解选更合适者。
- 采用前比较至少两个可行机制或与当前方法对照，说明材料成本及适用边界。
- 用触发问题的同一输入验证改动，保留有效方法，丢弃不能改善交付的装饰功能。
- 外部资料帮助调整方法，不能替代用户事实；实际复用受许可约束的内容时保留必要声明。

### 交付前逐项复核

1. 对照原始材料，检查是否改变数字、条件、角色或时间。
2. 检查推荐路径是否符合用户现有工具和材料条件。
3. 把仍需核验的结论与已经完成的内容分开。
4. 用下方模拟案例执行主流程，核对输出是否能落地。
5. 遇到模拟案例未覆盖的真实限制，缩小承诺后再交付。
6. 对后续反馈只改影响本轮目标的判断，避免无关扩展。
7. 输出文件与对话结论保持一致，不把计划称为执行结果。

### 明确模拟的执行示范

- 模拟原文：“在当今快速发展的时代，我们致力于通过多元化赋能全面提升沟通效率。”
- 模拟补充：实际动作是将每周三次进度会改为一次；没有效率测量。
- 改写：“我们把每周三次进度会合并为一次，让大家集中同步本周进展。”
- 对照：删掉时代背景和赋能，换成已提供的会议调整。
- 核验：没有写节省多少时间，也没有把减少会议次数说成效率已提升。
- 下一步：用户确认会议调整已实施；未实施则改为“计划把”。
