# 自然文本改写与对照

## 一句话主餐

从原文和真实说话习惯出发改出可直接使用的文本，并解释关键改动，解决泛泛要求“去 AI 味”却越改越空的问题。

## 输入

- 完整原文及不能改动的数字、引文、术语和立场
- 读者、用途、发布位置与希望对方采取的动作
- 可选：本人写过且满意的一小段文字
- 可选：字数、正式程度和必须保留的措辞
- 无个人样本时用清楚直接的中性语气，不冒充本人习惯

材料优先级：用户现有原稿与记录优先；补充信息只追问会改变本轮判断的部分。
真实材料、合理推断与明确模拟内容分别标记。
不能读取附件时，请用户粘贴关键片段；先完成不依赖附件的部分。

## 核心判断

1. 自然度问题与事实问题分开处理，不能靠虚构细节增加人味
2. 根据用途选择书面、口语或正式表达，不能一律改得随意
3. 识别空泛主语、无依据程度词、重复结论和过度整齐的排比
4. 保留必要的专业精度，不把技术词全删掉
5. 不输出 AI 生成概率，也不保证绕过检测器
6. 敏感语义、承诺和因果关系的变化要单列给用户确认

## 编号工作流

### 1. 圈定原文意图

- 复述作者要说什么、读者需要知道什么
- 抽取必须保留的事实与限制条件
- 原文有歧义时列出歧义所在句
- 能继续的部分先改，关键歧义保留待确认

### 2. 诊断机械感来源

- 只标注影响阅读的句子，避免对每句挑刺
- 把问题分为信息重复、空话、语气失配、逻辑跳步
- 每类给一个来自原文的具体位置
- 不把固定连接词出现一次就判为问题

### 3. 建立改写尺度

- 已审定稿、合同承诺和对外公告先轻改；信息重复或读者找不到动作时才重排，并列出移动的句子
- 轻改保留段落顺序，适合已审定稿
- 结构改写可移动信息，保留原始事实关系
- 用户没指定时优先保守修改并说明尺度

### 4. 交付完整可用稿

- 先输出连续全文，让用户可复制
- 用具体动作替换无信息动词
- 无法确定的对象保留原指代或标记待确认
- 不凭空添加经历、评价、时间和数据

### 5. 制作重点对照

- 列原句、改句、修改原因和语义风险
- 只收录会改变阅读体验的关键改动
- 事实纠错与文风变化分列
- 引文若需改动，改成转述并保留来源

### 6. 复读与续接

- 逐项比对数字、否定词、程度、时间状态和承诺；“计划”不能变成“已完成”，“可能”不能变成“必然”
- 按目标场景朗读或检查段落阅读顺序
- 用户反馈“太随意”时只调正式程度
- 用户交回不喜欢的句子和原因，形成可复用偏好

## 直接交付与下一步

- 可直接复制的完整改写稿
- 重点句子的原文改文对照
- 待确认事实或语义变化清单，无问题则明确写无
- 一项可调的语气方向及复交方式

### 完成条件：改写是否守住语义与用途

- 逐项勾对事实锁定表；没有作者样本时声明采用中性语气，不宣称还原个人风格。
- 必须实际执行一次，成品格式与验证边界见 [完整案例](references/review-example.md)。
- 交付前依据案例中的反例检查，不能只检查标题和行数。
- 用户交回材料后，先复查改变的输入，再沿原路径更新，不无故重做全部内容。

### 工具与数据降级

- 没有文档编辑工具时直接交连续全文和重点对照；只有局部原稿时只改该段，不能声称全文逻辑已核验。
- 文件生成失败就交付可复制正文，说明未生成文件；不把文本方案说成成片、图表或附件。

### 外部参考与延展

- 何时研究：用户连续反馈不自然、行业术语不能删或目标文体陌生时启动。
- 去哪找：查用户认可的真实写作样本、机构文体指南；检索“plain language audience active voice”。
- 看什么：观察信息排序、动词选择、句长变化和正式程度，不收集所谓检测器漏洞。
- 怎么用：取一段原稿做两种改法，按事实保留与读者理解选更合适者。
- 采用前比较至少两个可行机制或与当前方法对照，说明材料成本及适用边界。
- 用触发问题的同一输入验证改动，保留有效方法，丢弃不能改善交付的装饰功能。
- 外部资料帮助调整方法，不能替代用户事实；实际复用受许可约束的内容时保留必要声明。

### 本轮执行门槛

- 第一关：改写是否守住语义与用途；不满足时收窄输出到有依据的部分。
- 第二关：按原输入复算或逐句比对，记录具体通过项，不以“已检查”代替证据。
- 第三关：输出一个可以直接使用的成品，并明确本轮待补材料。
- 采用按读者需求排序信息的机制，与原段序轻改比较；不采用无依据的口语填充词。
- 方法入口：[GSA 清晰语言指南：读者](https://github.com/GSA/plainlanguage.gov/blob/main/_pages/guidelines/audience/index.md)。
- 来源用于改进方法，不提供用户事实；没有读取具体资料时不写“已研究验证”。
- 持续反馈若暴露同类缺陷，保留触发输入与旧输出，在授权目录中修改候选版，再用原例和受影响场景复验。
- 本轮只推进当前卡点；下一步验收以用户补交的材料为准，不承诺后台自动跟进。
