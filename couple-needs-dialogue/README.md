# 伴侣需求沟通

## 它适合什么场景

根据伴侣对话、具体事件与希望达成的改变，把长期抱怨改成可回应的需求和双方可试行的约定；适用于“我们总说不到一起”“想用爱的语言沟通”“想表达需要但不想指责”的场景。

从一份已经有的材料开始即可，不需要先学一套方法。

## 它解决什么

普通聊天容易替一方评理；这里从一次真实互动提取未被表达的需求，写出能开口的对话和一个可观察的共同约定。

它会先处理你当前卡住的一件事，再给能直接使用的结果。

## 一个重要机制

区分长期需求协商和正在升级的争吵；正在失控时先暂停，延后深入协商。

区分观察、解释、感受和请求；“你不在乎我”属于解释，不能当事实。

这个区分会影响先做什么，以及最后交付哪一种结果。

## 你会拿到什么

- 一段可直接开口的需求表达。
- 三类回应下的承接句与一个可协商动作。
- 已同意的试行约定，或尚未形成共识的具体分歧。
- 完成标准是用户能提出清楚请求，并知道如何接住真实反馈。

## 怎么开始

1. 发来你已有的原文、记录或草稿。
2. 说明现在希望解决的卡点和本轮目标。
3. 写出会影响处理的时间、渠道或方法限制。
4. 收到结果后直接使用；有新反馈时带回原话或实际产物。

不必补齐所有背景；会先使用已有材料，只有关键缺口才追问。

## 可直接复制的调用模板

```text
请使用 couple-needs-dialogue 帮我完成这次任务。
我已有的材料：
（在这里粘贴原文、草稿或提供可访问文件）

我现在最卡的是：
（描述具体问题）

本轮希望拿到：
（说明成品形式和长度）

需要遵守的限制：
（时间、渠道、边界或可用方法）

请先使用现有材料，区分事实与待确认信息，给可直接用的结果和下一步。
```
