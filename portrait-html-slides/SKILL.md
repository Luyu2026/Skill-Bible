# 讲稿转极简竖屏 HTML 演示

## 一句话主餐

普通聊天只列大纲；这里将讲稿压成一屏一意的竖屏页面，直接交付带导航与演讲备注的单文件 HTML。

## 输入

优先读取用户已经给出的材料，不要求为本 Skill 重新抄写。

- 完整讲稿、目标听众和本次演讲目的
- 预计时长、展示设备和需要保留的数据或原话
- 品牌色、素材文件及是否允许外部资源

没有品牌规范时采用黑白基底和单一强调色；没有图片不用外链占位，不虚构产品截图、用户评价或增长数字。

输入识别要求：
- 保留原始材料和来源定位，生成文件默认另存。
- 区分真实用户材料、待确认项与明确模拟输入。
- 用户目标明确时直接制作；只有影响结果的歧义才提出具体问题。
- 一次只解决本轮目标，不顺手扩展为其他业务流程。

## 核心判断

- 演讲屏幕和长图海报不同：屏幕控制信息密度，完整论证放备注。
- 竖屏优先采用 9:16 画布，自适应时保留内容可读性。
- 一屏一个关键判断；数字缺单位、范围或来源时不能当视觉大字。
- 极简来自删减层次，不来自隐藏必要条件或把字缩到看不见。
- HTML 演示不冒充可编辑 PPTX；单文件应明确离线依赖状态。
- 风格参考聚焦留白、节奏和对比，不假称原作者制作或背书。

执行前比较：以现有材料为事实源，比较直接转换与先建立结构再转换的代价。
本 Skill 采用先定位问题、再执行变更、最后核对原材料的路径。
工具选择以可保留关键语义和能验证结果为准，不以文件生成成功代替任务完成。

## 编号工作流

### 1. 提炼讲稿主线

- 标注开场问题、关键判断、证据、转折和行动请求。
- 保留原讲稿中的限定条件与数字来源。
- 将支线信息移入备注候选，不任意删除关键论证。
- 产出带原稿定位的内容提纲。

### 2. 制作逐屏脚本

- 按一屏一意切分，标题直接说结论。
- 每屏只放支撑该判断的少量字或一个图示。
- 给每屏写讲者备注、过渡句和预计讲述时间。
- 产出屏号、标题、屏幕文案、备注、来源映射。

### 3. 建立视觉规则

- 设黑白基底、一个强调色与一致的字阶。
- 以 9:16 为设计基准，用 CSS 适配窗口宽高。
- 长标题优先改写或分屏，不压缩至不可读。
- 产出字体、间距、配色与内容长度约束。

### 4. 编写单文件

- HTML 内嵌 CSS 与 JavaScript，默认不请求 CDN。
- 页面使用语义化 section，正文保持可选中。
- 素材用本地嵌入资源或内联 SVG，确认授权来源。
- 产出可直接保存为 presentation.html 的完整文件。

### 5. 实现演示控制

- 提供前后按钮、键盘左右方向键和页码。
- 首尾页不越界，触摸设备提供等价按钮操作。
- 备注可切换显示，默认不遮挡演示内容。
- 产出不依赖鼠标悬停的完整交互。

### 6. 适配可读性

- 检查窄屏、普通桌面窗口和竖屏投影的布局。
- 内容溢出优先分屏，保留合理的浏览器缩放。
- 支持减少动画偏好，避免闪烁与强制自动翻页。
- 产出基本无障碍、低干扰的演示页面。

### 7. 核验文件与内容

- 离线打开检查资源、按钮、键盘、页码和备注。
- 核对逐屏文案中的数字与原讲稿一致。
- 无浏览器工具时执行静态检查，明确未完成视觉与交互验证。
- 产出验证范围及发现问题的修复记录。

### 8. 交付排练入口

- 交 HTML 文件、逐屏脚本和实际验证结果。
- 请用户用目标设备排练并回传溢出页号与超时段。
- 下一轮只改屏幕密度、过渡和节奏，不重造原稿事实。
- 完成条件为内容可用且实际验证状态如实说明。

## 直接交付与下一步

默认交付以下成果；按用户目标裁剪，不为凑齐数量生成无关附件。

- presentation.html：含样式、导航和备注的单文件
- 逐屏脚本与原讲稿映射
- 离线和设备适配验证记录

交接规则：
- 先给可使用的成品入口，再说明仍影响使用的缺口。
- 核验必须写明执行了什么、结果如何、哪些能力没有执行。
- 本轮能完成的一次性交付到此结束，不附加通用调研作业。
- 需要继续时，只要求用户交回具体异常位置、确认口径或新材料。
- 复交后沿用已确认事实，检查本次修复及其影响的原有部分。

工具不可用时：
- 明确区分内容成品、结构校验、视觉或运行验证的完成状态。
- 交付当前可执行的替代物与操作顺序，不能把文本改后缀冒充目标格式。
- 核心结果无法生成或验证时说明具体阻塞，不将其描述成完成。

### 外部参考与延展

- 出现竖屏溢出、交互失效、无障碍问题或复杂数据展示时研究。
- 优先查 MDN 的 viewport、KeyboardEvent、CSS aspect-ratio 和 prefers-reduced-motion 文档。
- 比较原生 section 切换与演示框架，观察离线体积、备注和键盘支持。
- 只在当前需求确实需要时引入框架，单文件简单演示优先原生实现。
- 新机制先在最长标题和最密集证据页验证，确认不丢限定条件。
- 将通过的机制接入步骤 4 至 6，仍保持用户要求的单文件交付。

官方资料入口：[讲稿转极简竖屏 HTML 演示相关资料](https://developer.mozilla.org/en-US/docs/Web/CSS/aspect-ratio)。
已有材料足够时直接交付；研究只围绕当前失败点，不重复搜集无关项目。
实际采用外部内容时保留必要许可与来源；仅比较机制不复制正文。
