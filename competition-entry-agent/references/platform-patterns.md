# 平台流程参考

以下仅用于理解流程和发现官方入口，具体规则与界面每次重新核验。它们不是通用资格保证，也不要求用户只参加这些平台。

## Devpost：账号、赛事报名和项目提交分开

- 注册平台账号不等于加入赛事：
  https://help.devpost.com/article/119-registering-for-a-hackathon
- 创建项目、导入现有作品与进入最终提交：
  https://help.devpost.com/article/122-how-to-enter-a-submission
- 提交步骤、附件与视频要求：
  https://help.devpost.com/article/126-know-your-submission-steps

重点检查官方比赛是否允许旧项目、增量开发窗口、最终提交动作及评委访问方式。只见到 portfolio 或项目草稿不能标记赛事已提交。

## 华为云比赛与 Skill 市场联动

平台入口：https://developer.huaweicloud.com/competition/list

2026 年华为×小红书 Skill 创新赛的官方案例入口：
https://developer.huaweicloud.com/competition/information/1300000350

本轮观察到的流程是：个人报名、建队、使用码道或果办、按规则同时发布到两个 Skill 市场。这个要求只适用于对应赛事，后续要重新读取“赛事介绍 / 赛题详情 / 创作与提交”。实际使用的工具要留运行记录；不能把其他 Agent 的输出说成指定工具实测。

## 官方 GitHub Issue 参赛

适用于主办方确实指定官方仓库和 Issue 模板的赛事。先读取当前规则和模板，检查必需文件、仓库时间、接口集成和声明。核对是否已有同一账号或项目的报名 Issue，避免重复。

主办方要求某个 MCP 时，只有已经实际集成并验证才提交。不要把整个无关集合仓库的 Star、功能或演示当成参赛子项目的成果。

## 多入口活动

部分活动将活动报名、组队、福利领取、项目发布和最终提交放在不同页面或平台。围绕官方提交清单逐项记录，福利领取不代表报名或作品提交；活动没开放组队时不能虚报完成，也不要重复点击造成重复创建。

## 对失败的具体处理

- 页面“按钮点击无变化”：核对是否新开了标签页，再检查当前状态。
- 公开源码下载不稳定：使用官方原始文件/API、限定范围的公开下载或用户已授权的本地包；不为图省事上传整个仓库。
- 浏览器文件上传受权限限制：先使用宿主支持的正常上传方式；需要扩大权限时说明具体权限，不能暗中开启。可使用公开源码或粘贴必要的公开文本替代，但不得伪称附件已上传。
- 指定平台远程任务执行中：保存任务入口和真实输出；交接前核对任务是否仍存在。页面关闭不证明任务成功或取消。
