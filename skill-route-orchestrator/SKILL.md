# Skill 路由器

将模糊事件路由为一条最短的 Skill 路径。目标不是展示能力目录，而是让用户立刻知道该做什么。

## 先判断，再调用

从用户描述中判断四件事：目标、当前阶段、主阻塞点和时间/材料约束。信息不完整时，只追问那个会改变路由结果的信息，不要把问诊变成表单。

## 路由规则

1. 每次只选一个主 Skill。主 Skill 必须直接解决当前主阻塞点。
2. 最多添加两个辅助 Skill，且只有当前一项输出确实是下一项输入时才串联。
3. 用户已明确指定专项任务时，直接进入对应 Skill，不再做总控分析。
4. 对应 Skill 未安装时，如实说明，并用通用方法完成当前最小动作；不要伪装调用成功。
5. 先完成当前事件的最小闭环，再由用户决定是否继续。

## 输出格式

```text
现在最该解决：<一句话主阻塞点>

主路径：<主 Skill> → <可选辅助 Skill>
为什么这样走：<一到两句>
你现在只要给我：<一项材料，或立刻可做的动作>
```

若材料已经足够，最后一行改为“现在开始：<第一个动作>”。

## 常见路由

| 用户状态 | 优先路径 |
| --- | --- |
| 不确定岗位是否值得投 | `job-application-match` → `resume-jd-tailor` |
| 确定投递但经历没有对齐 JD | `resume-jd-tailor` |
| 临近面试但项目讲不清 | `interview-prep-brief` → `interview-resume-deep-dive` |
| 有答案但表达生硬、像 AI | `interview-script-naturalizer` |
| 面试后不知道怎么改 | `interview-transcript-replay` → `interview-learning-loop` |
| 多个 Offer 难以选择 | `offer-decision-advisor` |

以上只是示例。实际路由应读取当前可用 Skill 的 description、输入输出和边界，而不是死记名称。

## 边界

- 不把推荐路径说成确定答案。
- 不把用户材料扩写成未经确认的事实。
- 不调用无关知识库或工具制造完整感。
- 涉及职业、医疗、法律或财务重大决策时，保留不确定性与人工核验项。
