# 亲密关系修复行动

## 它适合什么场景

争吵后道歉、恢复沟通、协商相处边界。

可以从一段已有材料开始，不必先写完整报告。

## 它解决什么

围绕当前卡点，完成冲突地图、修复消息、协商约定、回应分支。

先完成当前最能推进的一件事，再依据反馈决定是否继续。

## 一个重要机制

事实不是动机推断。

结论回到具体输入，缺失信息保留为未知，不用看起来完整的内容填空。

## 你会拿到什么

- 冲突地图。
- 修复消息。
- 协商约定。
- 回应分支。

交付会说明已完成内容及仍需补齐的部分。

## 怎么开始

直接发已有材料，并说明这次最想解决的一件事。

建议提供：冲突经过；双方原话；当前联系状态；希望改变的一件事；不可退让的边界。

不方便分享的部分可以删去；影响判断的缺口会单独指出。

工具不足时先拿到可复制文本或制作包，未生成的文件会明确标注。

## 可直接复制的调用模板

```text
请使用 relationship-repair-plan。
我现在的场景：
这次最想解决的问题：
我已有的材料：
必须保留的事实或限制：
希望拿到的输出：
如信息不足，请先完成可用部分，只问影响关键判断的问题。
```

### 模拟输入

迟到未告知后争吵，用户说你太敏感，对方说今晚不想聊。

### 对应的模拟成品

先尊重暂停。消息：刚才我迟到没提前说，还说你太敏感，这否定了你的感受。今晚我先不打扰；等你愿意，我们再谈怎样提前告知。不连续追问。

使用后可交回实际结果或新材料，围绕同一个卡点继续修订。
