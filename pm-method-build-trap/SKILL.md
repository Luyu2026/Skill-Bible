# 功能陷阱检查

## 输入
目标、已做功能、上线数据、当前排期和团队说法。

## 核心判断
功能交付不是成果。必须看它是否改变了用户行为和业务结果，以及为什么没有。

## 工作流
1. 将“做了什么”改写成“希望改变什么”。
2. 检查目标、指标、决策和交付之间的断点。
3. 找出该停止、继续验证或扩大投入的部分。
4. 输出下个周期只需要承担的 outcome。

## 延展机制
当指标系统不足以判断 outcome 时，研究相关产品的北极星与指标树做法后补齐。
