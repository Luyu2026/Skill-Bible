# JD 采样与结论模板

学生在第一轮采样时使用。不要先把每条 JD 改写成简历语言。

## 一、JD 采样表

| 编号 | 公司/行业 | 岗位与城市/经验 | 采样日期与链接/截图 | 这个岗位对什么结果负责 | 它通常怎么推进工作 | 公司想看到什么证据 | 一句原文依据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| JD-01 |  |  |  |  |  |  |  |

填写要求：

- “对什么结果负责”不能只填“运营”，要写拉新、留存、付费转化、订单、内容供给、品牌认知、线索等具体结果；
- “怎么推进工作”写判断—动作—复盘的顺序，例如“分层找问题 → 设计触达/活动 → 看留存和转化”；
- “公司想看到什么证据”写项目、指标、工具、行业经验或协同，不要只抄“沟通能力强”；
- 保留一句能证明自己判断的原文，避免事后凭印象总结；
- 不可比样本单独标记原因，例如经验年限差距过大、明显偏销售/客服、城市不同或岗位实际属于另一条线。

## 二、学生的初步结论

交表时用自己的话回答：

1. 这批岗位共同对什么结果负责？
2. 它们最常见的工作链路是什么？
3. 招聘方不是只要“会做什么”，而是希望我拿什么证明自己？
4. 我已有的哪两段经历最能证明这些要求？各自缺什么事实或数据？
5. 因此我主投什么方向、备选什么方向；暂时不投什么方向，为什么？

## 三、验收表

| 检查项 | 通过标准 |
| --- | --- |
| 样本可比 | 同一城市/经验段为主，岗位族没有混杂 |
| 原文依据 | 每条都有链接、截图或关键原文 |
| 结果意识 | 能说清每条 JD 对什么结果负责 |
| 共性判断 | 至少引用 3 条 JD 支撑，不把形容词当结论 |
| 个人映射 | 区分“我做过但没写”“待补事实”“确实不会” |

未通过时，只补样本或重写结论，不进入简历改写。
