# ADHD 友好日计划

## 一句话主餐

普通聊天容易排满一天；本技能依据今天的精力、硬约束和卡点，交付能立即启动且允许中断恢复的三步计划。

## 输入

- 读取现有待办、日历、未完草稿或用户随口描述，不要求先整理。
- 确认今天必须发生的事情、真实截止时间和可用时段。
- 请用户用低、中、高描述当前精力，可不提供诊断信息。
- 识别卡点是任务含糊、材料缺失、难以取舍还是环境干扰。
- 未知时间采用顺序清单；未知精力采用低负担起步，不假装获得日历访问权。

输入处理顺序：
1. 先读取已给材料，复述本轮目标。
2. 只补问会改变执行路线的信息。
3. 可以合理假设的内容单独标记，事实缺口不能伪造。
4. 用户只要演示时明确标“模拟”，不称真实案例脱敏。

## 核心判断

1. 硬截止与自我期待分开；先保护真实承诺，再安排可选推进。
2. 启动动作必须包含动词、对象和结束标志；“研究项目”不能直接排入。
3. 估时仅作起点，以用户实际耗时调整，不作为自律评分。
4. 优先减少任务切换，将找材料与正式制作分开。
5. 日计划用于任务支持，不诊断 ADHD，也不提供用药或治疗建议。
6. 中断视为可恢复状态，保留文件位置和下一动作，不惩罚性补排。

决策落地要求：
- 每个判断都必须影响本轮的取舍、动作或交付。
- 解释只写到足以让用户理解当前选择，不堆砌理论。
- 用户更正输入时，撤回受影响结论并重做对应部分。

## 编号工作流

### 1. 收拢今天的承诺

- 从原始材料列出任务和截止。
- 最多提出一个会改变排序的问题。
- 把不影响今天的任务放入停车区。
- 标记等待他人回复的事项。
- 交付：今天必须做、可做、等待三类清单。

### 2. 选一个推进目标

- 按截止、后果和前置依赖选主任务。
- 目标写成可见成果，如一页汇报初稿。
- 把完美版本降成今天够用的版本。
- 说明本轮暂缓的任务。
- 交付：唯一主目标及取舍原因。

### 3. 拆成今天三步

- 第一步应能在几分钟内完成。
- 第二步产出粗糙但可看见的中间稿。
- 第三步只做最低限度核对或交接。
- 每一步都注明完成信号和需要的材料。
- 交付：动作、时间盒、结束标志三列表。

### 4. 安排启动环境

- 指出要打开哪个文件或页面。
- 只移走一个最明显的干扰源。
- 提供用户可拒绝的短时间盒。
- 时间不足时保留第一步和草稿保存动作。
- 交付：现在这一分钟的具体行动。

### 5. 准备中断恢复

- 每一步结束保存一句“下一步做什么”。
- 被打断后先读恢复句，不重新整理全部计划。
- 卡住时把当前动作再拆小一次。
- 材料未到则改做不依赖它的部分。
- 交付：一张可直接复制的恢复卡。

### 6. 用实际反馈重排

- 接收完成、卡住、没开始中的任意状态。
- 记录实际阻碍而非评价态度。
- 只调整剩余步骤和估时。
- 当天无法完成时说明最低交接成果。
- 交付：下一动作及是否移到明天的明确结论。

## 直接交付与下一步

- 今天三步计划、停车区和一张中断恢复卡。
- 用户现在只执行第一步，不同时启动三个任务。
- 完成标准是得到约定的最低成果，允许后两步按真实反馈调整。
- 用户反馈一句“做到了哪里、卡在哪里”即可续接。
- 提醒工具不可用时提供手动闹钟文字，不声称会主动催办。

交付前验收：
- 对照用户原始输入，检查关键事实和目标没有被替换。
- 逐项检查本技能承诺的产物已实际给出，而非只说将会生成。
- 把未确认项写在相应结论附近，不藏在笼统说明里。
- 用户能直接采取下一动作，无需再把输出加工成另一个任务。
- 不宣称访问过未访问的材料，也不宣称运行了未运行的工具。

### 外部参考与延展

- 触发：连续两轮没有开始、时间盒造成压力，或任务拆得很细仍不知道怎么做。
- 优先看用户历史完成记录和有效习惯；研究任务分解、implementation intentions、外化提醒等机制。
- 检索入口可用大学学习支持中心的 executive function planning 指南；健康类新主张须查权威临床来源。
- 比较启动门槛、切换次数和中断恢复成本，不能仅按计划排版是否好看选择。
- 选一处改动接入第一步，用实际是否启动及卡在哪里验证；不据此宣称治疗效果。

研究后的采用规则：
1. 先记录本轮具体缺口，再选互补机制，不以项目热度决定。
2. 优先复用用户已验证有效的方法；材料已足够时直接交付。
3. 外部机制只能改变执行方法，不能替代用户事实。
4. 新机制先用于当前产物，按上面的验收标准核对。
5. 找不到可靠改进时保留现有可用路径，并如实说明局限。

随附 `demo.md` 是明确模拟的输入与成品，用于理解交付尺度。
实际调用不复用其中的个人事实或把模拟结果当成用户结果。
